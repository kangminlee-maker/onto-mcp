# commerce-performance-marketing-kr Domain — 구조 명세

이 문서는 국내 커머스 성과 마케팅 문서와 시스템이 가져야 하는 구조를 정의한다.
구조의 목적은 광고 플랫폼 중심의 성과 보고를 거래 대상, 주문, 정산, 고객, 준수 권위와 연결해 의사결정 가능한 형태로 만드는 것이다.

분류 축: **성과 권위 계층(performance authority layer)** — 어떤 구조 요소가 최종 판단 권위를 가지는지에 따른 분류.

## 필수 상위 구조

모든 커머스 성과 마케팅 문서는 아래 상위 구조를 가져야 한다.

1. 비즈니스·판매 환경
2. 거래 대상·마진·공급 제약 구조
3. 고객 상태와 구매 여정
4. 유입 투자 유형과 채널 구조
5. 캠페인·소재·오퍼 구조
6. 전환 이벤트와 주문 구조
7. 데이터 권위와 어트리뷰션 구조
8. 리포트·의사결정 구조
9. 준수·정책 구조

이 중 2, 6, 7이 없으면 광고 성과는 운영 신호일 뿐 손익 판단 기준이 될 수 없다.

## 1. 비즈니스·판매 환경 구조

필수 필드:

| 필드 | 필수성 | 설명 |
|---|---|---|
| `commerce_type` | 필수 | 자사몰, 스마트스토어, 마켓플레이스, 쿠팡, 리테일 미디어, 혼합 환경 중 하나 이상 |
| `commerce_definition_basis` | 필수 | 주문·결제·정산 가능한 단위 거래를 1차 성과로 보는 근거 |
| `primary_sales_channel` | 필수 | 최종 주문이 발생하는 주 판매 채널 |
| `secondary_sales_channels` | 조건부 | 보조 판매 채널. 채널별 정산·데이터 권위를 구분한다. |
| `purchase_environment` | 필수 | 웹, 앱, 플랫폼 내부, 혼합 여정 |
| `business_goal` | 필수 | 결제액 확대, 신규 고객 획득, 재구매, 재고 소진, 마진 개선 등 |
| `decision_metric` | 필수 | 해당 목표의 최종 판단 지표 |
| `amount_basis` | 필수 | 결제액, 광고 기여 결제액, 정산 기준 결제액, 회계상 매출 중 어떤 금액 기준인지 |
| `excluded_metrics` | 권장 | 이번 판단에서 사용하지 않는 지표와 제외 이유 |

구조 규칙:

- 판매 환경이 2개 이상이면 채널별 주문 권위와 정산 권위를 분리한다.
- 자사몰과 플랫폼 스토어를 같은 전환 구조로 합치지 않는다.
- 플랫폼 내부 구매는 플랫폼 리포트와 정산 리포트를 모두 둔다.
- 목표가 재고 소진이면 ROAS보다 SKU별 잔여 재고, 할인 후 마진, 소진 기간이 함께 있어야 한다.
- 거래 대상이 디지털·콘텐츠이면 재고 대신 접근권, 좌석, 라이선스, 제공 가능 기간, 환불 조건 같은 공급 제약을 둔다.

## 2. 거래 대상·마진·공급 제약 구조

거래 대상 구조는 실물 상품과 디지털·콘텐츠 거래를 모두 표현할 수 있어야 한다.

| 단계 | 예시 | 용도 |
|---|---|---|
| 거래 대상군 | 뷰티, 건강식품, 의류, 강의, 리포트, 템플릿 | 목표 ROAS와 예산 배분 |
| 거래 대상 | 세럼 30ml, 단백질 쉐이크, 셔츠, 개별 클래스, 유료 리포트 | 소재·랜딩·리뷰 관리 |
| 판매 옵션 | SKU, 콘텐츠 ID, 이용권 ID, 옵션 ID | 재고 또는 공급 제약, 원가, 환불·반품 판단 |

필수 필드:

| 필드 | 필수성 | 설명 |
|---|---|---|
| `commerce_item_id` | 필수 | 거래 대상 식별자 |
| `product_id` | 조건부 | 실물 상품 또는 플랫폼 상품 식별자 |
| `sku_id` | 조건부 | 실물 상품의 SKU 식별자 |
| `category` | 필수 | 거래 대상군 또는 카테고리 |
| `item_type` | 필수 | 실물 상품, 디지털 재화, 콘텐츠, 이용권, 클래스·이벤트 티켓 등 |
| `selling_price` | 필수 | 판매가 |
| `product_cost` | 필수 | 원가 또는 원가 범위 |
| `selling_fee_rate` | 조건부 | 플랫폼·PG·제휴 수수료 |
| `shipping_cost_policy` | 조건부 | 실물 상품의 판매자 부담, 고객 부담, 무료배송 조건 |
| `delivery_or_access_policy` | 조건부 | 배송, 다운로드, 접근권 부여, 수강권 지급, 예약 확정 방식 |
| `promotion_cost_policy` | 조건부 | 쿠폰·포인트·사은품·플랫폼 지원금 구분 |
| `refund_or_return_rate` | 권장 | 거래 대상군, SKU, 콘텐츠, 이용권별 환불·반품률 |
| `inventory_status` | 조건부 | 실물 상품의 판매 가능, 품절 위험, 시즌성, 소진 목표 |
| `supply_constraint_status` | 조건부 | 재고 비해당, 좌석 제한, 라이선스 제한, 제공 기간, 승인 대기 등 |
| `canonical_product_id` | 권장 | 내부 기준 상품·콘텐츠·이용권 식별자 |
| `channel_product_id` | 조건부 | 네이버, 쿠팡, Google Merchant Center, Meta Catalog 등 채널 상품 식별자 |
| `catalog_item_id` | 조건부 | 상품 피드 또는 카탈로그 광고에서 사용하는 아이템 ID |
| `event_item_id` | 조건부 | 조회, 장바구니, 구매 이벤트에 실리는 상품 ID |
| `price_availability_sync` | 조건부 | 피드, 랜딩, 주문 가능 상태의 가격·재고 일치 여부 |
| `feed_rejection_status` | 조건부 | 상품 피드 반려, 승인 대기, 제한 노출, 정상 노출 상태 |

필수 관계:

- 거래 대상은 하나 이상의 판매 채널에 연결된다.
- 캠페인은 하나 이상의 거래 대상군, 거래 대상, 판매 옵션에 연결된다.
- 목표 ROAS는 상품 경제성에서 파생된다.
- 재고 부족, 품절, 접근권 제공 불가, 좌석 제한, 라이선스 제한은 캠페인 예산 증액보다 우선하는 제약이다.
- 쇼핑·카탈로그·리테일 미디어 캠페인은 `channel_product_id`, `catalog_item_id`, `event_item_id` 매칭 상태를 가져야 한다.
- 가격·재고·랜딩 정보가 피드와 다르면 상품 데이터 이슈로 표시하고 소재·입찰 성과와 분리한다.

## 3. 고객 상태와 구매 여정 구조

고객 상태 구조:

| 상태 | 정의 기준 | 필수 데이터 |
|---|---|---|
| `new_customer` | 지정 기간 또는 전체 이력 기준 첫 구매 | 고객 식별자, 첫 주문일 |
| `existing_customer` | 구매 이력 보유 | 고객 식별자, 과거 주문 |
| `repeat_customer` | 2회 이상 구매 | 구매 횟수, 구매 간격 |
| `reactivated_customer` | 휴면 후 재구매 | 휴면 기준, 재구매일 |
| `unknown_customer` | 상태 판정 불가 | 미식별 사유 |

구매 여정 구조:

1. 노출
2. 클릭 또는 유입
3. 상품조회
4. 장바구니 또는 찜
5. 결제시작
6. 구매완료
7. 취소·반품·교환
8. 정산 확정
9. 재구매 또는 휴면

앱 구매 여정 추가 필드:

| 필드 | 설명 |
|---|---|
| `deep_link_target` | 광고·메시지가 도착시키는 앱 화면 또는 상품상세 |
| `install_attribution_source` | MMP, 광고 플랫폼, SKAN·AdAttributionKit, Firebase 등 설치 어트리뷰션 원천 |
| `app_event_name` | SDK 또는 MMP에 전송되는 앱 이벤트명 |
| `mmp_partner_event_name` | 광고 네트워크로 포스트백되는 파트너 이벤트명 |
| `conversion_value_schema` | SKAN·AdAttributionKit 등 집계 측정에서 구매·결제액 구간·가입을 전환값으로 매핑하는 규칙 |
| `postback_window` | 앱 설치·클릭·조회 이후 포스트백 또는 전환 인정 기간 |
| `iap_or_external_payment` | 앱스토어 인앱 결제, 외부 결제, 플랫폼 내부 결제 구분 |

구조 규칙:

- 신규 고객과 기존 고객은 같은 캠페인 안에서도 리포트상 분리 가능해야 한다.
- 리타게팅, CRM, 브랜드 검색은 기존 수요 회수 가능성이 있으므로 신규 획득 구조와 분리한다.
- 고객 상태를 모를 경우 임의로 신규 고객으로 분류하지 않는다.
- 재구매 분석은 상품군별 구매 주기와 마진 유지 여부를 함께 가져야 한다.
- 앱 설치, 앱 실행, 앱 구매는 서로 다른 이벤트이며, 설치 어트리뷰션만으로 구매 성과를 확정하지 않는다.
- SKAN·AdAttributionKit 포스트백은 집계 측정 권위이고 주문·정산 권위를 대체하지 않는다.

## 4. 유입 투자 유형과 채널 구조

채널 구조는 아래 계층을 가진다.

1. 유입 투자 유형
2. 플랫폼 또는 매체
3. 캠페인
4. 광고그룹 또는 운영 묶음
5. 노출 방식
6. 노출 위치
7. 노출 미디어 포맷
8. 노출 시점
9. 타겟·키워드·상품그룹·지면
10. 소재
11. 랜딩 또는 상품상세
12. 전환 이벤트
13. 주문

필수 채널 속성:

| 속성 | 설명 |
|---|---|
| `acquisition_type` | 유료, 보유, 획득, 플랫폼 자연, CRM, 제휴, 인플루언서, 혼합 |
| `platform` | 네이버, 카카오, Google, Meta, 쿠팡, 자사몰, 이메일, 문자 등 |
| `organic_discovery_type` | 조건부. SEO, 플랫폼 SEO, AEO, GEO, 소셜 검색, 마켓플레이스 검색 등 |
| `exposure_method` | Search Ad, Display Ad, Shopping Listing Ad, Retail Media Ad, Social Feed Ad, Video Ad, Message Ad 등 |
| `media_format` | 텍스트, 이미지만, 이미지+텍스트, 상품 카드, 캐러셀, 숏폼 영상, 롱폼 영상, 라이브, 리치 메시지 등 |
| `placement` | 검색 결과, 쇼핑 결과, 상품상세, 카테고리 목록, 피드, 스토리·릴스, 영상 스트림, 메시지함, 푸시 등 |
| `exposure_moment` | 능동 검색, 상품 비교, 콘텐츠 소비, 소셜 탐색, 리타게팅, 장바구니·결제, CRM 생애주기 등 |
| `cost_basis` | 매체비, 제작비, 수수료, 할인비, 운영비 포함 범위 |
| `conversion_window` | 전환 인정 기간 |
| `attribution_model` | 마지막 클릭, 데이터 기반, 조회 기여, 내부 규칙 등 |
| `customer_state_visibility` | 신규·기존 고객 식별 가능 여부 |
| `compliance_constraints` | 수신동의, 표시광고, 맞춤형 광고 등 제약 |

구조 규칙:

- Paid / Non-paid는 `acquisition_type`으로 표현한다. `non_paid` 같은 단일 값으로 합치지 않는다.
- 자연 유입은 `organic_platform` 하나로 끝내지 않는다. 검색 결과 목록, 플랫폼 내부 검색, 답변형 결과, 생성형 AI 응답, 소셜 검색 중 어떤 발견 표면인지 분리한다.
- 광고 채널은 `platform`만으로 정의하지 않는다. `exposure_method`, `media_format`, `placement`, `exposure_moment`가 함께 있어야 고객 노출 맥락을 판단할 수 있다.
- Search Ad는 검색어·키워드·검색 결과 위치를 가져야 한다.
- Display Ad는 노출 위치와 미디어 포맷을 가져야 한다. DA라고만 쓰면 이미지 단독, 이미지+텍스트, 캐러셀, 영상, 네이티브 콘텐츠를 구분할 수 없다.
- Video Ad는 영상 길이, 숏폼·롱폼·라이브 구분, 재생 맥락을 가질 수 있다.
- Message Ad와 CRM Owned는 노출 위치보다 발송 채널, 수신동의, 발송 시점, 수신거부 구조가 우선 속성이다.
- 보유 채널과 자연 유입도 비용 범위와 운영 책임을 가져야 한다.
- 제휴·인플루언서 채널은 커미션, 할인코드, 광고 표시 구조를 가져야 한다.
- 플랫폼 자연 유입은 광고 성과로 귀속하지 않는다. 다만 광고가 자연 순위나 검색량에 영향을 줄 가능성은 별도 분석한다.

### 자연 발견 최적화 구조

자연 발견 최적화는 아래 속성을 가진다.

| 속성 | 설명 |
|---|---|
| `organic_discovery_type` | SEO, 플랫폼 SEO, AEO, GEO, 소셜 검색, 마켓플레이스 검색 |
| `query_or_prompt_class` | 검색어, 질문, 비교 요청, 추천 요청, 문제 해결 요청, 구매 의도 프롬프트 등 |
| `discovery_surface` | 검색 결과, 쇼핑 검색, featured snippet, PAA, AI Overview, AI Mode, AI assistant, 플랫폼 추천, 소셜 검색 등 |
| `target_entity` | 브랜드, 상품, 카테고리, 콘텐츠, 판매자, 문제 해결 주제 |
| `source_asset` | 자사몰 페이지, 상품상세, FAQ, 리뷰, 가이드, 비교표, 외부 리뷰, 플랫폼 상품 정보 |
| `answer_extractability` | 정의, 요약, 표, 목록, FAQ, 비교, 근거 문장처럼 답변 추출 가능 구조 |
| `entity_consistency` | 브랜드·상품·가격·정책·리뷰·판매자 정보의 표면 간 정합성 |
| `claim_evidence` | 효능, 비교, 추천, 가격, 수상, 판매량, 리뷰 주장에 대한 근거 |
| `visibility_metric` | 검색 노출, 클릭, 답변 노출, 인용, 언급, 추천 문맥, 후속 브랜드 검색, assisted conversion |

자연 발견 구조 규칙:

- SEO는 검색 결과 노출과 클릭을 중심으로 보되, AEO/GEO와 같은 답변·생성형 표면을 자동 포함하지 않는다.
- AEO는 직접 답변으로 추출될 수 있는 질문·답변 구조와 구조화 데이터를 가져야 한다.
- GEO는 생성형 응답 표면, 인용 가시성, 언급 가시성, 추천 문맥, 외부 신뢰 신호를 가져야 한다.
- AEO/GEO 성과는 일반 세션 수만으로 판단하지 않는다. 클릭 없는 노출, 인용, 언급, 후속 검색과 보조 전환을 별도 리포트한다.
- 생성형 응답은 플랫폼이 통제하는 결과이므로 특정 문구나 순위를 보장하는 구조로 표현하지 않는다.

## 5. 캠페인·소재·오퍼 구조

캠페인 필수 구조:

| 필드 | 필수성 | 설명 |
|---|---|---|
| `campaign_id` | 필수 | 캠페인 식별자 |
| `campaign_goal` | 필수 | 신규 획득, 재구매, 재고 소진, 객단가 상승 등 |
| `target_products` | 필수 | 상품군, 상품, SKU 연결 |
| `target_customer_state` | 필수 | 신규, 기존, 재구매, 휴면, 전체 등 |
| `exposure_method` | 필수 | 검색, 디스플레이, 쇼핑 목록, 소셜 피드, 영상, 메시지 등 |
| `media_format` | 필수 | 텍스트, 이미지, 이미지+텍스트, 상품 카드, 캐러셀, 영상 등 |
| `placement` | 필수 | 검색 결과, 상품상세, 피드, 영상 지면, 메시지함 등 |
| `exposure_moment` | 필수 | 검색 의도, 탐색, 비교, 콘텐츠 소비, 리타게팅, CRM 생애주기 등 |
| `budget` | 조건부 | 예산과 기간 |
| `bid_or_delivery_strategy` | 조건부 | 입찰, 목표 ROAS, 자동 최적화, 수동 운영 |
| `primary_metric` | 필수 | 1차 성공 기준 |
| `guardrail_metrics` | 필수 | 반품률, 마진, 재고, 수신거부, 빈도 등 제한 지표 |
| `decision_rule` | 필수 | 증액, 유지, 축소, 중단 조건 |

소재 구조:

- 소재는 하나 이상의 상품, 오퍼, 랜딩, 고객 상태, 노출 방식, 미디어 포맷, 노출 위치와 연결된다.
- 소재 검증은 클릭률만이 아니라 상품상세 진입, 구매율, 반품률, 마진을 포함할 수 있다.
- 비교·최저가·효능·후기·추천 표현이 있으면 실증 근거 또는 표시 근거와 연결한다.
- 이미지 단독, 이미지+텍스트, 상품 카드, 캐러셀, 숏폼 영상, 롱폼 영상은 서로 다른 소재 구조로 관리한다.
- 같은 메시지라도 검색 텍스트, 디스플레이 배너, 소셜 피드 이미지+텍스트, 숏폼 영상에서는 성과 기준과 정책 검토가 달라질 수 있다.

오퍼 구조:

- 오퍼는 할인 주체를 가진다: 판매자 부담, 플랫폼 부담, 공동 부담, 제조사 부담.
- 오퍼는 비용 반영 방식을 가진다: 결제액 차감, 마케팅 비용, 수수료 차감, 정산 차감.
- 오퍼 변경은 소재·타겟 변경과 분리 가능한 실험 구조를 가져야 한다.

## 6. 전환 이벤트와 주문 구조

필수 이벤트:

| 이벤트 | 필수 속성 | 권위 수준 |
|---|---|---|
| `view_item` | 상품 ID, 가격, 카테고리 | 행동 신호 |
| `add_to_cart` | 상품 ID, 수량, 금액 | 구매 의도 신호 |
| `begin_checkout` | 장바구니 금액, 상품 수 | 결제 의도 신호 |
| `purchase` | 주문번호, 금액, 통화, 상품 ID, 수량 | 구매 이벤트 |
| `cancel` | 주문번호, 취소 금액, 취소 시점 | 주문 보정 |
| `return` | 주문번호, 상품 ID, 반품 금액 | 결제액·마진 보정 |
| `exchange` | 원 주문, 교환 상품, 금액 차이 | 주문 보정 |

주문 필수 속성:

| 속성 | 설명 |
|---|---|
| `order_id` | 주문 식별자. 중복 제거 기준 |
| `customer_id` | 고객 식별자. 없으면 고객 상태 판정 불가 |
| `order_status` | 결제완료, 취소, 배송중, 배송완료, 반품, 교환, 정산확정 |
| `payment_amount` | 주문 결제액 |
| `payment_amount_basis` | 총결제액, 순결제액, 정산 기준 결제액 등 금액 기준 |
| `recognized_revenue_ref` | 조건부. 회계상 매출과 비교해야 할 때만 회계 매출 참조를 둔다. |
| `discount_amount` | 할인 금액 |
| `shipping_amount` | 배송비 |
| `product_cost` | 상품원가 |
| `fee_amount` | 플랫폼·PG·제휴 수수료 |
| `attribution_keys` | UTM, 클릭 ID, 쿠폰코드, 제휴코드 등 |

구조 규칙:

- 구매 이벤트에 주문번호가 없으면 중복 제거와 환불 반영이 불완전하다.
- 광고 기여 결제액은 주문 구조와 연결되어야 내부 판단 지표가 될 수 있다.
- 취소·반품·교환은 구매 이벤트의 사후 보정 이벤트로 연결한다.
- 정산 확정 전 결제액과 정산 기준 결제액은 서로 다른 권위 수준으로 표시한다.
- 회계상 매출은 결제액 구조의 기본 필드가 아니다. 회계상 매출과 비교해야 하는 경우에만 별도 참조로 연결한다.

## 7. 데이터 권위와 어트리뷰션 구조

권위 계층:

| 계층 | 데이터 | 역할 |
|---|---|---|
| L1 | 광고 플랫폼 리포트 | 플랫폼 내 운영 최적화 |
| L2 | 분석 도구 이벤트 | 사이트·앱 행동 분석 |
| L3 | 서버 이벤트 | 전환 유실 보완, 주문 연결 |
| L4 | 주문 DB | 확정 주문, 취소, 고객 상태 |
| L5 | 정산 DB | 순결제액, 수수료, 환불, 실제 차감 |
| L6 | 증분성 테스트 | 인과 효과 판단 |

측정 신뢰도 필수 필드:

| 필드 | 설명 |
|---|---|
| `reported_metric` | 판단에 사용한 성과 지표 |
| `measurement_confidence_level` | 플랫폼 리포트, 분석 이벤트, 서버 이벤트, 주문 DB, 정산 DB, 증분성 테스트 중 어느 수준인지 |
| `source_event_or_table` | 지표를 만든 이벤트, 테이블, 리포트 |
| `identifier_key` | 주문번호, 클릭 ID, 고객 ID, 쿠폰코드 등 매칭 키 |
| `deduplication_status` | 중복 제거 완료, 일부 가능, 불가 |
| `known_gap` | 추적 유실, 모델링 전환, 환불 미반영, 조회 기여 포함 등 한계 |
| `decision_allowed` | 이 신뢰도에서 허용되는 결정. 예: 운영 조정, 손익 판단, 인과 주장 |

어트리뷰션 구조 필수 요소:

- 전환 기간
- 클릭 기여와 조회 기여의 분리
- 직접 전환과 간접 전환의 분리
- 플랫폼 간 중복 제거 방식
- 주문번호 기준 중복 제거
- 신규 고객과 기존 고객 분리
- 브랜드 검색, CRM, 리타게팅의 기존 수요 회수 표시

구조 규칙:

- 채널별 플랫폼 광고 기여 결제액을 단순 합산해 전체 결제액으로 사용하지 않는다.
- 내부 전체 결제액과 채널별 기여 결제액의 합은 다를 수 있다.
- `매출`이라는 입력 필드가 있으면 `amount_basis`로 결제액 기반 관습 표현인지 회계상 매출인지 판정한다.
- 증분성 테스트가 없는 경우 "기여"라고 표현하고 "증가분"이라고 표현하지 않는다.
- 데이터 권위가 낮은 지표는 높은 권위의 의사결정에 단독 사용하지 않는다.

## 8. 리포트·의사결정 구조

리포트는 최소 4개 화면 또는 섹션을 가진다.

1. 경영 판단 리포트: 순결제액, 기여이익, MER, 신규 고객, 재고, 반품률
2. 채널 운영 리포트: 플랫폼별·노출 방식별·미디어 포맷별·노출 위치별 노출, 클릭, 비용, 전환, ROAS, 전환 기간
3. 상품·오퍼 리포트: SKU 또는 거래 대상별 결제액, 마진, 할인, 재고 또는 공급 제약, 환불·반품, 리뷰
4. 데이터·준수 리포트: 이벤트 누락, 중복 전환, 수신동의, 광고 표시, 정책 이슈

의사결정 로그 필수 필드:

| 필드 | 설명 |
|---|---|
| `decision_date` | 결정일 |
| `decision_type` | 증액, 축소, 중단, 유지, 실험, 수정 |
| `basis_metric` | 결정에 사용한 지표 |
| `authority_level` | 사용 지표의 권위 계층 |
| `expected_effect` | 기대 효과 |
| `guardrail_check` | 마진, 재고, 반품, 준수 제약 확인 |
| `review_date` | 재검토 시점 |

구조 규칙:

- 예산 증액은 목표 지표뿐 아니라 제한 지표를 통과해야 한다.
- 성과 하락 원인은 채널, 노출 방식, 미디어 포맷, 노출 위치, 노출 시점, 소재, 오퍼, 상품상세, 가격, 재고, 배송, 리뷰, 추적 오류로 분해한다.
- 의사결정 이후 결과를 같은 기준으로 재측정한다.

## 9. 준수·정책 구조

준수 구조 필수 요소:

| 영역 | 필수 구조 |
|---|---|
| 개인정보·행태정보 | 수집 항목, 수집 목적, 제3자 제공, 보관 기간, 거부권, 처리방침 반영 |
| 맞춤형 광고 | 픽셀·SDK 사용 여부, 리타게팅 대상, 민감 추론 방지, 거부 수단 |
| 광고성 정보 | 채널별 수신동의, 발송 시각, 광고 표시, 수신거부 처리 |
| 표시·광고 | 가격·할인·효능·비교·후기 표현의 실증 근거 |
| 추천·보증 | 대가 관계, 협찬 표시, 인플루언서·리뷰어 고지 |
| 전자상거래 | 판매자 정보, 배송·환불·청약철회, 추가 비용, 거래조건 |
| 플랫폼 정책 | 광고 심사, 금지 품목, 업종 제한, 데이터 사용 제한 |

준수 게이트 필수 필드:

| 필드 | 설명 |
|---|---|
| `gate_area` | 개인정보·행태정보, 광고성 정보, 표시·광고, 추천·보증, 전자상거래, 플랫폼 정책 |
| `applicable_campaign` | 게이트가 적용되는 캠페인, 소재, 발송, 랜딩, 타겟 |
| `required_evidence` | 필요한 준수 증빙 유형 |
| `evidence_artifact` | 동의 로그, 수신거부 반영 로그, 처리방침 반영 내역, 실증 자료, 광고 표시 캡처, 거래조건 스냅샷 등 |
| `blocking_condition` | 증빙이 없거나 충돌할 때 시작을 막는 조건 |
| `approval_owner` | 준수 확인 책임자 또는 승인 주체 |
| `review_date` | 재검토일 또는 정책 변경 확인일 |

구조 규칙:

- 준수 구조는 캠페인 시작 전 확인 항목으로 존재해야 한다.
- 필수 준수 증빙이 없는 캠페인은 경고가 아니라 시작 차단 대상으로 둔다.
- 정책 민감 상품군은 소재 승인과 랜딩 검토를 별도 게이트로 둔다.
- 수신거부 데이터는 CRM 발송 대상보다 높은 차단 권위를 가진다.
- 인플루언서·제휴 콘텐츠는 성과 리포트와 표시 근거를 함께 연결한다.

## 고립 노드 금지

- 캠페인에 연결되지 않은 광고비 → 경고
- 노출 방식, 미디어 포맷, 노출 위치, 노출 시점이 없는 광고 캠페인 → 경고
- 상품 또는 SKU에 연결되지 않은 구매 전환 → 경고
- 주문번호 없이 구매로 집계된 전환 → 경고
- 광고 기여 결제액은 있으나 내부 주문 매칭이 없는 경우 → 경고
- 높은 ROAS 캠페인에 상품 마진 또는 반품률이 없는 경우 → 경고
- CRM 발송 기록은 있으나 수신동의 또는 수신거부 반영 기록이 없는 경우 → 경고
- 인플루언서 기여 결제액은 있으나 광고 표시 근거가 없는 경우 → 경고
- 재고 소진 캠페인에 재고 상태가 없는 경우 → 경고
