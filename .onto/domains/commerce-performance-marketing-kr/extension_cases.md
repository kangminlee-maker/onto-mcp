# commerce-performance-marketing-kr Domain — Extension Cases

이 문서는 국내 커머스 성과 마케팅 패키지를 확장해야 하는 상황과 확장 절차를 정의한다.
확장의 기본 원칙은 새 플랫폼명을 문서에 계속 추가하는 것이 아니라, 기존 변동 축과 권위 구조에 새 사례를 매핑하는 것이다.

분류 축: **확장 원인(extension driver)** — 새 판매 환경, 새 유입 유형, 새 데이터 권위, 새 준수 제약 중 무엇이 바뀌었는지에 따른 분류.

## EXT-01. 새 판매 채널 추가

트리거:

- 새로운 오픈마켓, 종합몰, 버티컬몰, 라이브커머스, 리테일 미디어, 커머스 앱에 입점하거나 광고를 시작한다.

필수 추가:

- `commerce_type` 값 또는 기존 값과의 매핑
- 주문 발생 위치
- 정산 데이터 권위
- 수수료·배송비·프로모션 비용 구조
- 고객 식별 가능 여부
- 광고 전환 정의와 전환 기간
- 노출 방식, 미디어 포맷, 노출 위치, 노출 시점
- 플랫폼 정책·금지 품목·심사 기준

금지 shortcut:

- 플랫폼 광고 리포트만 추가하고 주문·정산 구조를 생략하지 않는다.
- 기존 채널과 같은 목표 ROAS를 자동 적용하지 않는다.
- 플랫폼명만 등록하고 Search Ad, Display Ad, Shopping Listing Ad, Video Ad 같은 노출 방식을 생략하지 않는다.

검증:

- CQ-SC-01, CQ-SC-04, CQ-UE-01, CQ-MA-02, CQ-CO-06을 재검토한다.

## EXT-02. 자사몰에서 플랫폼 스토어로 확장

트리거:

- 자사몰 중심 판매자가 스마트스토어, 쿠팡, 오픈마켓, 카카오 쇼핑 등 플랫폼 내부 구매 환경을 추가한다.

필수 추가:

- 플랫폼별 상품 ID와 내부 SKU 매핑
- 플랫폼 수수료와 정산 주기
- 플랫폼 내부 광고 전환과 내부 주문 DB 매칭 가능 여부
- 리뷰, 찜, 장바구니, 검색 랭킹 같은 플랫폼 신호
- 고객 데이터 접근 제한과 CRM 연결 가능성

금지 shortcut:

- 자사몰 픽셀 기준 전환 구조를 플랫폼 내부 구매에 그대로 적용하지 않는다.
- 플랫폼 광고 기여 결제액을 자사몰 주문 결제액과 같은 권위로 합산하지 않는다.

검증:

- 판매 환경별 결제액, 정산, 마진, 고객 상태가 분리되는지 확인한다.

## EXT-03. 앱 커머스 구매 여정 추가

트리거:

- 자사 앱, 플랫폼 앱, 앱 딥링크, 앱 푸시, 인앱 구매 여정이 성과 마케팅의 주요 경로가 된다.

필수 추가:

- SDK 이벤트
- 딥링크 구조
- 앱 설치·실행·구매 이벤트 구분
- MMP, SKAN·AdAttributionKit, Firebase 등 앱 측정 권위 구분
- 전환값 스키마와 포스트백 윈도우
- 앱스토어 인앱 결제와 외부 결제의 금액·정산 기준
- 로그인 또는 고객 식별 권위
- 앱 푸시 수신동의와 수신거부
- 웹 구매와 앱 구매 중복 제거

금지 shortcut:

- 앱 설치를 구매 성과로 대체하지 않는다.
- 웹 픽셀 전환과 앱 SDK 전환을 같은 이벤트로 합치지 않는다.
- 집계 포스트백을 개별 주문 DB나 정산 기준 결제액으로 대체하지 않는다.

검증:

- CQ-SC-03, CQ-MA-01, CQ-MA-06, CQ-MA-09, CQ-CR-02, CQ-CO-02를 재검토한다.

## EXT-04. 리테일 미디어 또는 쿠팡광고 고도화

트리거:

- 쿠팡, 오픈마켓, 종합몰 내부 광고를 핵심 결제액 기여 채널로 운영한다.

필수 추가:

- 직접 전환과 간접 전환 정의
- 광고 전환 판매수와 광고 전환 주문수의 차이
- 목표 ROAS 설정 방식
- 상품별 광고 운영 단위
- 상품 피드·카탈로그 ID와 주문 상품 ID 매칭
- 가격·재고·랜딩 정합성
- 피드 반려·제한 노출 상태
- 검색 결과, 상품상세, 추천, 카테고리, 홈 피드 등 플랫폼 내부 노출 위치
- 플랫폼 자연 판매와 광고 기여 판매의 분리
- 정산 기준 결제액과 광고 리포트의 광고 기여 결제액 차이

금지 shortcut:

- 플랫폼이 제공한 목표 ROAS를 손익분기 ROAS로 오인하지 않는다.
- 간접 전환을 신규 수요 창출로 단정하지 않는다.
- 피드·카탈로그 오류를 입찰가 또는 소재 문제로만 처리하지 않는다.

검증:

- CQ-UE-02, CQ-AC-05, CQ-AC-12, CQ-MA-03, CQ-MA-04, CQ-MA-10을 재검토한다.

## EXT-05. 인플루언서·공동구매·라이브커머스 추가

트리거:

- 인플루언서 협찬, 공동구매, 라이브 방송, 리뷰 콘텐츠, 쿠폰코드 기반 판매를 운영한다.

필수 추가:

- 대가 관계와 광고 표시 근거
- 링크, 쿠폰코드, 파트너 ID
- 고정비, 수수료, 샘플, 제작비
- 판매 기간과 사후 검색·직접 유입 관찰 기간
- 반품률, CS, 리뷰 변화

금지 shortcut:

- 쿠폰코드 기여 결제액만 보고 전체 인플루언서 효과로 확정하지 않는다.
- 광고 표시 누락을 성과가 좋다는 이유로 허용하지 않는다.

검증:

- CQ-AC-04, CQ-CO-04, CQ-MA-04, CQ-GV-01을 재검토한다.

## EXT-06. CRM·재구매 운영 강화

트리거:

- 카카오 채널, 문자, 이메일, 앱 푸시, 멤버십, 쿠폰 자동화가 주요 결제액 기여 수단이 된다.

필수 추가:

- 채널별 수신동의와 수신거부 데이터
- 고객 상태: 신규, 기존, 반복, 휴면, 재활성화
- 상품군별 재구매 주기
- 발송 빈도, 발송 시간, 메시지 유형
- 할인비와 발송비
- 수신거부율, 차단율, 신고율

금지 shortcut:

- CRM 기여 결제액을 신규 획득 성과에 포함하지 않는다.
- 수신동의가 불명확한 고객에게 광고성 메시지를 발송하지 않는다.

검증:

- CQ-CR-02, CQ-CR-04, CQ-CR-05, CQ-CO-02를 재검토한다.

## EXT-07. 반복구매 상품군에서 LTV 사용 시작

트리거:

- 소모품, 식품, 뷰티, 반려동물용품 등 반복구매 가능성이 있는 상품군에서 LTV 기반 광고비 판단을 도입한다.

필수 추가:

- 코호트별 반복구매율
- 구매 간격
- 할인 의존도
- 반품률
- 마진 유지율
- 관측 기간과 예측 기간
- 첫 구매 손실 허용 한도와 회수 기간

금지 shortcut:

- 업종 평균 또는 희망 반복구매율만으로 LTV를 만들지 않는다.
- 결제액 기준 LTV만 보고 마진 기준 LTV를 생략하지 않는다.

검증:

- CQ-CR-03, CQ-UE-04, CQ-DC-02를 재검토한다.

## EXT-08. 서버 이벤트·CAPI·데이터 웨어하우스 도입

트리거:

- 픽셀 유실, 앱·웹 중복, 플랫폼 모델링 전환 차이, 개인정보 제약으로 서버 이벤트 또는 데이터 웨어하우스를 도입한다.

필수 추가:

- 이벤트 생성 권위
- 주문번호 매칭
- 중복 제거 키
- 브라우저 이벤트와 서버 이벤트의 공통 이벤트 ID
- 상품 피드 ID와 이벤트 상품 ID 매칭
- 이벤트 전송 지연
- 실패 재시도 정책
- 개인정보 처리 근거와 보관 기간
- 플랫폼별 이벤트 매핑
- 앱 이벤트가 포함되면 MMP 이벤트명, 파트너 이벤트명, 집계 포스트백 구분

금지 shortcut:

- 서버 이벤트와 픽셀 이벤트를 중복 제거 없이 동시에 구매로 집계하지 않는다.
- 개인정보 처리방침과 내부 보관 정책 없이 식별 데이터를 확장하지 않는다.
- 서버 이벤트 도입만으로 상품 단위 ROAS나 앱 구매 어트리뷰션이 자동으로 정확해진다고 보지 않는다.

검증:

- CQ-MA-01, CQ-MA-03, CQ-MA-06, CQ-MA-09, CQ-MA-10, CQ-CO-01을 재검토한다.

## EXT-09. 새 광고 플랫폼 또는 자동화 캠페인 도입

트리거:

- 새로운 광고 플랫폼, 자동 입찰, 목표 ROAS, 상품 피드 자동화, AI 소재 자동화, Performance Max형 캠페인을 시작한다.

필수 추가:

- 캠페인 목표와 최적화 이벤트
- 노출 방식, 미디어 포맷, 노출 위치, 노출 시점
- 전환 기간과 기여 모델
- 상품 피드 권위
- 학습 기간
- 예산 변경 제한
- 소재·상품 제외 규칙
- 플랫폼 정책과 데이터 사용 제한

금지 shortcut:

- 자동화 캠페인의 플랫폼 권장 설정을 내부 손익 목표로 대체하지 않는다.
- 학습 기간 중 단기 성과만으로 캠페인을 중단하지 않는다.
- 자동화 캠페인 안에 여러 노출 위치와 포맷이 섞여 있으면 평균 성과만으로 소재나 지면을 확정하지 않는다.

검증:

- CQ-DC-05, CQ-MA-02, CQ-UE-01, CQ-CO-06을 재검토한다.

## EXT-10. 개인정보·광고성 정보·표시광고 규제 변경

트리거:

- 개인정보, 행태정보, 맞춤형 광고, 광고성 정보, 표시광고, 추천·보증, 전자상거래 관련 법률·가이드라인·플랫폼 정책이 바뀐다.

필수 추가:

- 변경된 의무와 적용 대상
- 영향 받는 채널과 캠페인
- 필요한 고지, 동의, 거부, 표시, 보관 정책 변경
- 기존 소재와 랜딩의 수정 필요성
- 시행일과 유예 기간
- 책임자와 재검토 일정

금지 shortcut:

- 법률 변경을 일반 운영 메모로만 남기지 않는다.
- 플랫폼 정책 변경을 심사 반려 후에만 반응하지 않는다.

검증:

- CQ-CO 전체와 CQ-GV-03을 재검토한다.

## EXT-11. 오프라인 구매 또는 매장 방문 연결

트리거:

- 온라인 광고가 오프라인 매장 구매, 팝업스토어 구매, 전화 주문, QR 구매로 연결된다.

필수 추가:

- 오프라인 전환 정의
- 쿠폰, QR, 전화번호, POS, 멤버십 ID 등 연결 키
- 온라인 접점과 오프라인 구매 사이의 전환 기간
- 중복 결제액 제거
- 개인정보 고지와 동의

금지 shortcut:

- 오프라인 결제액 증가를 온라인 광고 증분 효과로 바로 확정하지 않는다.
- 식별 불가능한 오프라인 결제액을 채널별 ROAS에 직접 귀속하지 않는다.

검증:

- CQ-MA-04, CQ-MA-07, CQ-CO-01을 재검토한다.

## EXT-12. 고위험 표현 상품군 추가

트리거:

- 건강, 의료, 금융, 다이어트, 기능성, 청소년 민감 상품, 안전 관련 상품처럼 광고 표현 리스크가 큰 상품군을 판매한다.

필수 추가:

- 금지·제한 표현 목록
- 사전 검수 책임자
- 실증 근거 보관 위치
- 플랫폼 심사 기준
- 후기·전후 비교·효능 표현 검토

금지 shortcut:

- 경쟁사가 쓰는 표현이라는 이유로 근거 없이 사용하지 않는다.
- 후기 표현을 사업자의 효능 주장처럼 편집하지 않는다.

검증:

- CQ-CO-03, CQ-CO-04, CQ-GV-01, CQ-GV-03을 재검토한다.

## EXT-13. AEO/GEO 또는 AI 발견 표면 추가

트리거:

- Google AI Overview, AI Mode, 생성형 AI assistant, 답변형 검색, 쇼핑 assistant, 소셜 검색, 플랫폼 내부 AI 추천 등 새로운 자연 발견 표면을 성과 마케팅 범위에 포함한다.

필수 추가:

- `organic_discovery_type`
- 대상 쿼리군 또는 프롬프트군
- 답변 표면 또는 생성형 응답 표면
- 인용·언급·추천 측정 방식
- 대상 브랜드·상품·카테고리 엔티티
- 출처 자산: 자사몰, FAQ, 상품상세, 리뷰, 외부 비교, 플랫폼 상품 정보
- 엔티티 일관성 점검
- 근거 가능 주장과 표시광고 리스크
- 후속 브랜드 검색, 직접 유입, assisted conversion 관찰 방식

금지 shortcut:

- AI 응답에 한 번 언급된 사실만으로 증분 구매 효과를 확정하지 않는다.
- GEO/AEO를 별도 마법 채널처럼 취급해 SEO, 상품 정보, 리뷰, 구조화 데이터, 외부 신뢰 신호와 분리하지 않는다.
- 생성형 응답 캡처를 남기면서 엔진, 지역, 시점, 프롬프트, 출처를 기록하지 않는 방식으로 측정하지 않는다.

검증:

- CQ-OD-01, CQ-OD-02, CQ-OD-03, CQ-OD-05, CQ-OD-07을 재검토한다.

## 확장 승인 체크리스트

확장 전 다음 질문에 모두 답해야 한다.

- 이 확장은 어떤 변동 축을 바꾸는가?
- 고객에게 노출되는 방식, 미디어 포맷, 위치, 시점이 기존 축으로 표현되는가?
- 검색 결과, 답변형 결과, 생성형 응답, 플랫폼 검색 중 어떤 자연 발견 표면이 바뀌는가?
- 기존 개념으로 표현 가능한가, 새 개념이 필요한가?
- 새 개념이 필요하다면 기존 개념과 중복되지 않는가?
- 주문·정산·마진 권위가 확보되는가?
- 고객 상태와 중복 전환을 판정할 수 있는가?
- 준수 제약이 캠페인 시작 전 확인되는가?
- 어떤 competency question을 추가 또는 수정해야 하는가?
