# commerce-performance-marketing-kr Domain — Conciseness Rules

이 문서는 국내 커머스 성과 마케팅 패키지가 불필요하게 커지거나 같은 개념을 여러 이름으로 반복하지 않도록 하는 규칙을 정의한다.

분류 축: **중복 발생 위치(redundancy location)** — 중복이 개념, 구조, 지표, 플랫폼, 준수, 예시 중 어디에서 발생하는지에 따른 분류.

## 기본 원칙

- 새 플랫폼명이나 AI 발견 표면을 추가하기 전에 기존 판매 환경 유형, 유입 투자 유형, 자연 발견 최적화 유형, 노출 방식, 미디어 포맷, 노출 위치, 노출 시점, 측정 권위 수준으로 표현 가능한지 확인한다.
- 새 KPI를 추가하기 전에 기존 KPI의 분자, 분모, 비용 범위, 기간, 고객 상태를 조정해 표현 가능한지 확인한다.
- 같은 의미의 용어는 하나의 표준 용어를 정하고, 다른 표현은 동의어 또는 주의어로만 둔다.
- 플랫폼 세부 기능은 지속적으로 변하므로, 문서에는 기능명이 아니라 판단 구조를 남긴다.
- 예시는 구조를 이해시키는 데 필요한 최소 수만 둔다. 예시가 규칙처럼 읽히면 안 된다.
- 법률·정책 내용은 원문을 길게 옮기지 않고, 마케팅 판단에 필요한 제약 유형과 확인 지점으로 축약한다.

## 개념 중복 규칙

다음은 하나의 개념으로 통합한다.

| 중복 후보 | 표준 개념 | 처리 |
|---|---|---|
| 광고 전환 매출, 광고 기여 매출, 플랫폼 매출 | 광고 기여 결제액 | 플랫폼 기여 모델을 따른 결제액으로 정의한다. |
| 객단가, AOV, 주문당 매출 | AOV | 분모가 주문인지 고객인지 명시하고, 금액 기준은 결제액으로 표시한다. |
| 신규 고객, 첫 구매 고객, 신규 구매자 | 신규 고객 | 판정 기간과 데이터 권위를 명시한다. |
| 반품률, 환불률, 취소·반품률 | 반품률 또는 구매 후 보정률 | 취소와 반품을 분리할 필요가 있을 때만 나눈다. |
| 무료 유입, 자연 유입, non-paid | 유입 투자 유형 | 직접 매체비 없음과 비용 없음은 구분한다. |
| 마진 ROAS, 이익 ROAS, 공헌 ROAS | 기여 ROAS | 어떤 비용을 차감했는지 명시한다. |

새 개념을 허용하는 경우:

- 기존 개념과 다른 데이터 권위를 가진다.
- 기존 개념과 다른 의사결정 결과를 만든다.
- 기존 개념과 다른 준수 의무를 만든다.
- 기존 개념과 다른 수명주기 또는 책임자를 가진다.
- 기존 개념으로 표현하면 검증 질문이 모호해진다.

## 지표 간결성 규칙

- ROAS 변형은 최대한 제한한다. 기본은 ROAS, 손익분기 ROAS, 기여 ROAS, MER로 충분해야 한다.
- CVR은 분모가 다른 경우에만 별도 이름을 둔다. 예: 클릭-구매 전환율, 상품상세-구매 전환율.
- CAC는 신규 고객 판정이 가능한 경우에만 문서에 둔다. 고객 상태를 모르면 CAC 대신 신규 주문당 비용 또는 구매당 비용으로 표현한다.
- LTV는 반복구매 근거가 있을 때만 둔다. 근거가 없으면 문서에서 LTV 확장을 보류한다.
- 반품, 취소, 교환은 구매 후 보정 이벤트로 묶되, 판단 결과가 다르면 별도 지표로 분리한다.
- 상단 퍼널 지표는 클릭률, 상품조회율, 장바구니율, 결제시작률처럼 구매 여정 단계별로 최소화한다.

## 구조 중복 규칙

- 캠페인 구조와 채널 구조를 중복 작성하지 않는다. 캠페인은 채널 구조 안에 배치한다.
- 상품 구조와 주문 구조를 중복 작성하지 않는다. 주문은 상품 또는 SKU를 참조한다.
- 고객 상태와 CRM 세그먼트를 중복 작성하지 않는다. CRM 세그먼트는 고객 상태의 운영용 하위 묶음으로 둔다.
- 데이터 권위와 어트리뷰션 구조를 분리하되, 같은 권위 표를 여러 문서에 반복하지 않는다.
- 준수 체크리스트는 캠페인 구조와 연결하되, 법률 조문을 모든 문서에 반복하지 않는다.

## 플랫폼 세부사항 규칙

플랫폼별 문서 추가는 다음 조건 중 하나를 만족할 때만 허용한다.

- 플랫폼이 독자적인 주문·정산 권위를 가진다.
- 플랫폼 전환 정의가 내부 주문 정의와 materially 다르다.
- 플랫폼 정책이 캠페인 운영 가능 여부를 바꾼다.
- 플랫폼의 비용·수수료·프로모션 구조가 손익 판단을 바꾼다.
- 플랫폼 내 자연 노출과 광고 노출이 강하게 상호작용한다.
- 플랫폼이 기존 노출 방식, 미디어 포맷, 노출 위치, 노출 시점으로 표현할 수 없는 새 고객 접점을 만든다.
- 새 답변형 또는 생성형 표면이 SEO/AEO/GEO 중 기존 자연 발견 유형으로 표현되지 않는다.
- 상품 피드, 카탈로그, MMP, SKAN·AdAttributionKit이 데이터 권위 또는 측정 제약을 바꾼다.

다음 내용은 별도 플랫폼 섹션으로 확장하지 않는다.

- 화면 메뉴명 변경
- 버튼 위치 또는 UI 절차
- 일시적 프로모션명
- 플랫폼 마케팅 문구
- 단순 기능 이름 변경
- 단일 사례의 성과 수치
- 플랫폼별 피드 오류 메시지 원문
- 앱 측정 도구별 화면 절차

## 준수 내용 간결성 규칙

- 법률명은 범위 문서의 운영 제약·자료 권위에 두고, 본문에는 판단에 필요한 의무 유형을 둔다.
- 조문 전문을 복사하지 않는다. 수집·고지·동의·거부·표시·실증·보관·철회 같은 운영 제약으로 바꿔 쓴다.
- 플랫폼 정책은 캠페인 가능 여부, 데이터 사용 가능 여부, 소재 승인 여부, 금지 표현 여부 중심으로 요약한다.
- 준수 항목은 성과 지표보다 앞선 차단 조건으로 표현한다.
- 같은 준수 의무가 여러 채널에 반복될 때는 채널별 차이만 별도로 둔다.

## 검색 보강 선별 규칙

- 검색으로 발견한 내용은 의사결정 권위, 준수 차단, 측정 재현성, 국내 판매 환경 차이 중 하나를 바꿀 때만 추가한다.
- 법률 조문, 플랫폼 도움말, 연구명은 본문에서 권위처럼 길게 반복하지 않고 운영 제약, 필수 필드, PASS/FAIL 질문으로 변환한다.
- 새 내용이 기존 개념의 별도 이름만 늘리고 판단을 바꾸지 않으면 추가하지 않는다.
- 보강 후 특정 축이 과도하게 커지면 사례·플랫폼명을 줄이고 상위 개념으로 합친다.

## 예시 사용 규칙

- 예시는 국내 커머스 맥락을 보여주는 데 필요할 때만 사용한다.
- 예시는 규칙보다 길어지면 안 된다.
- 예시 수치는 실제 권장 기준처럼 쓰지 않는다.
- 플랫폼 예시는 "예: 네이버 쇼핑검색광고, 쿠팡 상품광고"처럼 범주 이해를 돕는 수준으로 제한한다.
- 특정 업종 예시는 건강식품, 뷰티, 패션, 생활용품 등 반복구매·반품률·표현 리스크 차이가 있는 경우에만 둔다.

## 명명 규칙

- 문서 본문은 한국어를 기본으로 한다.
- 안정적인 enum 값은 영어 snake_case를 사용한다.
- 한국어 용어와 enum 값이 함께 필요한 경우 `신규 고객(new_customer)`처럼 최초 1회 병기한다.
- 플랫폼명은 공식 표기를 따른다. 단, 플랫폼명이 바뀌어도 구조가 유지되도록 범주명을 함께 둔다.
- 지표 약어는 처음 나올 때 의미를 설명한다. 이후에는 약어를 사용할 수 있다.
- 같은 개념에 새 약어를 만들지 않는다.

## 제거 기준

다음 항목은 문서에서 제거하거나 축약한다.

- 실무 팁이지만 검증 기준이나 구조를 바꾸지 않는 문장
- 특정 플랫폼 UI 절차처럼 빠르게 낡는 설명
- 같은 법률 의무를 반복한 문장
- "중요하다", "관리해야 한다"처럼 구체적 판단 기준이 없는 문장
- 플랫폼명만 다르고 노출 방식·포맷·위치·시점이 같은 반복 설명
- AEO, GEO, AI SEO 같은 새 명칭이지만 실제 목표 표면·측정 지표·권위 구조가 기존 개념과 같은 반복 설명
- 단일 캠페인 사례에서만 유효한 수치
- 상품군 전체에 일반화할 수 없는 개별 경험칙

## 추가 전 체크리스트

새 개념, 섹션, 지표, 플랫폼 설명을 추가하기 전에 다음을 확인한다.

- 기존 개념으로 표현할 수 없는가?
- 의사결정 결과가 달라지는가?
- 데이터 권위가 달라지는가?
- 발견 표면이 검색 결과, 답변형 결과, 생성형 응답 중 무엇인지 달라지는가?
- 준수 의무가 달라지는가?
- 새로운 competency question이 필요한가?
- 기존 문서 중 한 곳만 수정해도 충분한가?
- 예시가 규칙으로 오해될 위험은 없는가?
