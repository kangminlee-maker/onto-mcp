onto MCP Implementation Map

현재 목표는 onto.review를 MCP tool로 호출 가능하게 만들고, 여러 lens가 분리된 context에서 병렬 검토한 뒤 surface finding을 root-cause issue로 묶고 문제 성격 분류와 통제된 숙의 결과를 synthesize가 보존적으로 정리하게 하는 것이다.

Current Decisions

MCP boundaryActive
src/mcp는 schema와 stdio server만 소유한다.
Review semanticsActive
src/core-runtime와 .onto 문서가 review 의미론을 소유한다.
Controlled deliberationActive
현재는 participating lens가 제한 context에서 재평가하고 teamlead 결과를 deliberation.md에 기록한다.
Issue closure artifactsActive
finding ledger, relation graph, issue ledger, stance matrix, deliberation plan, problem framing을 prompt-backed runtime step으로 생성하고 검증한다.
Codex pathActive
--codex, Codex host, Codex-selected execution은 codex-main-subprocess로 수렴한다.
Core APIActive
src/core-api는 기존 runtime을 library처럼 호출한다.
Fail loudActive
config, executor, deliberation mode가 맞지 않으면 즉시 에러로 드러낸다.
Record provenanceActive
lens output의 domain provenance 섹션은 YAML list만 허용하고, ReviewRecord 조립에서 검증한다.
Snapshot retiredActive
대형 시스템 스냅샷 문서는 active surface에서 제거했고, 현재 정본은 AGENTS.md, .onto/processes, architecture docs가 나눠 가진다.

Scope Boundaries

Area현재 seat다음 설계 질문
reviewMCP surface 구현됨. lens + issue closure artifacts + controlled deliberation + problem framing + synthesize + ReviewRecord 경로가 TS runner에 연결됨.남은 질문은 issue별 lens response를 별도 구조화 파일로 분리할지, 현재 deliberation.md 중심 구조를 유지할지이다.
learn기존 runtime 영역. MCP surface 편입 대상.학습 산출물의 authority seat와 tool schema를 먼저 정한다.
govern기존 runtime 영역. MCP surface 편입 대상.principle 승격/검증 workflow를 MCP tool 단위로 나눈다.
reconstruct제품 방향에 포함. domain 문서를 함께 사용한다.구현물에서 ontology seed를 역산하는 artifact contract를 정의한다.
evolve제품 방향에 포함. ontology 기반 설계 프로세스다.기능 추가 설계안을 어떤 record로 남길지 정한다.
