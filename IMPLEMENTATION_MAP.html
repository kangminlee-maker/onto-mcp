2. Review Execution Flow

review는 하나의 호출을 interpretation/binding으로 고정한 뒤, lens를 분리된 context에서 실행하고, 모든 issue에 대한 stance와 이견을 보존한 상태로 controlled deliberation을 수행합니다. 명시적 단일 lens selection도 지원하며, 이 경우 cross-lens disagreement는 적용되지 않는 bounded single-lens evidence로 기록됩니다.

1. MCP Callonto_review receives target, intent, optional domain and lens controls.
2. Core APIreview-api.ts captures runtime facts and returns structured refs plus llmPresentation prompts.
3. Invocationinterpretation and binding are materialized as runtime-owned artifacts.
4. Preparationpre-dispatch gates, execution plan, review context manifest, packet refs, and packet hashes are written.
5. Isolated Lensselected lens set runs through worker seats only after manifest and packet guards pass.
6. Issue Closurefindings are grouped into root-cause issue clusters and stance matrices.
7. Deliberationcontested positions are revisited by participating lens contexts under teamlead control.
8. Synthesizesynthesis consumes lens outputs and deliberation result, then writes a comprehensive final result explanation.
9. RecordReviewRecord, manifest, final output, and MCP result overview are produced.

10. Boundary Decisions

Canonical public path

onto mcp exposes MCP tools. Review-specific npm scripts have been removed from the public package surface; internal harnesses call TypeScript entrypoints directly.

Deliberation transport

SendMessageA2A is treated as one host transport idea. The product requirement is transport-neutral: different context-isolated lens units must revisit contested claims under teamlead-controlled deliberation.

Presentation ownership

Runtime owns bounded facts and artifact truth. Host LLM owns user-facing explanation through llmPresentation prompt/input pairs, so MCP clients do not depend on CLI stdout formatting.
