2. Review Execution Flow

review는 하나의 호출을 interpretation/binding으로 고정한 뒤, lens를 분리된 context에서 실행하고, 모든 issue에 대한 stance와 이견을 보존한 상태로 controlled deliberation을 수행합니다.

1. MCP Callonto.review receives target, intent, optional domain and lens controls.
2. Core APIreview-api.ts captures runtime facts and returns structured refs plus LLM presentation prompts.
3. Invocationinterpretation and binding are materialized as runtime-owned artifacts.
4. Preparationexecution plan, context bundle, and prompt packets are written.
5. Isolated Lens9 lens set or selected lens set runs through worker seats.
6. Issue Closurefindings are grouped into root-cause issue clusters and stance matrices.
7. Deliberationcontested positions are revisited by participating lens contexts under teamlead control.
8. Synthesizesynthesis consumes lens outputs and deliberation result, then writes a comprehensive final result explanation.
9. RecordReviewRecord, manifest, final output, and MCP result overview are produced.

8. Boundary Decisions

Canonical public path

onto mcp exposes MCP tools. npm run review:* scripts remain useful as development harnesses and conformance checks, not as the long-term user interface.

Deliberation transport

SendMessageA2A is treated as one host transport idea. The product requirement is transport-neutral: different context-isolated lens units must revisit contested claims under teamlead-controlled deliberation.
