> Status: **design v4 — triple cross-validated, awaiting approval to implement.** Source: root-cause workflow `wf_e740c3a4-4d3`. Cross-validated by (1) onto self-review (`.onto/review/20260619-a8d17f8b`, 8 material, 0 blocker), (2) ultracode design-review (`wf_be2196bc-424`, 22 confirmed, **sound_with_revisions**, 0 blocker), (3) codex-CLI 3-perspective review (3 HIGH + mediums, sound direction, 0 blocker). **v3 split secret/sensitive-data filtering to Track 2** (`20260619-deterministic-sensitive-data-source-safety-preprocessing-design.md`). **v4 fixes the codex-CLI HIGHs**: M4b does NOT reuse `candidate_limitation_refs` (authority mix) → dedicated `revision_blocker_limitation_refs`; G needs a loader extension + dynamic obligation proof (the loader currently drops obligations); M1.5 row-narrowing would regress codex-R3-2 → DEFERRED behind the §6 lineage-binding prerequisite. Full analyses: `20260619-reconstruct-silent-defect-rootcause-analysis.json`.

## 1. Goal & completion criteria

**Goal**: stop the structurally-guaranteed regeneration of silent-defect findings in reconstruct by making each load-bearing property a *single derived-and-enforced contract*, instead of hand-re-asserting it at every disk-replay stage.

**Refined root cause (v2)**: the property is not merely "implemented as scattered re-assertions" — for the P1s the **contract already exists in the registry** (`validate_baseline_rows_cover_selected_purpose_frame_required_elements` registry:2546; `validate_matrix_row_ids_are_stable_and_baseline_row_refs_close` registry:2564/:2582) **but has no live runtime enforcer** (`validateMaturationBaseline:716`, `validateActionabilityMatrix:1003` iterate present rows only). This is the repo's own canonical root cause (`declared≠wired`). So M1 does not *invent* an invariant — it **wires the already-declared obligation**, and G must guard that every declared obligation has a live enforcer.

**Done-when**:
- The three P1s FAIL validation (deleted/extra/duplicated required row; matrix drops a baseline row; `claim_scope` omits non-closed rows) — enforcing the registry obligations that already exist. *(M1.5 mixed-lineage tightening is NOT in this PR's scope — deferred behind the §6 lineage-binding prerequisite, see M1.5.)*
- Every load-bearing property has ONE enforcer, and G fails CI if any declared `validation_obligation` has no active validator assertion (`declared≠wired` becomes a build error, not a review round).
- Dual-case drift tests exist for each invariant (delete a member / mutate a carried value / over-budget item / closed-row-must-not-trip-frontier / unresolved non-reuse proposal). *(secret-bearing-ref dual → Track 2.)*
- `npm run test:vitest` + guards green; concept surface net-neutral-or-down (helpers *enforce existing obligations* and replace per-field blocks; net-new obligation concepts = 0).

## 2. Root cause (one line)

Every reconstruct stage trusts the artifact it is handed and checks only that *present* records resolve; **no stage derives the closed expected set/value from the single upstream authority and asserts conservation** — even where the registry already *declares* that obligation. The guarantee is therefore unenforced, re-leaks at the next un-guarded hop, and round count is bounded by chain length, not fix quality.

## 3. High-level design — four single-owner mechanisms

### M1 — Derive-from-authority + conservation  *(rank 1; maturation-validation.ts; THIS PR)*

Closes the conservation/coverage members of the P1 trio + #22 (~11–13 findings). Wires obligations the registry already declares.

1. **`deriveExpectedBaselineTuples(selected)`** → the **closed universe** of `(purpose_element_id, actionability_surface_ref, maturity_dimension_ref)` tuples, enumerated from `selected.adequacy_frame.required_elements[].actionability_surface_refs × maturity_dimension_refs` — the *same* triple-nested enumeration the baseline builder (`buildMaturationBaselineArtifact:525-558`) performs, so builder and validator share one universe. **Coverage authority is the TUPLE, not the id (codex M-2)**: `baseline_row_id` is itself a slug/truncate projection, so keying coverage on it re-introduces the collision risk. Diff on the **`(element, surface, dimension)` tuple** (mandatory one row per tuple); verify `baseline_row_id` SEPARATELY as a derived stable-id projection (its own determinism check). Both are checked; neither substitutes for the other.
   - `validateMaturationBaseline`: diff present rows' tuples against the expected tuple set → `missing_required_coverage` (absent tuple), `duplicate_id` (two rows on one tuple), `conflicting_state` (tuple not in authority).

2. **`assertProjectionConservation({ upstreamIds, downstreamRefs, requireOneToOne, code })`** — generic "no member dropped/added/duplicated across a hop", keyed on the **raw `baseline_row_id`** values stored in `matrix.rows[].baseline_row_refs` (NOT the slugged `matrix_row_id`). `upstreamIds = baseline.baseline_rows[].baseline_row_id`, `downstreamRefs = flatten(matrix.rows[].baseline_row_refs)`, assert `baseline_row_refs.length===1` per matrix row and a 1:1 cover.
   - `validateActionabilityMatrix`: 1:1 baseline↔matrix on raw ids, **PLUS matrix-row PAYLOAD field-equality (codex M-1)** — after resolving the single `baseline_row_ref`, assert the matrix row's `purpose_element_ref / actionability_surface_ref / maturity_dimension_ref / materiality_ref / member-lineage / CQ+assessment refs` EQUAL the baseline row's (a row can cite baseline A while mutating those fields). Only maturity/support/limitation/readiness may change by validated rules.
   - `validateMaturationContinuationDecision`: recompute included/excluded from `actionabilityMatrix.rows` (closed→included; non-closed→excluded), assert `decision.claim_scope` equals it. **Plumbing (codex M-3)**: it currently does NOT receive `maturationBaseline` — threading it requires updating `validateMaturationContinuationDecision`, `writeMaturationContinuationDecisionValidationArtifact`, the run.ts call sites, the tests, AND the registry `maturation-continuation-decision-validator.input_authority_refs`.

3. **`assertCarriedValueConserved({ upstream, downstream, field, mode })`** — `mode ∈ {equal | superset}` (drop the ambiguous word "unchanged"; onto issue-007/ultracode #3,#15).
   - candidate-ref hops (baseline↔candidate, matrix↔baseline): `equal`.
   - `decision.limitation_refs`: **`superset` only** — it legitimately carries EXTRA builder-derived refs (ontology-expansion subject_ids, convergence ref), so no one-to-one/no-extra assertion. The expected lower-bound set is authority-DERIVED: `candidate ∪ row ∪ ontology-expansion ∪ convergence`, require `decision.limitation_refs ⊇` it.
   - **Carve-out (ultracode #15)**: the convergence/final-requestion guard (`actionable_ready ⇒ no_new_material_question`) and the analogous material-frontier / candidate-limitation `actionable_ready` guards are **state-vs-status** predicates, NOT carried-value checks — keep them as their own standalone gates, do not route through the carry helper.

4. ~~Re-anchor the frontier conservation check to authority~~ — **DROPPED (onto issue-003/ultracode #2,#4,#20)**. `member_readiness` is a runtime-computed state with no authority source; re-anchoring would falsely demand a frontier question for legitimately closed(L4)/limitation-backed required rows. Keep the frontier check's narrow correct property (`member_readiness==='frontier_required'` ⇒ a question exists). Deleted-row closure is owned by helpers 1+2. Add a **negative drift test**: a closed/limitation-backed required row must NOT trip the frontier check.

5. **M1.5 — mixed-lineage exemption (ultracode #9; was UNASSIGNED) — DEFERRED, prerequisite-gated (codex H-C)**: the over-permissive `mixed_lineage_missing` exemption (mat-val:788-801) is a predicate-scoping bug no conservation helper can fix. **But the v3 "narrow to row-scoped now" would REGRESS the codex-R3-2 fix** — the current contract/test deliberately accept a `limitation_backed` candidate/frame as justifying a mixed-lineage gap. Row-only narrowing would false-positive those valid candidates. So M1.5 **does NOT land in this PR**: the structured candidate-limitation→row-lineage binding (the §6 decision) is a **prerequisite**, not optional. This finding is **partially closed** in Track 1 (named, not fixed); the predicate-tightening waits on the lineage-binding design. Stated explicitly in §1 done-when scope.

Tradeoff: medium-high; self-contained to one file; reuses existing failure vocabulary; net-new obligation concepts = 0.

### M2 — Source-evidence reserve under the real prompt budget  *(run.ts; THIS PR)*

Closes the #1 evidence cluster (~6–7). **Corrected (onto issue-001/008, ultracode #7,#22)**: the 50K cap (`COMPETENCY_QUESTION_ASSESSMENT_PROMPT_CHAR_LIMIT`) governs the WHOLE prompt; `source_evidence` is one field. M2 owns only the **evidence reserve**, not the whole envelope.

- `boundForPromptBudget(items, budgetChars)` measures the actual serialized evidence and returns `{kept, stub, omitted}`. `budgetChars` is the **evidence reserve, derived** = `PROMPT_CHAR_LIMIT − measuredNonEvidenceChars − margin`, not the static 24K. **Pin the build order (codex M-4)**: per batch — (1) serialize the non-evidence payload (questions/claim-map/validation/policy) with EMPTY evidence + the system prompt, (2) measure it, (3) derive the reserve `= LIMIT − measured − margin`, clamp `≥ 0`, (4) bind evidence via `boundForPromptBudget`, (5) keep the 50K terminal assert. Add a large-non-evidence + evidence dual.
- The **batch builder remains the owner of the 50K-minus-reserve whole-prompt check**, and `assertPromptPayloadCharLimit`'s fail-loud halt (run.ts:8224/8263) **stays** as the terminal guard — when non-evidence alone exceeds the limit the run must still loud-halt (the fix converts *some* halts to delivered bounded payloads; it cannot eliminate the terminal guard).
- **Retain a candidate pre-cap** (do NOT delete `EVIDENCE_CANDIDATE_LIMIT` — it is a real pre-serialization cost guard; keep it as a constant or a derived internal ceiling inside the one function). Only `EVIDENCE_EXCERPT_LIMIT` is genuinely redundant.
- Count `evidence_body_omitted_for_budget` as **omitted, never projected** (R7-5); instruct the assessor a stub is insufficient body evidence. Reserve direct-question + domain-semantic evidence slots BEFORE the candidate pre-cap (R7-2).

### M3 — Per-kind capture-size policy + seed-stage snapshot  *(target-material-kind.ts / run.ts)*

> **Secret/sensitive-data filtering moved to Track 2** (`20260619-deterministic-sensitive-data-source-safety-preprocessing-design.md`). The reviews confirmed capture-size alone cannot close the secret-exposure hole (a typical `.env` < 6K still projects whole), so secret protection is its own deterministic, opt-in preprocessing track. M3 here keeps only the capture-size policy + resume snapshot; it makes **no secret-exposure closure claim**.

- **(a) Policy collapse**: ONE per-kind policy module `{captureCeiling, fullExcerptEligible}` **imported by both** the capture owner **`src/core-runtime/reconstruct/materialize-preparation.ts`** (codex M-5 — the *actual* capture owner; the v3 "target-material-kind.ts/run.ts" omitted it, leaving the capture→projection hop half-closed) **and** `run.ts:isFullExcerptProjectionEligible` + the truncation sink + the resume fallback (currently re-threaded at run.ts ~:5700/:5724/:5831/:5882). Mechanical de-duplication (concept-economy ↓).
- **(a-default) Capture-size baseline**: an **explicit** positive language-extension allowlist (codex M3a low — enumerate it; no `…`, shared constant) — `.ts/.js/.py/.go/.rs/.java/.c/.cpp/.cs/.rb/.php/.swift/.kt/.scala/…` earn whole capture; other code-classified extensions (config/data) default to the bounded sample. **Quality + cost** default, a defense-in-depth *partial* volume reduction — **not** secret closure (Track 2). Fail-safe: unknown extensions default to bounded. Duals: allowlisted code whole-captured + truncation surfaced; config/data bounded.
- **(c) Seed-stage observation snapshot (ultracode #10; codex M-6)**: on resume, the `length!==1` fallback measures the POST-maturation observation set, silently dropping the single-document truncation event (run.ts:13146). Persist the pre-maturation projected set as a **canonical artifact** `seed-stage-prompt-source-observations.yaml` (or a `seed-stage-projection-truncation-manifest.yaml`) with a registry authority entry, included in the run-manifest and the reuse-match hash; the resume fallback measures the snapshot. Dual: a resumed single large truncated document + a maturation-accepted source request must still emit the truncation event.
- Note: reverting R2-3 whole-capture entirely re-opens the #21 partial-file seed-authoring defect — not a free win.

### M4 — Deterministic revision coverage  *(SPLIT; v4-corrected authority — codex-CLI H-A all 3 perspectives)*

**Correction (v3)**: `run.ts:1449` is the **stop gate** (`stopDecisionAllowedDecisions`), NOT claim projection. The `actionable_ready` leak lives in **maturation-validation.ts** (the continuation builder/validator carry no `revisionProposal`). M4 is **not** "independent / any order / contained to run.ts".

- **One `isRevisionBlocker(p)` predicate, used consistently (codex M-7)**: define ONE predicate and use it identically at the stop gate AND the continuation gate. Decide its set explicitly: `reject|defer` block; `extend|rename|split` are **disclosed** (all non-reuse) but the blocking set is the same at both sites — no `reject|defer` here vs `non-reuse` there inconsistency.
- **M4a (run.ts)**: deterministic disclosure append (all non-`reuse`); **sanitize/resolve `target_id`** against known artifact ids before the append (run.ts:9834 — only `failure` target ids resolve today).
- **M4b (maturation-validation.ts; cross-dependency — sequence AFTER M1, NOT a free reuse)**: the public `actionable_ready` claim must not publish while a blocking proposal remains. **v3's "reuse `candidate_limitation_refs`" was WRONG (codex H-A)**: that field is the *selected purpose candidate's* authority and M1 asserts candidate↔baseline **equal** conservation; injecting revision blockers there mixes authorities and breaks M1's equal rule. Instead: add a **dedicated `revision_blocker_limitation_refs`** lower-bound that the continuation **builder derives from `revision-proposal-validation.yaml`** and the **validator requires present in `decision.limitation_refs`** (superset) + rejects `actionable_ready` when any blocker remains. The continuation validator must **consume `revision-proposal-validation.yaml` directly**, declared in the registry `maturation-continuation-decision-validator.input_authority_refs`. Dual at the continuation layer (not only run.ts text). This is a real boundary expansion (§5).

### G — Obligation-coverage + field-parity gate  *(governance; reframed; onto issue-002, ultracode #1,#6,#11,#13)*

**Reframed**: the sha is already runtime-derived; the P1 obligations are already *declared* but unenforced. The promotion/sha framing misses the real gap. **v4 prerequisite (codex H-B)**: `loadReconstructContractRegistry` currently **drops `validation_obligations`/`conditional_validation_obligations`** from its parsed type, so a loader-based coverage gate would run on empty data (vacuous). G's first step is to **extend the registry loader/types to preserve obligations** (or a typed raw-YAML walker). G = these concrete, **mandatory** parts:

- **(a) Obligation-coverage gate — dynamic proof, not a static map (codex H-B)**: a static `obligation_id → assertion_handle` map is just another declared-only table. Instead, validators **record the obligation ids they actually asserted** (e.g. emit `asserted_obligation_ids` in the validation artifact, or a CI fixture that executes each validator path and captures invoked handles). The gate fails CI when an **active** obligation has no recorded assertion on its validator path. **Scope by tier (codex medium)**: `validator_records.validation_obligations` = mandatory-active; conditional obligations = mandatory once their activation predicate is implemented; `planned_validator_records` = a separate *planned-coverage* status (not forced to active). For the P1 obligations, M1's helpers are the recorded enforcers (M1 duals reference the obligation ids).
- **(b) Field-parity guard with a real registry home (codex M-8)**: add a registry node `prompt_projection_contracts.competency_question_assessment` declaring `{payload_fields, policy_fields, budget_fields}` explicitly; the guard compares that exact declared set against `competencyQuestionAssessmentProjectionContract()` payload/policy keys + the M2/M3 budget/eligibility constants — fail on any added/dropped field. (Do not compare against an ad-hoc `Object.keys(...) + constants` that mixes payload and nested-policy fields.)
- **(c) Append-sections registry model (codex M-9)**: add a structured registry list `{section_id, heading, activation_predicate, append_owner, provenance_binding_required}` from which BOTH the prompt policy `deterministic_runtime_append_sections` AND the provenance bindings derive (runtime currently has underscore prompt ids + hyphen provenance ids + conditional sections). Include `unresolved_revision_proposals`. Drift-test add/drop.
- Register all as net-NEW parity checks in the `check-invariant-drift` aggregator (no registry-aware guard exists to "extend"). G closes "declared obligation with no live enforcer" + "prompt-surface shape desync" — no "closes the cluster as a class via promotion/sha" overclaim.
