# 이론 계열 적합성: 믿음 개정·진리유지·근거와 출처

- 계열: AGM 믿음 개정 / TMS·ATMS(진리유지) / justification 기반 추론 / W3C PROV / 양시간 모델링 / 이벤트 소싱
- 작성: 2026-07-31, 재설계 미션 탐색 서브에이전트
- 판정 요약: **component_candidate** — 어떤 core 계열을 고르든 그 아래에 깔려야 하는 "장부·개정·근거 계층"이다. R4·R5·R7의 사실상 유일 후보이고 R2에 부분 답을 주지만, R1(귀납)과 R6(다형 소스 통일)에는 침묵한다. 이 계열만으로는 논리 체계가 생기지 않는다 — 이미 생긴 논리 체계가 **무너지지 않게** 한다.

---

## 1. 미션 용어로 번역: 이 계열이 하는 일

이 계열의 공통 전제는 하나다: **결론은 명제이고, 명제는 근거 위에 서 있으며, 근거가 무너지면 무엇이 같이 무너지는지 계산할 수 있어야 한다.** 각 이론이 이 시스템에서 맡는 일로 번역하면:

| 이론 | 이 시스템에서 하는 일 |
|---|---|
| AGM 공준 (Alchourrón·Gärdenfors·Makinson 1985) | 개념/규칙이 충돌할 때 "무엇을 버리는 게 합리적인가"의 **규범**. 핵심 요구는 entrenchment(고착도) 순서 — 충돌 시 덜 고착된 믿음부터 철회한다. 알고리즘이 아니라 채점표다. |
| JTMS (Doyle 1979) | 모든 판정 노드에 justification(근거 링크: 어떤 전제·규칙에서 나왔나)을 달고, 전제가 철회되면 **의존 전파로 무너지는 결론만 정확히 무효화**한다. 단일 일관 문맥 유지. |
| ATMS (de Kleer 1986) | 결론마다 "어떤 가정 집합 아래서 성립하는가"의 라벨을 유지해 **경쟁 해석을 동시에 보유**한다. "이 코드는 의도된 로직이다" vs "우발적 잔해다"를 가정으로 놓고 증거가 한쪽 environment를 죽일 때까지 병존시키는 그림. |
| justification 기반 추론 | review 판정이 "틀렸다"가 아니라 **어느 전제(어느 소스 구간, 어느 규칙)가 판정을 지탱하는지의 유도 트리**를 내놓게 한다. 고칠 곳 = 실패한 justification의 전제 위치. |
| W3C PROV (PROV-DM/PROV-O) | "이 개념은 어느 reconstruct 실행이, 어느 소스 구간에서, 어느 추출기 버전으로 도출했다"를 적는 **표준 어휘**(Entity/Activity/Agent, wasDerivedFrom/wasGeneratedBy/used). 교환 형식이지 추론기가 아니다. |
| 양시간(bitemporal) 모델링 | valid time("이 개념이 구현물에 대해 참이던 기간")과 transaction time("논리 체계가 그걸 알게 된 시점")의 분리. **과거 판정을 소급 정정하되 당시 무엇을 믿었는지의 감사 기록은 보존** — 재검토·되돌리기의 기반. |
| 이벤트 소싱 | 온톨로지를 가변 YAML이 아니라 **append-only 개념 이벤트 로그(asserted/split/renamed/retracted + 근거)의 결정론적 투영**으로 정의. 되돌리기 = 이벤트 이전 시점 재투영, 증분 = 투영 캐시. |

한 문장으로: AGM이 "무엇을 버릴지"의 규범, TMS가 그 계산기, justification·PROV가 기록 형식, 양시간·이벤트 소싱이 저장 구조다.

## 2. R1~R7 중 실제로 답하는 것 — 어떻게

전부 답하지 않는다. 답하는 것은 R4·R5·R7 (강), R2 (부분), R1 (약한 보조).

### R4 진화 시 무모순 유지 — 이 계열의 본진

- **충돌 탐지**: 새 개념/규칙 이벤트가 들어올 때, 기존 판정 중 그 개념을 justification 전제로 쓰는 노드를 역방향 탐색하면 영향 집합이 결정론적으로 나온다. "무엇을 철회하면 무엇이 무너지는가"가 그래프 도달성 계산이 된다 — LLM 재판정 없이.
- **해소 순서**: AGM이 요구하는 entrenchment 순서는 onto-mcp에 이미 있다 — **Authority 8단 위계가 조야한 entrenchment다** (lexicon rank 1 > principles rank 2 > 계약 rank 5 > 구현 rank 6). 충돌 시 낮은 rank가 굽힌다는 규칙이 이미 운영 중이고, 이 계열은 그걸 기계 계산 가능하게 만든다. 단, **동일 rank 내 충돌**(lexicon 개념 둘이 충돌)의 순서는 위계가 정해주지 않는다 — §4 깨지는 지점 참조.
- **되돌리기**: 이벤트 소싱이면 철회 = 보상 이벤트 추가, 재투영으로 임의 시점 복원. 양시간이면 "그 판정은 당시 믿음 기준으로는 옳았다"를 보존한 채 정정할 수 있다. 현행 development-records/가 사람용 transaction-time 기록인데, 이걸 기계가독으로 승격하는 그림이다.
- 반복 개정(개정의 개정)은 AGM 원형이 못 다루고 Darwiche-Pearl 반복 개정(1997)이 규범을 보강하지만, 구현 표준은 없다 — 규범으로만 참조.

### R7 판정의 유용성 — justification이 "왜"의 자료구조다

review 산출이 `{verdict, justification: {전제 노드들(소스 구간 해시·규칙 id·선행 판정 id), 판정 주체(모델·프롬프트 해시), 시각}}` 형태를 강제당하면:
- "왜" = justification 트리 그 자체. 프롬프트로 설명을 뽑는 게 아니라 구조가 설명이다.
- "무엇을 고쳐야" = 실패한 판정의 전제 중 대상물 쪽 전제의 위치(span). 규칙 쪽 전제가 문제면 그건 논리 체계 자기 개정 신호다 — **고칠 곳이 대상인지 이론인지가 전제의 종류로 구별된다.** 이 구별은 이 계열 없이는 표현 자체가 안 된다.
- 현행 review의 obligation-coverage ratchet·materiality guard는 판정 품질을 사후 검사하는데, justification 강제는 그 검사를 산출 시점의 스키마 제약으로 앞당긴다 (LLM/역량 경계 원칙과 정합: 금지 반복 대신 비수용).

### R5 비용과 증분성 — TMS가 곧 증분 재계산이다

- 캐시 무효화의 단위 = justification 전제. 소스 파일이 바뀌면 content_sha256이 바뀐 span을 전제로 쓰는 판정만 stale. 규칙이 바뀌면 그 규칙을 전제로 쓰는 판정만 stale. 나머지는 손대지 않는다.
- **현행 onto-mcp의 `content_sha256 + extractor_logic_sha256` 재사용 키가 정확히 이것의 원형이다** — 입력 해시 + 규칙 해시가 바뀌면 재계산. 다만 현행은 추출물(inventory) 한 층에만 있고, 이 계열은 같은 키 규약을 **판정 그래프 전체로 일반화**하라고 말한다. 개념 경제상 신규 개념이 아니라 기존 reuse-key 개념의 확장으로 도입해야 한다.
- 투영 증분(이벤트 N까지의 투영 캐시 + 이후 이벤트만 fold)은 이벤트 소싱의 표준 기법.

### R2 자기적용의 정합성 — 부분 답: 자기승인을 구조로 차단

- justification 그래프에 **well-foundedness(정초성) 검사**를 걸면 순환 권위가 결정론적으로 잡힌다: 모든 판정은 유한 단계 안에 **전제 노드(axiom)** — 소스 아티팩트 해시, 또는 owner 결정 기록 — 에 닿아야 한다. 개념 A의 근거가 A 자신(또는 A에서 유도된 판정)이면 그래프 사이클이고, 사이클 검출은 하드 블록 가능한 구조 위반이다 (결정론 판정이므로 하드 블록 규약에도 맞다).
- 부트스트랩 첫 고정점에 대한 이 계열의 답: **고정점은 믿음 집합 밖에 있다.** 소스 구현물(해시로 고정)과 owner의 명시 결정만 axiom이 될 수 있고, 논리 체계가 스스로 생성한 판정은 영원히 derived다. 이건 "무한퇴행을 끊는 곳"을 지정하는 답이지, "그 axiom이 좋은 axiom인가"에 대한 답은 아니다 — 후자는 R1의 문제이고 이 계열은 못 답한다.

### R1 노이즈로부터의 이론 귀납 — 보조 장치 하나만

ATMS 스타일로 "이 패턴은 의도다/잔해다"를 경쟁 가정으로 병존시키고, 이후 관측(반복 출현, 테스트가 참조, 다른 소스와 정합)이 한쪽 environment를 죽이게 할 수 있다. 그러나 **가정을 생성하고 판별 증거를 대는 것은 전부 이 계열 밖의 일**(LLM 의미 판정 또는 통계/압축 계열)이다. 이 계열은 경쟁 가설의 장부만 대준다. R1의 답이라고 쓰면 과대 계상이다.

### 답하지 않는 것
- **R1 본체**: 믿음이 이미 명제로 존재한다고 가정한다. 귀납은 남의 일이다.
- **R3**: 결정론/LLM 경계에 대한 함의는 있으나(장부는 결정론, 링크 생성은 의미 작업) 경계 설계 자체는 이 계열의 내용이 아니다. §4-2의 난점이 오히려 R3를 어렵게 만든다.
- **R6**: PROV 어휘가 형식 무관이라는 소소한 장점뿐, 코드/문서/시트를 같은 지평에 올리는 내용이 없다.

## 3. 현행 onto-mcp가 이미 하고 있는 부분 (중복 도입 금지 지점)

| 현행 | 이 계열에서의 위치 | 처분 |
|---|---|---|
| Authority 8단 위계 | entrenchment 순서의 조야한 형태 | **재사용·정밀화**. 새 순서 개념 도입 금지 |
| `content_sha256`·`extractor_logic_sha256` 재사용 키 (artifact-io.ts) | premise 해시 + 규칙 해시 = 캐시 무효화 단위 | **확장**: 한 층 → 판정 그래프 전역 규약 |
| `pipeline-execution-ledger.ts`, 관측 카탈로그 원장 | 실행 이력의 append-only 장부 원형 | **확장 후보**: 개념 이벤트 로그의 착지점 검토 |
| G6 드리프트 리포트, 보호키 변경 마커 | 수동·부분적 충돌 탐지 | justification 역탐색으로 **대체 가능** (장기) |
| development-records/ 전체 | 사람용 transaction-time 기록 | 기계가독 이벤트 로그가 생기면 서술 계층으로 남김 |
| obligation-coverage ratchet (한 방향 래칫) | 단조 강화 = 개정의 특수 사례(축소 금지 제약) | 일반 개정 모델의 특례로 흡수 가능 |
| INV-* 하드블록 = 결정론 위반만 | 사이클 검출·정초성 검사는 하드 블록 적격, 의미 충돌은 비차단 공시 | 기존 규약과 정합 — 그대로 |

즉 이 계열을 채택해도 신규 개념은 "justification 노드/링크"와 "개념 이벤트" 정도이고, 나머지는 기존 개념의 일반화다. 개념 경제 비용이 비교적 낮다.

## 4. 깨지는 지점 (이 미션에서의 실패 조건)

1. **R1 공백이 구조적이다.** 이 계열은 믿음을 관리하지 생성하지 않는다. core로 앉히면 "완벽하게 장부 정리된 빈 온톨로지"가 나온다. 귀납을 소유하는 다른 계열과 결합해야만 성립하고, 그 계열의 산출이 명제 꼴이 아니면(예: 임베딩·확률 분포) 접합면에서 다시 설계 문제가 생긴다.
2. **LLM 판정은 논리적 귀결이 아니다.** TMS의 보증("전제가 살아있으면 결론도 살아있다")은 justification 링크가 건전한 추론일 때 성립한다. 링크가 LLM 의미 판정이면 같은 전제에서 재실행 시 다른 결론이 나올 수 있다(비결정성·모델 교체). 처방은 있다 — justification에 모델·프롬프트 해시를 넣고 전제 불변이면 재판정하지 않는 결정론 캐시 규약 — 그러나 이건 "판정이 옳다"의 보증이 아니라 "재현된 것으로 친다"는 **운영상 결정**이다. 이 허구를 허구로 명시하지 않으면 장부가 주는 확신이 거짓 정밀이 된다. 고전 TMS에는 불확실성 표현이 없다 (확률 확장 연구는 있으나 성숙 구현 부재 — 확인필요).
3. **ATMS 라벨 폭발.** environment 라벨 계산은 최악 지수 복잡도로 알려져 있다. 162k줄 코드베이스의 span 단위로 "의도/잔해" 가정을 전면 병존시키면 현실적으로 터진다. 실전 형태는 JTMS(단일 문맥) 전역 + 미결 클러스터에만 국소 ATMS.
4. **동일 rank 내 entrenchment 미정.** AGM은 순서를 요구할 뿐 출처를 말하지 않는다. Authority 위계가 rank 간 순서는 주지만 rank 내 충돌(두 lexicon 개념의 충돌)의 세부 순서는 비어 있다. 사람 관여 최소 목표와 정면 긴장 — 자동 유도(사용 빈도? 도출 증거량?)는 이 계열 밖의 추가 설계다.
5. **AGM 공준은 런타임 검증기가 아니다.** 공준 준수 검사는 논리적 귀결 계산을 요구해 일반적으로 비싸거나 비결정적이다. 실무 축소형 = 유한 belief base(Hansson 계열) + 명시적 충돌 탐지 + 위계 기반 해소. "AGM 준수"를 완료 기준으로 걸면 반증 불가능한 기준이 된다.
6. **기록 강제의 운영 부담.** 모든 판정에 justification 강제는 쓰기 비용·아티팩트 부피·스키마 진화 부담(이벤트 버전업 시 투영기 마이그레이션)을 낳는다. 단일 사용자 도구의 assurance 수준을 넘는 중장비(전용 이벤트 스토어, RDF 스택)를 들이면 순손실 — git 버전 관리되는 append-only JSONL + 결정론 투영기 수준이 적정선이다.

## 5. 실재 구현체·표준 (성숙도·비용)

- **W3C PROV-DM / PROV-O** — W3C Recommendation (2013). 성숙 표준. 비용: 어휘(Entity/Activity/Agent, 관계명)만 차용하면 거의 무료; full RDF/트리플스토어 채택은 이 규모에 과잉. Python `prov` 패키지 등 도구 존재 (TS 생태계의 성숙 구현은 확인필요).
- **SQL:2011 temporal tables** — 표준. MariaDB·SQL Server·Db2 구현. 비용: RDBMS 도입 자체가 이 파일 기반 런타임에 이질적.
- **XTDB** — 양시간 DB(구 Crux), JVM/Clojure. 실재·활동적 (v2의 현재 상태는 확인필요). 비용: JVM 의존 — TS 단일 프로세스 런타임에 무겁다. 설계 참조용으로 가치.
- **Datomic** — transaction-time 불변 DB. 실재, 상용(무상 사용 가능 정책 이력 있음 — 확인필요). 단시간 축만이라 양시간엔 부족. JVM.
- **EventStoreDB** — 이벤트 소싱 전용 DB. 성숙. (Kurrent로 개명했다는 기억이 있으나 확인필요.) 비용: 운영 서비스 — 단일 사용자 도구엔 과잉. 적정 대체 = git 관리 append-only JSONL + 결정론 투영기(자작, 소규모).
- **JTMS/ATMS 구현** — 고전 참조 구현은 Forbus & de Kleer, *Building Problem Solvers* (MIT Press, 1993)의 Common Lisp 코드(JTMS/ATMS/LTMS). 유지보수되는 현대 TS/JS TMS 라이브러리는 아는 바 없음 (확인필요). JTMS 코어는 작아서(그래프 + 전파, 수백 줄 수준) 자작이 현실적이며, 오히려 기존 reuse-key 규약과 접붙이기 쉽다.
- **Darwiche-Pearl 반복 개정 (1997)** — 논문 규범. 구현 표준 없음. 규범 참조만.
- 인접: **Differential Dataflow**(Rust, 실재)는 R5 증분 뷰 유지의 일반해지만 도입 중량이 크고 이 계열 씨앗 밖 — 언급만.

## 6. 결합 조건과 판정

- **판정: component_candidate.** 재설계의 core(귀납·표현 계열)가 무엇이 되든, 그 산출을 (a) 근거 달린 명제로 착지시키고 (b) 소스 변경 시 증분 무효화하고 (c) 충돌 시 위계로 해소하고 (d) 언제든 재투영으로 되돌리는 계층으로 이 계열이 필요하다. R4·R5·R7을 이만큼 직접 계산 가능하게 만드는 다른 계열은 씨앗 목록에 없다.
- **채택 형태 권고(최소형)**: ① 판정·개념 산출 스키마에 justification(전제 해시 목록 + 규칙 id + 판정 주체 해시) 필수화 — submit 도구가 유일 수용 경로, 누락은 비수용. ② 개념 변경을 append-only 이벤트로, 현행 YAML은 투영 산출물로 강등. ③ 정초성(사이클 0) 검사를 하드 게이트로. ④ ATMS는 전역 도입 금지, 미결 클러스터 국소 한정. ⑤ 전용 DB 도입 없이 git+JSONL.
- **경계 명시**: 이 계열이 주는 확신은 "장부가 맞다"까지다. "믿음이 맞다"는 R1을 소유한 계열과 검증 규율(반증 가능한 완료 기준)이 책임진다. 둘을 혼동하는 순간 — §4-2 — 이 계열은 거짓 정밀의 공급원이 된다.
