# 이론 계열 적합성: 프로그램 분석 기반 — 사실 그래프의 실제 생산 수단

- 날짜: 2026-07-31
- 계열: Code Property Graph / SCIP·LSIF / Kythe·Glean / tree-sitter / stack graphs / 추상해석 / e-graph / 증분 계산(Salsa 계)
- 판정: **component_candidate** — 논리 체계의 핵심이 아니라 논리 체계가 딛고 서는 **사실층(fact substrate)의 생산 수단**. R1의 반증 절반·R3·R5·R7의 앵커링에 강하고, R1의 귀납 절반·R2·R4에는 침묵한다.

## 1. 이 계열이 이 시스템에서 하는 일 (미션 용어 번역)

학계 용어를 걷어내면 이 계열의 산출물은 전부 한 문장으로 수렴한다: **"구현물에 대한 결정론적으로 재생산 가능한 사실의 그래프"**. 노드는 (심볼, 정의, 파일, 범위), 엣지는 (정의–참조, 포함, import, 호출, 상속), 모든 노드가 소스의 바이트 범위와 content hash로 앵커된다.

이 미션에서 그 그래프가 맡는 역할은 세 가지다.

1. **반증 표면**: LLM이 귀납한 개념 주장("X 개념은 이 다섯 파일이 구현한다", "이 필드는 죽었다")을 그래프 질의로 검사 가능하게 만든다. 주장이 그래프와 어긋나면 결정론이 기각한다. 이것이 R1의 "판정 근거는 무엇이고 어떻게 반증되는가"의 절반이다.
2. **판정의 실행 형태**: "논리 체계가 결론을 낸다"에서 구조적 결론은 그래프 질의 실행이다. CodeQL/Datalog/Angle이 이 형태가 실전에서 성립함을 이미 증명했다 — 보안 취약점 판정을 프롬프트가 아니라 질의로 산업 스케일 운영 중.
3. **증분성의 단위**: 파일 content hash + 추출기 로직 hash가 캐시 키, 크로스 파일 엣지의 의존 클로저가 무효화 단위. rust-analyzer(Salsa)가 이 문제의 정답 모양을 이미 갖고 있다.

핵심 통찰: 이 계열에서 이식할 가치가 있는 것은 **언어별 파서 기술이 아니라 사실 그래프 데이터 모델과 그 운영 규율**(출처 앵커, 결정론적 재생산, 증분 키, soundness 라벨)이다. 파서는 수단이고 교체 가능하다.

## 2. 씨앗 질문에 대한 답: 타입체커 없는 name resolution은 실재하는가

**결론: 일반해는 실증적으로 죽은 길이다.** 이 질문에 정면 도전한 유일한 산업 구현이 GitHub stack graphs였다 — tree-sitter 문법 위에 언어별 name binding 규칙을 선언적 DSL(.tsg)로 쓰고, 빌드·컴파일러 없이 파일 단위 증분으로 정의–참조를 해석한다. 2026-07 현재 **github/stack-graphs 저장소는 public archive, "no longer being maintained" 명시**. GitHub 스케일의 투자로도 언어당 규칙 저작·유지 비용이 컴파일러 래핑 대비 수지가 안 맞았다는 것이 합리적 해석이다(공식 사유 미공표 — 해석임을 명기).

산업 수렴점은 반대쪽이다: **언어당 실 컴파일러/타입체커를 래핑한 인덱서**가 표준 포맷(SCIP)으로 사실을 내보낸다. scip-typescript는 TS 타입체커 위에, scip-java는 javac 위에, Glean의 C++ 인덱서는 clang 위에 서 있다. 즉 "정밀 참조 엣지"와 "언어당 툴체인 회피"는 현존 기술에서 **양립하지 않는다**.

따라서 이 미션의 실제 선택지는 이분법이 아니라 **정밀도 계층**이다:

| 계층 | 수단 | 얻는 것 | 비용 |
|---|---|---|---|
| T2 정밀 | 언어당 SCIP 인덱서 (TS·Python·Java 등 주요 언어만) | sound에 가까운 def–ref·타입 참조 | 언어당 인덱서 운영, 대개 의존성 설치/빌드 필요 |
| T1 근사 | tree-sitter 심볼 + 휴리스틱 결속(동일명·import 경로 매칭) | 참조 **후보** 엣지, unsound 명시 라벨 | 현행 자산 재사용, 오탐 관리 |
| T0 러프 | layout observer (현행) | 구간·포함관계 | 이미 있음 |

이 계층화는 현행 repo가 이미 채택한 모양(Tier 2 tree-sitter 정밀 / Tier 1 layout 러프)의 자연 연장이다. 신규 축은 "엣지의 soundness를 사실의 속성으로 명기"하는 것 — 근사 엣지를 정밀 엣지와 같은 스키마에 넣되 신뢰 등급을 붙여, 소비자(LLM 판정·review 질의)가 등급별로 취급을 달리하게 한다.

## 3. R1~R7 적합 판정

### R1 노이즈로부터의 이론 귀납 — **절반 답함 (반증 절반)**
이 계열은 무엇이 개념인지 판정하지 못한다. 그래프는 외연(extension)이고 개념은 내포(intension)다. 그러나 노이즈 판별의 **결정론적 신호**를 공급한다:
- 죽은 잔해: 참조 유입이 0인 서브그래프 (도달 불가 정의, 소비자 없는 export)
- 유령 개념: 문서·이름에는 있으나 정의 노드가 0개
- 개념 분산: 같은 정규명이 N곳에 정의되고 상호 참조가 없음 (개념 경제 위반의 그래프적 형상)
- 응집: 참조 엣지 밀도가 높은 클러스터 = 개념 후보의 외연적 흔적

배선: LLM이 개념 가설을 내면, 각 가설에 "이 개념이 실재하면 그래프에서 성립해야 할 질의"를 붙이고 결정론이 실행한다. 카디널리티 0이면 가설 기각(공허 통과 방지 규율과 합동). 이것이 owner corpus의 LLM/역량 경계와 정확히 같은 절단면이다: **귀납은 LLM, 반증은 그래프 질의**. MEMORY의 "부재 주장은 전수 확인이 필요하다" 교훈도 이 배선의 근거다 — 부재 판정을 LLM의 grep 습관이 아니라 그래프의 전수 참조 엣지가 소유하면 그 실수 클래스가 구조적으로 닫힌다.

한계: 참조 엣지가 unsound한 언어(동적 디스패치·리플렉션·DI 프레임워크)에서는 "참조 0"이 죽음의 증거가 못 된다. soundness 라벨이 있어야 반증 강도를 조절할 수 있다.

### R2 자기적용 정합성 — **침묵. 단 부트스트랩 재료는 공급**
무한퇴행·순환권위를 막는 논리는 이 계열에 없다. 다만 실용적 사실 하나: onto-mcp 자신이 TypeScript 단일 언어라서, scip-typescript(실 TS 타입체커 래핑)로 **자기 자신의 정밀 사실 그래프를 즉시, 싸게** 얻을 수 있다. 자기-reconstruct의 첫 대상에 한해 polyglot 문제를 풀 필요가 없다. 권위 고정점 문제 자체는 다른 계열(논리·증명 체계 쪽)의 몫.

### R3 결론과 action의 결속 — **강하게 답함**
이 계열의 최상 적합점. "실행 가능한 판정"의 실증된 형태가 그래프 질의다:
- 결정론이 소유: 그래프 생산, 질의 실행, 결과 카디널리티, 출처 앵커, 위반 경로 열거
- LLM이 소유: 의미 기준 → 질의로의 번역(질의 저작), 질의 결과의 중대성 판정, 고칠 방향 서술
- 수용 채널: 질의와 그 결과가 아티팩트로 직렬화되면 review 판정이 재실행·재검증 가능해진다 — "green은 실 경로 통과일 때만 신뢰"가 구조적으로 성립

CodeQL이 이 모양의 산업 증명이고, Glean/Angle이 Datalog류 질의가 일반 사실 저장소 위에서 성립함을 증명한다. 단 이 계열이 결속하는 것은 **구조적 결론**뿐이다. 의미적 결론("이 설계는 의도에 안 맞다")은 질의로 컴파일되지 않는다 — 그건 LLM 몫이고, 이 계열은 그 판정이 딛는 사실만 보증한다.

### R4 진화 시 무모순 유지 — **답 못함**
사실 그래프는 단조적 관찰의 스냅샷이다. 규칙 추가·수정 시 기존 판정과의 충돌 탐지(믿음 개정)는 truth maintenance/ASP 계열의 문제. e-graph는 동치류 유지이지 모순 해소가 아니다 — 이 미션에서 e-graph는 "같은 개념의 표기 변이를 하나의 동치류로 관리"라는 영감 수준 이상이 안 된다(도입 비용 대비 확실한 소비자가 없음).

### R5 비용과 증분성 — **강하게 답함, 그리고 현행과 연속적**
- 현행 `content_sha256 + extractor_logic_sha256` 재사용 키는 이미 Salsa식 메모 키의 원시형이다. 파일 단위 증분은 있다.
- 없는 것: **크로스 파일 엣지가 생기는 순간의 의존 추적**. 파일 A의 심볼을 B가 참조하면, A 변경 시 B의 엣지 캐시가 무효화돼야 한다. Salsa/rust-analyzer의 답: 질의가 읽은 입력을 기록하고(질의 의존 그래프), 변경 시 red-green 재검증(입력이 같으면 파생값 재사용). SCIP의 답: 인덱스가 문서(파일) 단위 청크라 파일 증분과 자연 합동, 크로스 파일 결합은 심볼 테이블 병합으로 후처리.
- 이 미션에 맞는 무효화 단위: 사실층은 **파일**(hash 키), 엣지층은 **심볼 의존 클로저**, 개념층(LLM 산출)은 "개념이 앵커한 사실 집합의 hash" — 앵커된 사실이 불변이면 개념 재귀납 불필요. 이 마지막 단계가 R5의 진짜 절약처다: LLM 재호출(비싼 쪽)의 캐시 키를 사실 그래프가 공급한다.

### R6 다형 소스 — **부분 답함: 참조가 명시적인 소스까지**
이 계열의 데이터 모델(정의–참조–범위–출처)은 코드 전용이 아니다. 소스별 사상:
- **스프레드시트: 의외로 최적합.** 셀 참조·명명 범위·시트 간 참조는 문법이 결정론적인 name resolution이다. 수식 의존 그래프는 사실 그래프에 손실 없이 올라간다. 기성 "SCIP for spreadsheets"는 없다고 판단(확인필요) — 자체 추출기 필요하나 문제 난도는 낮고, 현행 `spreadsheet-structure-observer.ts`가 이미 그 자리에 있다.
- **설정 파일: 부분.** 키 경로 정의와 코드 쪽 읽기 지점(`config.x.y` 접근, env var 읽기)을 근사 결속 가능. unsound 라벨 필수.
- **문서(prose): 구조적 참조만.** 링크·앵커·경로 인용·코드펜스 속 심볼명은 엣지가 된다. 그러나 서술이 코드와 의미로 연결되는 것("이 문단이 그 함수의 계약을 서술한다")은 명시 표기가 없으면 이 계열로 표현 불가 — 그 결속은 LLM이 만들고, 이 계열은 만들어진 결속의 앵커(양쪽 범위+hash)와 실효 검사(앵커가 깨지면 결속 재검토 플래그)만 소유한다.

즉 R6의 답은 "하나의 지평 = 사실 그래프 스키마"이되, **엣지 생산자가 소스마다 다르고 soundness가 다르다**는 것을 스키마가 정직하게 담아야 한다. Kythe/Glean 스키마가 이 일반화("typed facts about artifacts")의 선례다.

### R7 판정의 유용성 — **구조 절반 답함**
그래프 위 판정은 공짜로 다음을 담는다: 위반의 위치(파일+바이트 범위), 위반 경로(어떤 엣지 사슬이 규칙을 깨는가), 관련자 전수(같은 위반의 다른 인스턴스). "왜 틀렸는가"의 구조적 성분과 "무엇을 고쳐야 하는가"의 대상 열거까지가 이 계열의 몫이다. 고침의 **방향**(어떻게 고쳐야 의도에 맞는가)은 의미 작업이라 밖이다. 현행 review가 산출하는 finding에 그래프 앵커가 붙으면, finding의 재검증("그 위반이 아직 있는가")이 결정론화된다 — 지금은 그 재검증도 LLM이 한다.

## 4. 깨지는 지점 (이 계열이 이 미션에서 실패하는 조건)

1. **제로컨픽 polyglot 정밀 해석은 없다.** stack-graphs 아카이브가 실증. 14개 언어 정밀 참조 엣지를 원하면 14개 인덱서를 운영해야 하고, 그 대부분이 대상 repo의 의존성 설치·빌드를 요구한다(scip-java는 빌드 통합, scip-python은 의존성 환경). reconstruct가 "임의의 남의 repo를 클론 직후 관찰"하는 시나리오면 T2 정밀층은 자주 결항하고 T1 근사층이 실질 하한이 된다. **이 계열을 도입해도 근사 엣지 운영 규율(오탐 관리·soundness 라벨)은 피할 수 없다.**
2. **내포 없음.** 그래프는 "무엇이 무엇을 참조한다"까지만이다. 의도·계약·트레이드오프·왜는 표현 불가. 이 계열을 핵심으로 삼으면 시스템은 정밀한 크로스레퍼런스 브라우저가 되고 논리 체계는 안 생긴다. 개념화·판정 기준은 반드시 다른 층이 소유해야 한다.
3. **동적성의 벽.** 리플렉션, 동적 디스패치, DI 컨테이너, 문자열 기반 라우팅에서 정적 참조 엣지는 원리적으로 불완전하다. "참조 0 = 죽음" 추론이 이 지대에서 오판을 만든다(현행 MEMORY의 부재 오판 교훈과 같은 클래스). 완화는 soundness 라벨과 "부재 판정은 sound 엣지에서만" 규율이지 해결이 아니다.
4. **운영 부담의 실측치들**: Joern은 JVM 기반에 대형 코드베이스에서 메모리 부담이 알려진 운영 이슈(확인필요 — 정량치 미확인). CodeQL은 사적 코드 상용 분석에 라이선스 제약(GitHub Advanced Security 계약 필요로 알고 있음, 세부 확인필요) + 컴파일 언어는 빌드 필요. Glean은 Haskell/C++ 스택 운영 + 외부 채택 사례 얇음. Kythe는 유지보수 활동 축소로 판단(확인필요).
5. **추상해석은 이 미션에 과잉.** 수치 불변식·종료성·경계 증명이 필요한 미션이 아니다. 언어당 의미론 정의 비용이 막대하고 산출물(값 범위·도달성 정밀화)의 소비자가 이 시스템에 없다. 기각.
6. **그래프 자체의 노이즈.** 사실 그래프는 구현물의 우발적 잔해도 충실히 담는다(죽은 코드의 내부 참조도 엣지다). "사실이 많다"와 "이론에 가깝다"는 다르다 — R1의 귀납 없이는 그래프가 커질수록 노이즈도 정밀하게 보존될 뿐이다.

## 5. 현행 onto-mcp와의 중복 — 개념 경제 판정

**현행 repo는 이미 이 계열의 T0~T1을 자체 구현했다.** 중복 도입 금지 대상:
- `code-structure-observer.ts`(tree-sitter 14언어) + `code-layout-observer.ts`(grammar-free) = 계층화된 사실 생산자
- `CodeStructureInventory`(spans+hierarchy+imports+content_sha256+extractor_logic_sha256) = 사실 그래프의 노드층 + 증분 메모 키. SCIP의 Document/Occurrence 모델과 구조적으로 동형인 부분집합
- `spreadsheet-structure-observer.ts` = R6의 비코드 추출기 자리 선점
- `code-structure-inventory-projection.ts` + 40,000자 예산 절단 = 그래프→프롬프트 투영(이 계열엔 없는, 이 시스템 고유의 소비층)

따라서 개념 경제상 올바른 경로는 **신규 개념 도입이 아니라 `CodeStructureInventory`의 확장**이다: 기존 spans/hierarchy/imports에 `symbols`(정규 심볼 id)와 `edges`(def–ref·호출·상속, soundness 라벨 포함)를 더한다. SCIP의 심볼 명명 규약(패키지·디스크립터 경로로 전역 유일 id)은 확장의 **모양 참조**로 쓰되, SCIP 포맷 통짜 채택은 별개 결정이다(protobuf 의존·외부 인덱서 실행 파이프라인이 따라옴). 알려진 한계로 명기된 "상속/구현/호출/타입 참조 엣지 없음, name resolution 없음"이 정확히 이 계열이 채우는 델타다.

## 7. 종합 판정

**component_candidate.** 이 계열은 재설계의 "사실층" 컴포넌트로서는 대체재가 없다 — 반증 가능한 판정(R1 절반·R3), 증분성(R5), 앵커된 유용한 finding(R7 절반)은 전부 이 계열의 사실 그래프를 딛어야 성립하고, 현행 repo가 이미 그 하반부(T0~T1 + 증분 키)를 보유해 연속 확장이 가능하다. 그러나 핵심이 될 수 없다: 개념 귀납(R1 상반부)·자기적용 권위(R2)·믿음 개정(R4)에 원리적으로 침묵하며, 이 계열만으로 만든 시스템은 논리 체계가 아니라 크로스레퍼런스 인덱스다. 도입 형태는 CodeStructureInventory 확장(symbols+edges+soundness 라벨) + 정밀도 계층(자기적용·주요 언어는 SCIP 인덱서, 롱테일은 tree-sitter 근사) + 개념층 캐시 키 공급(R5의 LLM 비용 절약)이 개념 경제상 맞다.
