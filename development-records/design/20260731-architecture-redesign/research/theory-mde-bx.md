# 이론 계열 적합성: 모델주도공학(MDE) · 메타모델 탑(MOF) · 양방향 변환(bx)

- 작성: 2026-07-31, 근본 재설계 미션 연구 트랙
- 판정 대상: MOF M0–M3 탑, EMF/Ecore, ATL/QVT, lens/TGG 계열 양방향 변환, conformance 형식 정의, 모델 발견(MoDisco/KDM), 메타모델 공진화(Edapt/COPE), 메가모델링
- 종합 판정: **component_candidate** — 개념 4개(자기서술 동결 커널, 판정 가능한 conformance, correspondence trace, 공진화 연산자 목록)는 채택 가치가 있다. 도구 사슬(EMF 생태계)은 기각. 계열 전체는 R1(노이즈 귀납)을 문제 설정 밖에 두므로 코어가 될 수 없다.

## 1. 핵심 아이디어의 미션 번역

학계 용어를 이 시스템의 일로 번역하면:

| 학계 용어 | 이 미션에서 하는 일 |
|---|---|
| 메타모델(M2) | **논리 체계 그 자체.** "무엇이 개념이고, 개념 간 어떤 관계가 허용되는가"의 스키마. 현행 core-lexicon.yaml이 비형식적으로 이 자리에 있다 |
| 모델(M1) | 구현물 하나를 논리 체계의 어휘로 서술한 것 — reconstruct의 산출물 |
| M0 | 실 소스(코드·문서·스프레드시트) 자체 |
| M3 (MOF/Ecore) | 논리 체계를 서술하는 언어. **자기 자신으로 자기를 서술**해서 탑이 여기서 끝난다 |
| conformance | review의 결정론 절반: "이 모델이 메타모델이 허용하는 형태인가"의 **판정 가능한** 검사 |
| OCL 제약 | 구조 타이핑으로 못 잡는 불변식("순환 참조 금지" 등)을 모델 위에서 평가하는 술어 — 위반 시 **어느 요소가 어느 제약을** 어겼는지 위치가 나온다 |
| 모델 발견(model discovery) | reconstruct의 결정론 절반: 소스에서 모델을 기계적으로 뽑는 injector. 현행 tree-sitter → CodeStructureInventory가 정확히 이것이다 |
| 변환(ATL/QVT) | 모델→모델 사상. 이 미션에선 "온톨로지 투영"(프롬프트 투영, 렌즈별 뷰)에 해당 |
| bx / lens 법칙 | "소스가 바뀌면 모델이 어떻게 따라 바뀌어야 하는가"의 **정확성 정의**(GetPut/PutGet). 증분 동기화가 맞았는지 틀렸는지를 반증 가능하게 만든다 |
| TGG correspondence graph | 소스 요소 ↔ 모델 요소의 **추적 링크를 1급 산출물**로 유지 — 캐시 무효화와 "왜 이 판정인가"의 근거 배선 |
| 메타모델 공진화(coupled evolution) | 논리 체계가 바뀔 때 기존 모델(과거 reconstruct 산출물)을 어떻게 이행시키는가 — 진화 시 무모순 유지의 이 계열식 답 |
| 메가모델링(Bézivin) | 모델·메타모델·변환·추적 링크 자체를 노드로 갖는 상위 장부 — "논리 체계가 스스로를 파악한다"의 자료구조적 형태 |
| technical space (Kurtev/Bézivin) | grammarware(코드)·XML-ware(설정)·modelware를 injector/projector로 잇는 다형 소스 프레임 — R6의 이 계열식 답의 뼈대 |

핵심 전제를 한 문장으로: **"메타모델이 먼저 있고, 모든 것은 그에 대한 인스턴스이며, 수준 간 관계(conformance)는 결정론적으로 판정된다."** 이 전제가 이 계열의 힘(R2·R3)과 이 미션에서의 치명적 약점(R1)을 동시에 만든다.

## 2. R1~R7 판정 — 실제로 답하는 것

### R2 자기적용: 이 계열의 최강 답 — 단, 답의 성격을 정확히 읽어야 한다

MOF 탑이 무한퇴행을 끝내는 방식은 영리한 트릭이 아니라 **동결(fiat)** 이다. M3는 자기 자신의 인스턴스다(MOF는 MOF로 기술된다) — 표현의 퇴행은 이 구조적 고정점에서 끝난다. 그러나 "MOF가 옳은 메타메타모델인가"는 MOF 자신이 증명하지 않는다. 표준 기구가 한 번 비준하고 동결했을 뿐이다.

미션 번역: **부트스트랩의 첫 고정점은 계산으로 얻는 것이 아니라, 작고 안정된 커널을 사람이 1회 비준하고 동결하는 것이다.** 자기승인을 막는 것은 커널의 자기서술성(구조적 폐쇄)이 아니라 (a) 커널이 충분히 작아서 1회 검토가 가능하다는 것, (b) 커널 변경만은 사람 게이트를 통과한다는 것. Ecore가 20년 넘게 거의 안 바뀐 것이 이 전략의 실증이다 — 커널을 작게 잡으면 동결이 실제로 유지된다.

한계 두 가지를 정직하게:
1. 자기서술은 **구조** 수준에서만 성립한다. "이 논리 체계의 판정 규칙이 좋은 규칙인가"라는 의미 수준 자기평가는 탑이 답하지 않는다. review가 자기 자신의 렌즈 정의를 review할 때의 순환은 탑 바깥 문제다 — 여기엔 별도 장치(예: 커널 계층은 self-review 대상에서 제외하고 사람 비준으로 승격)가 필요하다.
2. 엄격 메타모델링(strict metamodeling: 요소는 정확히 한 수준 위 요소의 인스턴스)은 온톨로지 작업에서 삐걱댄다. "개념"이 어떤 문맥에선 타입이고 어떤 문맥에선 인스턴스인 상황(clabject 문제, Atkinson & Kühne)이 도메인 온톨로지에서 반드시 나온다. deep instantiation/potency로 푸는 다수준 모델링 연구가 있으나(MetaDepth, Melanee (확인필요: 현재 유지 여부)) 학술 단계다. 현행 .onto/domains의 concepts 파일이 이미 이 긴장을 갖고 있다 — 도메인 개념은 core-lexicon 개념의 인스턴스이면서 실 코드 요소의 타입이다.

### R3 결론과 action의 결속: 결정론 절반에 대한 정밀한 답

conformance + 제약 평가는 **판정 가능(decidable)** 하고, 위반은 **위치가 있다**(어느 요소, 어느 제약). 이것이 "논리 체계가 결론을 낸다"의 결정론 소유분에 대한 이 계열의 답이다:

- **LLM 소유**: 소스에서 모델로의 의미적 리프팅(이 함수 뭉치가 어떤 개념의 구현인가), 제약 후보의 저작, 위반의 중대성 판정.
- **결정론 소유**: 모델이 일단 존재하면 conformance 검사·제약 평가·추적 링크 유지·투영은 전부 기계다. LLM이 낸 모델이 스키마를 위반하면 **비수용**(invalid)이다 — 프롬프트로 금지를 반복할 필요가 없다.

이는 owner corpus의 LLM/역량 경계 원칙과 정확히 동형이다: 메타모델 = "필수 구조화 출력의 결정론적 submit 도구"의 스키마 부분. 현행 onto-mcp가 zod 스키마 + validator로 이미 하고 있는 것의 형식적 일반화다. 이 계열이 더 주는 것은 **제약 언어를 모델 위 1급 산출물로 두는 것**(OCL의 자리) — 지금은 불변식이 TypeScript 테스트 코드에 흩어져 있는데, 논리 체계가 자기 규칙을 "파악"하려면 규칙이 데이터여야 한다.

### R5 증분성: bx 계열의 주특기 — 개념은 채택, 법칙은 완화 필요

- **캐시 무효화의 단위 = correspondence trace(추적 링크).** TGG는 소스 그래프·타깃 그래프·둘을 잇는 correspondence 그래프를 함께 유지하고, 소스 델타가 오면 링크를 따라 영향받은 타깃 부분만 재계산한다. "구현물이 바뀔 때 전체 재구축 회피"의 자료구조적 답이 이것이다. 현행 content_sha256 + extractor_logic_sha256 재사용 키는 파일 단위 조잡한 버전이고, 요소 단위 trace가 그 정밀화다.
- **lens 법칙(GetPut/PutGet)은 증분 동기화의 정확성을 반증 가능하게 만든다** — "재구축 결과 = 증분 갱신 결과"라는 등식은 테스트로 놓을 수 있는 음성 통제군이다. 검증 규율(반증 가능한 완료 기준)과 맞물린다.
- 단, 법칙의 **완전한** 성립은 이 미션에서 불가능하다(§3-2). 채택 형태는 "법칙을 증명하는 bx 언어"가 아니라 "법칙을 **테스트로 감시하는** 증분 파이프라인"이다.
- 복잡도 정직 표기: TGG 매칭은 서브그래프 매칭(일반적으로 NP-hard)이라 실 도구들은 패턴 제한·증분 매칭 엔진으로 우회한다. correspondence 저장은 메모리를 많이 먹는다 — eMoflon::Neo가 런타임 모델을 Neo4j로 내린 이유가 이것이다.

### R4 진화 시 무모순: 부분 답 — 어휘와 연산자 목록은 주지만 믿음 개정은 없다

메타모델 공진화(COPE→Eclipse Edapt)는 이 문제를 정면으로 연구했다: 메타모델 변경을 **연산자 목록**(rename, extract-class, push-down… 각각에 인스턴스 이행 규칙이 딸린)으로 기록하고, 변경 이력을 1급 산출물로 저장하며, 기존 모델을 자동 이행한다. 변경을 breaking/non-breaking으로 분류하는 어휘도 준다. 미션 번역: **논리 체계의 개정은 diff가 아니라 이행 규칙이 딸린 연산자 열로 기록되어야 하고, 그래야 과거 reconstruct 산출물이 자동으로 따라오고 되돌리기도 연산자 역적용으로 정의된다.**

그러나 이것은 **구조 이행이지 믿음 개정이 아니다.** 개정된 규칙이 과거 review 판정과 충돌하는지(어제 PASS가 오늘 규칙으론 FAIL인지)는 재평가를 돌려야만 안다 — 공진화 프레임은 "무엇을 재평가해야 하는가"(trace를 따라 영향 범위 산출)까지는 주지만 충돌의 의미적 해소(어느 쪽 믿음을 버릴 것인가)는 주지 않는다. 그건 belief revision/truth maintenance 계열의 몫이다(별도 트랙 판정 사안).

### R7 판정의 유용성: 절반의 답 — "무엇을 고칠지"는 변환 규칙에서 공짜로 나온다

conformance 위반은 위치·제약 식별자가 붙어 나오므로 "왜"의 최소 형태는 기본 제공이다. 더 흥미로운 것은 TGG 기반 **consistency restoration**: 일관성 규칙 자체에서 수리 연산(repair rule)이 도출된다 — "규칙 r을 어긴 상태"에서 "r을 만족시키는 최소 편집"을 규칙으로부터 계산한다(short-cut rule 계열 연구, arXiv:2312.09828 등). 미션 번역: **review의 판정 규칙을 선언적으로 쓰면 '고쳐야 할 것'의 후보가 규칙에서 기계적으로 나온다** — 프롬프트로 "수정안을 제안하라"고 비는 것과 질적으로 다르다. 단, 이것이 되는 범위는 규칙이 선언적·구조적일 때뿐이고, 의미적 결함("이 추상화가 잘못됐다")의 수리안은 여전히 LLM 몫이다.

### R6 다형 소스: 뼈대만 답 — 동일 지평화가 구문 수준에서 멈췄다

technical space 프레임(모든 소스를 injector로 typed graph에 올린다)과 KDM(ISO/IEC 19506: 코드·데이터·UI·설정을 한 메타모델에)은 정확히 R6를 겨냥한 표준이었다. 정직한 결과: **표현의 균질화는 성공했으나 의미의 정렬은 실패했다.** KDM은 채택이 얇았고, 스프레드시트·자연어 문서는 사실상 커버 밖이었다(KDM엔 문서 개념이 형해화된 수준으로만 있다). "모든 것이 typed graph"라는 표현 지평은 채택할 가치가 있지만, "코드의 이 함수와 문서의 이 절이 같은 결정을 서술한다"는 cross-space 정렬은 탑이 안 준다 — 그 정렬이야말로 LLM이 소유할 의미 작업이다.

### R1 노이즈 귀납: **답하지 않는다 — 이 계열의 문제 설정 바깥이다**

이 계열 전체가 "메타모델은 주어진다"를 공리로 갖는다. 모델 발견(MoDisco)조차 **미리 정해진 메타모델로의 결정론적 사상**이지 귀납이 아니다 — Java 코드에서 Java 메타모델의 인스턴스를 뽑을 뿐, "무엇이 의도된 로직이고 무엇이 잔해인가"는 묻지 않는다. 예제에서 메타모델을 유도하는 연구(example-driven metamodel development, de Lara/Guerra 그룹 등 (확인필요: 구체 도구명))가 있으나 예제가 전부 positive라고 가정하며 노이즈 판별 기준이 없다. **미션의 출발점(노이즈 섞인 구현물에서 사람 관여 0으로 이론을 귀납)은 이 계열이 한 번도 풀려고 한 적 없는 문제다.** 이 계열을 코어로 삼으면 R1은 통째로 외부(LLM + 별도 귀납 이론)에 떠넘겨진다.

## 3. 깨지는 지점 (이 미션에서의 실패 조건)

1. **R1 역행 — 전제의 방향이 반대다.** 탑은 위(스키마)에서 아래(인스턴스)로 흐른다. 미션은 아래(노이즈 낀 구현물)에서 위(이론)로 흘러야 한다. 이 계열을 코어로 채택하면 "메타모델을 누가 만드는가"가 답 없는 구멍으로 남고, 그 구멍이 미션의 본체다.
2. **bx 법칙은 실 코드↔모델 쌍에서 성립하지 않는다.** round-trip engineering이 산업에서 죽은 직접 원인. 소스→모델이 정보를 버리는 추상화인 이상 PutGet은 원리적으로 깨지고(버린 정보를 복원 못 함), LLM이 리프팅의 한쪽을 소유하면 비결정성 때문에 법칙 **증명**은 아예 불가능하다. 법칙은 "감시용 테스트 등식"으로 격하해 써야 하며, bx 언어(Boomerang류)로 변환을 저작하는 길은 막혀 있다.
3. **도구 생태계가 JVM/Eclipse에 결박, 상당수 동면.** 현행 런타임은 TypeScript다. EMF를 물면 이중 런타임 + 모델 직렬화 브리지 유지가 상시 비용이 된다. eMoflon::IBeX-TGG는 2024년 개발 중단(후속 eMoflon::Neo는 EMF+Neo4j, 학술 유지), QVT-R은 완전 구현이 사실상 없다. "표준은 있으나 도구가 없는" 계열이다.
4. **엄격 메타모델링의 경직성.** 개념이 타입이자 인스턴스인 온톨로지 상황에서 2-수준 관계가 부자연스러워지고, 이를 푸는 deep instantiation은 학술 단계다. 도메인 온톨로지가 늘수록 이 마찰이 커진다.
5. **모델의 이중 진실 문제.** MDE가 산업에서 시든 최대 원인: 모델과 코드가 둘 다 손으로 유지되면 반드시 드리프트하고, 드리프트한 모델은 신뢰를 잃어 버려진다. — 단, 이 미션은 여기서 유리하다. "사람 관여 0의 reconstruct"는 **모델의 유일 저자를 기계로 만든다**는 뜻이고, 이는 MDE를 죽인 경제 구조(사람이 모델을 이중 유지)를 정확히 제거한다. 조건: 모델을 사람이 직접 편집하는 경로를 **비수용**으로 만들어야 한다(편집은 소스에, 모델은 재유도로만). 이 조건이 깨지면 MDE와 같은 이유로 죽는다.
6. **운영 복잡도.** correspondence 저장·증분 매칭 엔진·공진화 이력은 각각이 유지 대상 서브시스템이다. 1인 owner 운영 규모에서 전면 도입하면 유지 비용이 가치를 초과한다 — 채택하더라도 개념만 가져와 TypeScript로 최소 구현해야 한다.

## 4. 산업에서 시든 이유 — 미션에의 교훈으로 압축

MDA(2001~) 붕괴의 원인 사슬: (a) PIM→PSM 전체 코드 생성이라는 과약속, (b) round-trip 실패로 모델이 곧 낡음, (c) 무거운 도구·표준(UML 의미 공백, XMI 호환 지옥), (d) 애자일 전환과의 문화 충돌, (e) 메타모델 진화 시 인스턴스 이행 고통. 살아남은 것들이 시사적이다: **Xtext(→TypeScript 후속 Langium)** 같은 텍스트↔모델 브리지, **Ecore라는 작은 커널**, 도메인 한정 DSL. 즉 이 계열은 "전면 채택"이 아니라 "작은 커널 + 판정 가능한 conformance + 좁은 브리지"로 쓸 때만 살아남았다. 미션에의 처방도 동일하다.

## 5. 현행 onto-mcp와의 중복 (개념 경제 경고)

현행 시스템은 이 계열의 조각을 **이미 비형식적으로** 갖고 있다. 재도입하면 유사중복이다:

- Authority 위계 8단 ≈ 비형식 메타레벨 탑 (core-lexicon=M2 자리, domains≈M1.5, 소스=M0). **부족한 것은 층이 아니라 층 간 conformance 관계의 형식화·판정 가능화다.**
- G1~G11 + 불변식 12종 ≈ conformance 검사의 흩어진 구현. OCL의 자리에 TypeScript 테스트가 있다 — 규칙이 코드에 있어 논리 체계가 자기 규칙을 데이터로 못 읽는다는 게 갭.
- CodeStructureInventory ≈ ASTM 수준 injector 산출물. 알려진 한계(참조·호출·타입 엣지 없음, name resolution 없음)는 정확히 ASTM(구문)과 KDM(의미) 사이의 갭이다 — 이 계열의 지도에서 현 위치가 어딘지 정확히 짚어준다.
- content_sha256/extractor_logic_sha256 재사용 키 ≈ 파일 단위 trace. 요소 단위 correspondence trace가 그 정밀화 방향.
- 결론: 도입할 것은 "빠진 개념"(요소 단위 trace, 데이터로서의 제약, 공진화 연산자 이력, 동결 커널의 명시화)이지 프레임워크가 아니다.

## 7. 종합

이 계열은 미션의 **뼈대 절반**을 준다: R2의 답 형태(작고 자기서술적이며 사람이 1회 비준한 동결 커널이 퇴행을 끝낸다), R3의 결정론 소유분(판정 가능한 conformance + 데이터로서의 제약 + 비수용에 의한 강제), R5의 자료구조(요소 단위 correspondence trace = 캐시 무효화 단위), R4의 기록 형식(이행 규칙 딸린 연산자 열), R7의 절반(선언적 규칙에서 수리 후보 도출). 이것들은 owner corpus의 LLM/역량 경계 원칙과 자연스럽게 동형이라 이식 마찰이 낮고, 현행 onto-mcp가 이미 비형식적으로 절반쯤 하고 있어 "형식화"지 "신규 도입"이 아니다.

그러나 미션의 **심장인 R1은 이 계열의 바깥**이다. 탑은 스키마가 주어진 뒤의 세계만 다룬다. 따라서 이 계열은 코어가 될 수 없고, 귀납을 담당할 다른 이론(LLM 리프팅 + 반증 절차, 혹은 별도 트랙의 귀납/개정 계열)이 코어 자리에 오고, 이 계열은 그 산출물이 착지하는 **판정 가능한 표현층과 증분 유지 기계**를 제공하는 부품으로 배치되어야 한다. 도구는 하나도 직도입하지 않는다 — JVM 생태계 결박과 동면 상태 때문에, 개념을 TypeScript 커널로 최소 재구현하는 것이 유일하게 수지가 맞는 경로다. 마지막으로, MDE를 죽인 이중 진실 드리프트는 이 미션에서 유일하게 구조적으로 회피 가능하다(모델의 유일 저자 = reconstruct, 사람 직접 편집 비수용) — 단 그 비수용을 역량 표면으로 강제하지 못하면 같은 이유로 죽는다.
