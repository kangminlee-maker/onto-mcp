# 이론 계열 적합성: 격자 기반 제약·설정 언어 (CUE / Nickel / Dhall / Jsonnet / JSON Schema)

- 작성: 2026-07-31, 아키텍처 재설계 미션의 이론 탐색 arm
- 판정: **component_candidate** — 미션의 심장(R1 귀납, R4 개정, 관계 정량)은 계열 밖이지만, "판정 커널 + 교환법칙 병합 대수"라는 부품으로는 계열 중 가장 강한 후보를 포함한다.

## 1. 핵심 아이디어를 미션 용어로 번역

이 계열의 대표 격인 CUE의 수학적 기반은 하나다: **모든 값이 정보 정밀도 순서로 배열된 격자(lattice)를 이룬다.** 미션 용어로 풀면 이렇다.

- **타입 = 값**: `string`(느슨한 지식)과 `"hello"`(확정 지식)가 같은 공간의 점이다. 즉 "개념"(제약)과 "관측 사실"(구체값)이 별도 세계가 아니라 한 축 위의 정밀도 차이다. 미션의 언어로: **개념 SSOT와 구현물에서 추출된 사실이 같은 표현 공간에 산다.**
- **통합(unification) = 부분 지식의 결합**: 두 값의 병합은 격자의 meet(둘 다 만족하는 가장 느슨한 값)이고, 이 연산은 **교환·결합·멱등**이다. 여러 관찰자(파일별·소스별·렌즈별)가 낸 부분 개념 조각을 **어떤 순서로 병합해도 결과가 같다.** 병합 도중 양립 불가가 생기면 결과는 bottom(⊥)이며, 평가기가 **모순 발생 경로와 충돌한 두 값을 결정론적으로 출력**한다.
- **검증 = 격자 순서 판정**: "이 구현물이 이 개념에 부합하는가"는 `사실 ⊑ 제약`이라는 순서 비교다. 프롬프트 서술이 아니라 평가기가 내리는 실행 가능한 판정이고, CUE는 일반 재귀가 없어 평가가 종료를 보장한다 (Dhall은 total language로 같은 보장을 더 강하게 준다).

계열 내 분화: Nickel은 격자 대신 **contract(런타임 계약)와 blame(위반 귀속)** + 우선순위 기반 병합. Dhall은 병합 대수는 없지만 **정규형 후 해시(semantic hash)** 라는 캐시 키 아이디어를 소유. Jsonnet은 제약 없는 순수 템플릿. JSON Schema는 검증 전용이며 병합 대수가 없다(`allOf`는 정규화 없는 논리곱).

## 2. R1~R7 중 실제로 답하는 것

### R3 결론과 action의 결속 — 계열의 최강 적합

이 계열이 미션에 주는 알짜가 여기다. owner corpus의 LLM/역량 경계 원칙과 **정확히 동형**인 분업이 언어 차원에서 성립한다:

- **LLM이 소유**: 구현물을 읽고 개념(제약)을 저작하는 귀납, 제약의 의미·근거 서술.
- **평가기가 소유**: 그 제약에 대한 사실의 부합 판정, 모순 검출, 판정의 재현성.

"논리 체계가 결론을 낸다"가 프롬프트 서술이 아니게 되는 조건 = 판정이 결정론 평가기의 출력일 것. CUE/Dhall 평가는 결정론적이고 종료 보장이 있으므로 이 조건을 만족한다. LLM이 낸 귀납 가설을 제약으로 직렬화하면 **가설이 반증 가능해진다** — 코퍼스 사실 전체에 대해 평가해 반례 경로가 나오면 가설 기각. 이것은 R1 자체의 해법은 아니지만 R1의 출력을 검증 가능한 형태로 강제하는 표면이다.

### R6 다형 소스 — "착지 표현"으로서의 부분 적합

코드/문서/시트/설정이 각자의 추출기를 거쳐 **격자값(레코드 트리)으로 정규화되기만 하면**, 그 뒤의 병합·판정·모순 검출은 소스 종류를 구별하지 않는 하나의 대수다. 같은 지평은 여기서 생긴다. 단 명확히 하자: **정규화(추출) 자체는 이 계열이 한 줄도 안 해준다.** 계열이 제공하는 것은 착지면이지 사다리가 아니다. 코드 → 격자값 변환은 여전히 tree-sitter류 추출기와 LLM의 몫이다.

### R2 자기적용 — "판정 채널" 부분만 답한다

부트스트랩 고정점 문제에 이 계열이 주는 답: **판정 권위를 버전 고정된 외부 평가기(언어 스펙 + 바이너리)에 둔다.** 논리 체계가 자기 자신을 review할 때도 판정을 내리는 것은 LLM이 아니라 얼어붙은 대수이므로, 자기승인(self-ratification) 경로가 구조적으로 차단된다 — "금지 반복" 없이 "불가능"으로 만드는 방식이다. 평가기 버전 회전은 명시적 사건(해시 변경)이므로 권위 변경이 침묵으로 일어나지 않는다.

한계: 이것은 R2의 절반이다. "개념이 개념 자신을 서술할 때의 무한퇴행"과 "첫 개념 집합은 어디서 오는가"는 답하지 않는다. 계열이 막는 것은 판정의 순환이지 서술의 순환이 아니다.

### R4 진화 시 무모순 유지 — 탐지는 공짜, 해소는 계열 밖

- **탐지**: 새 개념/규칙을 기존 격자 인스턴스에 병합하는 순간 기존 사실·기존 제약과의 모순이 ⊥로 즉시, 결정론적으로, 경로와 함께 드러난다. 이것은 현행 onto-mcp에 없는 역량이며 손으로 만들면 비싸다.
- **되돌리기**: 병합이 교환법칙적이므로 "소스 파일 하나를 빼고 재병합"이 잘 정의된다. **파일(출처) 단위 revision은 된다.**
- **안 되는 것**: 격자는 단조다 — 정보는 늘기만 하고 철회가 없다. "기존 판정 중 어느 명제를 포기할 것인가"라는 belief revision(AGM류 우선순위 기반 개정)은 표현 자체가 불가능하다. 해소 정책은 반드시 계열 밖(설계 소유)에서 와야 한다.

### R5 비용과 증분성 — 약한 부분 적합, 아이디어 하나는 값짐

- **Dhall의 semantic hash**: import를 정규형(normal form)으로 환원한 뒤 해시한다. 포매팅·리팩터·이름 변경에 불변인 캐시 키 — 현행 `content_sha256`(바이트 해시)의 개념적 상위 호환이다. 채택한다면 Dhall 언어가 아니라 **이 아이디어**(정규형 후 해시를 캐시 무효화 단위로)를 가져오는 것이 맞다. 개념 경제상 이것은 기존 reuse key 개념의 정밀화(파생)이지 신규 개념이 아니다.
- **CUE의 증분 평가**: 1급 기능이 아니다. 인스턴스/패키지 단위 재평가가 기본이고, evalv3가 structure sharing으로 성능을 올렸지만 "바뀐 부분만 재평가"를 보장하는 API는 없는 것으로 안다 (확인필요 — evalv3 이후 증분 API 존재 여부).

### R7 판정의 유용성 — "무엇이 충돌했나"까지, "왜·무엇을 고칠까"는 못 미침

- CUE 충돌 오류: 경로 + 충돌한 양쪽 값 + 각 값의 출처 위치. "어디서 무엇이 양립 불가인가"는 산출된다.
- **Nickel의 blame**: contract 위반 시 "어느 당사자의 어느 계약이" 깨졌는지 귀속한다. 계열 내 에러 품질 최상. review가 요구하는 "위반의 책임 소재"에 가장 근접한 메커니즘이다.
- 그러나 "왜 이 개념이 존재하고, 고치려면 무엇을 해야 하는가"는 언어가 산출할 수 없다. 그것은 제약에 실린 메타데이터(근거 출처·수리 힌트·개념 계보)에서 와야 하고, 그 필드 설계는 이 계열이 아니라 우리 설계가 소유한다. 계열은 위반 지점과 위반 당사자까지만 결정론적으로 좁혀주는 역할이다.

## 3. 깨지는 지점 (이 계열이 이 미션에서 실패하는 곳)

1. **R1 정면 실패 — 귀납이 없다.** 계열 전체가 "쓰인 제약을 판정"하는 기계이지 "구현물에서 제약을 도출"하는 기계가 아니다. 노이즈/개념 구분은 100% 상류 몫이며, 이 계열을 도입해도 R1은 한 발짝도 전진하지 않는다. 이 계열을 core로 삼는 설계는 미션의 가장 어려운 문제를 미해결로 남긴 채 껍데기만 갖추는 오답이다.
2. **단조성 벽 — defeasible 일반화 표현 불가.** 실제 코드베이스의 개념은 "대체로 X, 단 legacy는 예외" 꼴이 다수다. CUE의 default(`*x`)와 disjunction이 제한적 장치로 있으나, 병합 간 default 의미론이 미묘하기로 악명 높고, 예외가 누적되는 현실 일반화에는 부적합하다. 철회 불가능성(위 R4)도 같은 뿌리다.
3. **관계 표현력 벽 — 그래프 정량이 언어의 영토 밖.** "모든 호출자는 인가 체크를 거친다" 같은 엣지 횡단 정량은 격자-트리 병합의 언어가 아니다. comprehension으로 흉내내면 조인이 수동이고 비용이 폭발한다. 이것은 Datalog 계열의 영토다. review 렌즈의 알짜 규칙(dependency·structure·evolution)이 정확히 이 표현력을 요구한다 — 현행 인벤토리에 호출/상속/타입참조 엣지가 없어서 아직 안 부딪혔을 뿐, 재설계가 엣지를 도입하는 순간 이 벽에 닿는다.
4. **성능 벽.** CUE 통합은 disjunction 조합에서 지수적 최악 사례가 있고, 대형 인스턴스 성능 문제는 evalv3 재작성의 동기였을 만큼 실재했다. evalv3는 v0.13.0(2025-05)부터 기본, v0.15.0에서 stable — 개선은 실측됐지만, 162k줄 코퍼스의 사실 전체를 단일 인스턴스에 넣는 설계는 여전히 위험하다. 인스턴스 분할 단위가 곧 설계 결정이 된다.
5. **운영 벽 — TS 런타임과의 경계.** CUE의 1급 API는 Go다. 공식 JS/TS 바인딩은 부재로 알고 있다 (확인필요) → 현행 TypeScript 런타임에서는 subprocess 경계가 강제되고, 판정 커널이 프로세스 경계 밖에 놓인다. Nickel은 Rust이며 WASM 빌드 경로가 있다 (확인필요). 어느 쪽이든 **새 언어 표면 추가**라는 개념 경제 비용이 든다: 배워야 할 문법 하나, 기존 YAML 권위(core-lexicon)와의 이중 권위 위험 하나.
6. **계열 내부의 부적합 후보.** Jsonnet은 제약이 없는 템플릿 언어라 이 미션에 줄 것이 없다. JSON Schema는 병합 대수가 없어 "부분 지식 결합"이라는 알짜를 못 준다 — 단 MCP tool 스키마로 이미 스택에 있으므로 경계 검증용으로는 현상 유지가 맞다.

## 4. 현행 onto-mcp와의 중복 (개념 경제 점검)

- **G1~G11 + INV-* 12종 = 손으로 짠 결정론 판정 커널.** 역할상 이 계열과 같은 자리에 있다. 도입한다면 **대체**이지 병설이 아니어야 한다 — 두 판정 권위의 병존은 동일 순위 충돌의 양산이다. 단 현행 가드는 TS 코드라 표현력 제한이 없다는 장점이 있고, CUE류는 선언성·병합 대수라는 장점이 있다. 트레이드오프이지 일방 우위가 아니다.
- **core-lexicon.yaml(데이터)과 domains/*/structure_spec·logic_rules(제약)가 이미 분리된 채 존재.** 이 계열이 주는 신규 역량은 정확히 하나다: **그 둘을 한 대수에 올리고, 여러 출처의 부분 지식을 교환법칙적으로 병합하며, 모순을 경로와 함께 결정론 검출하는 것.** 이것만이 현행에 없고 손으로 만들면 비싼 부분이다.
- **JSON Schema는 이미 스택에 있다** (MCP tool outputSchema). 신규 도입이 아니라 기존 사용의 확인.
- **reuse key(content_sha256 + extractor_logic_sha256)는 이미 바이트 해시 캐시.** Dhall식 semantic hash는 이 기존 개념의 정밀화로 흡수 가능 — 새 개념 불필요.

|---|---|---|

| Jsonnet | 매우 성숙 (Google 유래, C++/Go 구현) | 제약·검증 없음. 이 미션에는 부적합 판정 |
| JSON Schema (ajv) | 초성숙, TS 생태계 1급 | 이미 스택에 있음. 병합 대수 부재로 경계 검증 이상의 역할 확장은 부적절 |

## 6. 판정 요약

**component_candidate.** 이 계열은 재설계의 core가 될 수 없다 — R1(노이즈로부터의 귀납), R4의 해소(belief revision), 그래프 관계 정량이라는 미션의 심장 셋이 전부 계열 밖이다. 그러나 두 부품은 계열 바깥에서 손으로 만들면 비싸고 틀리기 쉬운 것을 언어 차원에서 준다: (a) **판정 커널** — LLM이 저작한 개념에 대해 결정론·종료 보장 판정을 내리는, LLM/역량 경계 원칙의 언어적 실현 (R3), (b) **교환법칙 병합 + ⊥ 모순 검출** — 다중 출처 부분 지식의 순서 무관 결합과 진화 시 충돌의 즉시 검출 (R6 착지면, R4 탐지 절반). 도입 시 현행 G-가드/INV 커널과의 이중 권위를 만들지 말 것, 관계 정량은 별도 계열(Datalog류)에서 찾을 것, 그리고 R1은 이 계열로 해결됐다고 착각하지 말 것 — 이 세 가지가 사용 조건이다.
