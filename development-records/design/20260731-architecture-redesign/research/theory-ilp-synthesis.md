# 이론 계열 적합성 탐색 — 귀납논리프로그래밍(ILP)·MDL 이론 귀납·프로그램 합성

- 미션: onto-mcp 근본 재설계 (reconstruct / review / 자기진화, R1~R7)
- 작성: 2026-07-31, 리서치 subagent
- 판정 요약: **component_candidate** — 계열 전체를 코어로 채택하는 것은 기각. 단, 이 계열이 가진 두 가지 — (a) MDL/압축을 "개념 자격"의 반증 가능한 점수로 쓰는 것, (b) LLM-제안 / 결정론-채점의 propose-verify 루프 — 는 재설계의 부품으로 직접 채택할 가치가 있다.

## 1. 이 계열이 미션 용어로 무엇을 하는가

학계 용어를 걷어내면 이 계열의 산출물은 전부 같은 모양이다: **"관찰(구현물)을 재현하는 최소 이론"**.

| 학계 용어 | 이 시스템에서 하는 일 |
|---|---|
| ILP (Popper·Metagol·ILASP) | 관계 사실(facts) + 양성/음성 예시에서 논리 규칙을 탐색으로 찾는다. reconstruct 용어로: "구현물에서 추출한 관계 그래프를 커버하는 규칙 집합 도출" |
| MDL (최소 서술 길이) | 이론 H의 가치를 `L(H) + L(D\|H)` 로 잰다 — "이론 자체의 크기 + 이론으로 설명 못 한 잔차의 크기". reconstruct 용어로: **개념은 도입 비용보다 corpus 압축 이득이 클 때만 존재 자격이 있다** — owner의 개념 경제를 계산 가능한 점수로 만든 것 |
| Version space | 관찰과 무모순인 가설 전부를 상·하한 경계로 유지. 노이즈 하나에 공간이 붕괴한다 |
| 라이브러리 학습 (DreamCoder·Stitch·Babble) | 프로그램 corpus에서 반복 구조를 추상(abstraction)으로 뽑아 corpus 전체를 그 추상 어휘로 다시 쓴다. reconstruct 그 자체의 코드 특화판 |
| 프로그램 합성 (Sketch·SyGuS·PROSE) | 명세(예시·제약)에서 그 명세를 만족하는 프로그램을 탐색. review 용어로 뒤집으면: "이 구현물이 이 명세의 해인가"라는 검증 문제 |

핵심 번역 세 줄:

1. **reconstruct = 이론 귀납.** 구현물 = 관찰 데이터 D. 온톨로지(개념+규칙) = 이론 H. 좋은 온톨로지 = D를 가장 짧게 다시 쓰게 하는 H.
2. **개념 = 압축 어휘.** 어떤 이름이 개념인 이유는 "그 이름을 도입하면 corpus 서술이 그 이름의 정의 비용 이상으로 짧아지기 때문"이다. 이것이 R1의 판정 근거가 된다.
3. **review = 잔차 판정.** 새 구현물이 기존 이론 아래서 서술 길이를 얼마나 늘리는지, 늘린 부분이 corpus 어디에 국소화되는지가 review의 1차 출력이다.

## 2. R1~R7 중 이 계열이 실제로 답하는 것

전부 답하지 않는다. 실질적으로 답하는 것은 **R1, R3, R7**이고, R5는 절반, R4는 인접 분야가 부분적으로 답한다. R2·R6은 사실상 침묵한다(§3).

### R1 노이즈로부터의 이론 귀납 — 이 계열의 최강 기여

MDL 2부 코드가 "무엇이 개념이고 무엇이 노이즈인가"에 **반증 가능한 정의**를 준다:

- 개념 후보 c에 대해 `Δ(c) = [c 없이 corpus를 서술한 길이] − [c의 정의 길이 + c를 어휘로 쓴 corpus 서술 길이]` 를 계산한다. `Δ(c) > 0` 이면 개념, 아니면 노이즈.
- **노이즈의 정의가 잔차로 떨어진다**: 최선의 이론이 설명하지 못하고 예외 목록에 남긴 것이 노이즈다. "이건 우발적 잔해다"라는 주장이 LLM의 인상이 아니라 측정치가 된다.
- **반증 방법이 내장된다**: 누군가 "이건 개념이 아니라 노이즈다"라고 주장하면, 그 개념을 제거하고 서술 길이를 재면 된다. 길이가 줄면 주장이 맞고, 늘면 틀리다. owner 검증 규율("메커니즘이 틀리면 실패하는 신호")과 정확히 같은 모양.
- 실증 근거가 실재한다: DreamCoder(wake-sleep으로 개념 라이브러리 성장)·Stitch(corpus 압축으로 추상 발굴, POPL 2023)·KRIMP/SLIM(MDL 패턴 집합 마이닝)이 전부 이 원리로 동작하며 실제로 사람 없이 재사용 어휘를 찾아낸다.

단, R1을 **절반만** 답한다 — §3-1의 "체계적 노이즈" 문제 때문에 압축 단독으로는 안 된다.

### R3 결론과 action의 결속 — 역할 분할이 owner의 LLM/역량 경계와 동형

이 계열의 현대적 형태(DreamCoder, LILO, LLM-guided synthesis)는 전부 같은 루프다:

- **제안자(비결정론)**: 후보 이론/추상/규칙을 생성한다. 여기가 LLM 자리 — 의미 작업(이름 짓기, 의도 해석, 어떤 반복이 의도적인지 가설 세우기).
- **채점자(결정론)**: 후보를 corpus에 적용해 압축 이득·커버리지·예외 수를 **계산**한다. 여기가 도구/코드 자리 — LLM이 "이건 개념 같다"고 말해도 채점기가 Δ ≤ 0 이면 **비수용**이다.

이것은 owner 원칙 "필수 구조화 출력은 결정론적 submit 도구를 유일 수용 경로로"의 이론 귀납 버전이다. LLM의 개념 제안이 프롬프트 서술로 끝나지 않고, 결정론 채점기를 통과해야만 온톨로지에 들어간다 — 즉 "논리 체계가 결론을 낸다"의 실행 가능한 최소 형태다. 그리고 일단 귀납된 규칙(논리 규칙이든 구조 제약이든)은 결정론적으로 재실행 가능하므로, 판정 자체는 LLM 없이 반복된다.

### R7 판정의 유용성 — 잔차의 국소화가 "무엇을 고칠지"다

- ILP류 산출물은 선언적 규칙이므로 위반 시 **어느 리터럴이 실패했는지** 추적이 나온다 — "왜 틀렸나"가 규칙 추적으로 떨어진다.
- MDL 프레임에서 review 출력은 "이 구현물은 현행 이론 아래서 서술 길이를 +X 늘린다. 초과분은 파일 F의 구간 S에 국소화된다. 가장 가까운 기존 개념은 c이고, c로 다시 쓰면 초과분이 Y로 줄어든다"가 된다. 이것은 맞다/틀리다를 넘어 **수리 방향**(어느 개념으로 접을 것인가)을 담는다.
- 한계: 압축 잔차는 "이론과 안 맞는다"까지만 말한다. "이론이 틀렸는지, 구현물이 틀렸는지"는 압축이 판정 못 한다(§3-1).

### R5 비용과 증분성 — 절반

- 잔차 채점은 증분 가능하다: 파일 하나가 바뀌면 그 파일의 `L(D_i|H)`만 다시 재면 된다. 캐시 키 = (파일 content_sha, 이론 버전 sha) — 현행 `extractor_logic_sha256` 회전과 같은 모양이라 접합이 자연스럽다.
- 그러나 **이론 자체의 최적성은 전역 속성**이다. 파일 추가가 어휘 선택을 뒤집을 수 있다(추상 A보다 B가 갑자기 더 압축적이게 됨). 증분 라이브러리 학습은 미해결에 가깝다 — 실무 타협은 "잔차 채점은 증분, 어휘 재컴팩션은 주기적 배치"다. 이 타협은 운용 가능하지만 계열이 R5를 푼 것은 아니다.

### R4 진화 시 무모순 유지 — 인접 답변만

ILP 본류가 아니라 그 옆의 이론 수정(theory revision) 계보와 ASP의 비단조 추론이 부분 답을 준다. ILASP는 노이즈 가중 예시·제약을 지원하고, ASP 규칙은 예외를 default+exception으로 표현할 수 있어 "기존 판정을 깨지 않고 예외를 추가"하는 형태의 개정이 표현된다. 그러나 충돌 탐지·최소 개정·되돌리기(믿음 개정 본론)는 이 계열의 상품이 아니다 — 그것은 별도 계열(belief revision/TMS)의 영토다.

## 3. 깨지는 지점 (이 미션에서 이 계열이 실패하는 조건)

### 3-1. 체계적 노이즈가 아름답게 압축된다 — R1의 반쪽 실패

압축은 **규칙성**을 재지 **의도**를 재지 않는다. 50번 복붙된 안티패턴, 코드 생성기가 찍어낸 boilerplate, 잘못된 관례의 관성적 반복은 전부 압축률이 훌륭하다 → MDL 단독 판정은 이것들을 "개념"으로 승격시킨다. 우발적 잔해가 **산발적**이면 잔차로 걸러지지만, **체계적**이면 이론에 편입된다. 이 미션의 구현물("의도된 로직과 우발적 잔해가 섞인")에서 잔해는 자주 체계적이다. 따라서 압축 점수는 개념 자격의 **필요조건 채점기**로만 쓰고, 의도 판정에는 직교 증거 축(소비 여부·권위 경로·실행 도달성 — owner의 "산출물은 소비되기 전까지 무효"가 정확히 이 축이다)이 반드시 결합돼야 한다.

### 3-2. 고전 ILP는 라벨된 예시 없이는 돌지 않는다

Popper·ILASP·Metagol은 양성/음성 예시 + 배경지식이 입력이다. reconstruct는 비지도다 — "이 코드는 올바른 예시, 저 코드는 위반 예시"라는 라벨이 없다. 예시 오라클을 LLM으로 만들면 그 라벨 자체가 검증 안 된 의미 판정이 되어 R1이 한 층 밀릴 뿐이다. 이것이 ILP 솔버 3종을 코어로 못 쓰는 첫째 이유다.

### 3-3. 자연어 문서에는 결정론적 서술 언어가 없다 — R6 실패

MDL은 서술 언어(인코딩)를 전제한다. 코드는 AST/관계 사실로, 스프레드시트는 셀·수식 관계로 결정론적 인코딩이 가능하다. 그러나 **산문 문서의 서술 길이는 결정론적으로 잴 수 없다** — gzip 길이는 의미와 무관하고, LLM 추정 codelength는 비결정론이라 owner의 역량 경계(결정론 값은 도구가 소유)를 위반한다. 다형 소스를 한 지평에 올리려면 문서를 먼저 구조 표현으로 사영해야 하는데, 그 사영 자체가 이 계열 바깥의 문제다.

### 3-4. 자기적용에 침묵한다 — R2 무답

이 계열이 R2에 주는 유일한 것은 정직한 부정적 통찰이다: **MDL 점수는 선택된 인코딩에 상대적이고, 인코딩 선택 자체는 MDL로 정당화할 수 없다**(Kolmogorov 복잡도 비계산성의 그림자). 즉 부트스트랩의 첫 고정점은 이 계열 안에서 나오지 않는다 — 서술 언어/인코딩이 사람이 동결하는 공리다. 이것은 결함이라기보다 "R2는 다른 계열에서 답을 구하라"는 명확한 경계 표지다.

### 3-5. 규모의 벽

ILP 탐색은 조합적이다. 문헌 실증 규모는 술어 수십·사실 수천 수준이고, 162,482줄 TS + 문서 + 스프레드시트의 관계 사실 전체를 ILP 탐색에 넣는 것은 실증된 바 없다. Stitch는 빠르지만(수만 노드 corpus) 입력이 람다식/DSL corpus라 TS→DSL 사영 파이프라인이 선행돼야 한다. "전체 corpus에서 이론을 한 번에 귀납"은 이 계열로 불가능하고, 후보를 좁힌 국소 귀납만 현실적이다.

### 3-6. 현행 입력이 빈약하다

ILP의 힘은 관계에서 나오는데, 현행 CodeStructureInventory는 포함관계+import 문자열뿐이다(상속/구현/호출/타입 참조 엣지 없음, name resolution 없음). 이 계열을 어떤 형태로든 쓰려면 관계 사실 추출층 보강이 선행 투자다 — 이는 계열 채택 여부와 무관하게 재설계의 공통 선행 조건일 가능성이 높다.

## 4. 실재 구현체·표준 (성숙도·비용)

전부 실재를 확신하는 항목이며, 세부 스펙에 확신 없는 곳만 표기했다.

| 이름 | 무엇 | 성숙도 | 이 미션 도입 비용 |
|---|---|---|---|
| Popper (Cropper) | learning-from-failures ILP, Python | 연구용, GitHub 활성 유지 | 관계 사실 추출 + 양/음 예시 오라클 필요(§3-2). 소규모 국소 문제 한정 |
| ILASP (Law) | ASP 규칙 학습, 노이즈 가중 예시 지원 | 연구용 바이너리, 학술 라이선스(상용 조건 확인필요) | 표현력 최고이나 인코딩·규모 부담 동일 |
| Metagol | 메타해석 학습, Prolog | 연구 프로토타입, 사실상 Popper로 세대교체 | 채택 비권장 |
| Aleph | 고전 ILP, Prolog | 오래됐으나 안정(SWI 포트) | 위와 동일한 입력 요구 |
| DreamCoder (Ellis et al. 2021) | wake-sleep 개념 라이브러리 학습 | 연구 코드, 재현 비용 큼 | 직접 도입 비현실적. **아키텍처 영감**(제안-압축-재서술 루프)으로만 |
| Stitch (Bowers et al., POPL 2023) | corpus 압축 추상 발굴, Rust, 고속 | 연구용이나 성능 실증 견고 | TS 구간→DSL corpus 사영 파이프라인 선행 필요 |
| Babble (POPL 2023) | e-graph + anti-unification 라이브러리 학습 | 연구용 | Stitch와 동급 용도, 택일 |
| LILO (Grand et al., ICLR 2024) | LLM 제안 + Stitch 압축 + 문서화 | 연구용 | §2-R3 루프의 기존 실증 — 설계 참조 가치 높음 |
| KRIMP / SLIM | MDL 패턴 집합 마이닝(itemset) | 학술 구현 안정 | 스프레드시트·설정 같은 표형 사실에 국소 적용 가능 |
| PROSE / FlashFill (Microsoft) | 예시 기반 변환 합성 SDK | **산업 등급** | 스코프가 문자열/표 변환 한정 — 스프레드시트 수식 의도 귀납에만 접점 |
| SyGuS 표준 + CVC5 | 문법 제약 합성 표준·솔버 | CVC5는 성숙 | 작은 함수 명세 한정, corpus 규모 이론 귀납과 무관 |
| Rosette / Sketch | solver-aided 합성·검증 | 학술 성숙 | 동일 — 국소 검증 부품 이상 아님 |
| CodeQL / Joern / Soufflé·DDlog | 코드의 관계 사실 추출·Datalog 평가(DDlog는 증분) | CodeQL·Soufflé 성숙, Joern 성숙, DDlog 유지 상태 확인필요 | 이 계열 자체는 아니나 §3-6 선행 투자의 기성 후보. CodeQL 라이선스는 비공개 corpus 사용 조건 확인필요 |

## 5. 현행 onto-mcp와의 중복 — 개념 경제 점검

- **개념 경제 원칙 = 비공식 MDL.** "새 개념 추가 전 가장 가까운 기존 개념을 찾고 재사용/확장/개명/분할을 명시적으로 고른다"는 규범은 MDL 판정의 사람-수행 버전이다. 이 계열의 기여는 새 개념 도입이 아니라 **기존 규범을 계산 가능한 채점기로 승격**하는 것 — 재사용이지 신설이 아니다.
- **reconstruct의 LLM 개념 seeding = 채점기 없는 제안자.** 현행 reconstruct는 §2-R3 루프의 제안자 반쪽만 있다. 누락된 반쪽이 결정론 압축/커버리지 채점기다.
- **G1~G11 + INV 12종 = 귀납된 이론의 소비자 원형.** 귀납이 만들어낼 "규칙"의 착지점(결정론 게이트로 강제)은 이미 존재한다. 새 규칙 표현을 발명하기 전에 이 게이트 표면으로의 컴파일 가능성을 먼저 보라.
- **`extractor_logic_sha256` 재사용 키 = R5 캐시 키의 선례.** (내용 sha, 로직 sha) 이중 키 회전은 잔차 채점 캐시에 그대로 이식된다.

## 6. 판정

**component_candidate.** 코어로 못 쓰는 이유: R2 무답, R6 실패(산문), 비지도 입력과의 불일치, 규모 벽. 부품으로 채택할 것 두 가지:

1. **MDL 압축 이득을 개념 자격의 결정론 채점기로** — 단독 판정이 아니라 필요조건 게이트 + 소비/권위 증거 축과의 결합(§3-1). 개념 경제를 반증 가능하게 만드는 유일하게 알려진 계산적 형태다.
2. **LLM-제안 / 결정론-채점 루프를 reconstruct의 골격으로** — LILO·DreamCoder가 실증한 구조이며 owner의 역량 경계 원칙과 동형이라 이식 마찰이 낮다.

ILP 솔버 자체(Popper·ILASP)는 inspiration 수준으로 격하하되, 온톨로지 규칙이 결국 관계 사실 위의 선언 규칙으로 표현된다면 국소 규칙 후보 발굴에 한정 재소환 여지는 남긴다. 선행 조건: 관계 사실 추출층 보강(§3-6)은 이 계열 채택 여부와 무관하게 필요해 보인다 — 별도 트랙(구조 증거 확장)과 합류 지점.
