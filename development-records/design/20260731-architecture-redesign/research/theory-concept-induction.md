# 이론 계열 적합성: 형식개념분석(FCA)·개념 격자·거친 집합 — 인스턴스에서 개념 도출

- 작성: 2026-07-31, 아키텍처 재설계 탐색 트랙
- 대상 미션: reconstruct / review / 자기진화, 난제 R1~R7
- 판정: **component_candidate** — reconstruct의 결정론적 개념-발견 전처리 + review의 함의 검사 엔진 + 개념 경제의 중복 판정기로서 채택 후보. 논리 체계 전체의 코어로는 부적합.

## 1. 이 계열이 이 시스템에서 하는 일 (미션 용어 번역)

학계 용어를 걷어내면 FCA의 본체는 하나의 결정론적 변환이다:

**입력**: 사건표(incidence table) — 행 = 인스턴스(코드 span, 문서 절, 스프레드시트 열, 설정 키), 열 = 속성(kind가 무엇인가, 무엇을 import하는가, 어떤 경로 세그먼트에 있는가, 어떤 네이밍 토큰을 쓰는가), 셀 = 보유 여부.

**출력**: 그 표가 함의하는 **모든 개념의 완전한 목록과 상하위 관계**(개념 격자). 여기서 "개념"은 수학적으로 정의된다: 외연(그 속성 조합을 정확히 공유하는 인스턴스 전부)과 내포(그 인스턴스 전부가 공유하는 속성 전부)가 서로를 완전히 결정하는 닫힌 쌍(Galois 연결). 닫혀 있지 않으면 개념이 아니다. 사람의 취향이 개입할 자리가 없고, 같은 표를 넣으면 같은 격자가 나온다.

부산물 세 가지가 미션에 직접 닿는다:

1. **함의 기저(Duquenne–Guigues canonical basis)** — 사건표에서 성립하는 모든 규칙("A 속성을 가진 것은 전부 B도 가진다")의 최소 무중복 집합. 구현물의 의사결정 로직을 규칙으로 **압축**한 것이며, 손으로 쓴 불변식(INV-*)의 기계 유도 대응물이다.
2. **속성 탐색(attribute exploration, Ganter)** — 시스템이 후보 함의를 하나씩 제시하고, 오라클(사람·LLM·또는 코퍼스 자체의 반례 탐색)이 수용하거나 반례를 내놓는 상호작용 알고리즘. 질문 수가 기저 크기로 한정되므로 "사람 관여 최소"를 **양적으로** 관리할 수 있다.
3. **거친 집합(rough sets, Pawlak)의 3치 근사** — 어떤 범주에 대해 "확실히 속함(하근사) / 확실히 아님 / 경계(현재 속성으로는 판정 불가)"를 결정론적으로 가른다. 경계 영역의 크기가 곧 "지금의 속성 어휘가 이 구분을 표현하지 못하는 정도"의 측정값이다.

핵심 재배치: 이 계열은 **"무엇이 개념인가"의 판정을 제거하지 않는다. 판정 지점을 위로 옮기고, 그 아래를 결정론화한다.** 속성을 무엇으로 삼을지(스케일링)는 여전히 의미 작업이지만, 일단 속성이 정해지면 개념의 존재·중복·포함·규칙·반례는 전부 코드 소유의 계산이 된다. 이것은 owner corpus의 LLM/역량 경계 원칙과 정확히 같은 절단면이다.

## 2. R1~R7 중 실제로 답하는 것

### R1 노이즈로부터의 이론 귀납 — **부분 답. 이 계열의 최강 기여이자 최대 한계가 같은 곳에 있다**

답하는 부분: "이것이 개념인가"에 반증 가능한 기준을 준다 — **닫힌 집합이면 개념, 아니면 아님.** LLM이 "이 코드베이스에 X라는 개념이 있다"고 주장하면, 그 주장은 외연 질의로 검증된다: X의 속성 조합을 공유하는 인스턴스 집합을 계산하고, 그 집합이 닫혀 있는지, 외연이 비어 있지 않은지(카디널리티 > 0 — 공허 통과 금지 규율과 동일) 확인한다. 두 개념 후보의 외연이 같으면 같은 개념(중복 도입 차단), 포함 관계면 상하위(재사용/확장/분할 선택지가 격자의 join/meet으로 결정론화). **개념 경제의 "가장 가까운 기존 개념 찾기"가 프롬프트 지시문에서 계산 가능한 질의로 바뀐다.**

노이즈 완화의 실제 형태:
- **Iceberg lattice**(지지도 문턱, TITANIC 계열 알고리즘, Stumme 등): 외연 크기 ≥ k인 개념만 유지. 1회성 우발 공출현이 개념으로 승격되는 것을 막는다. 닫힌 빈발 항목집합 마이닝(LCM, Uno 등)과 수학적으로 동치라서 이 경로의 알고리즘은 매우 성숙하다.
- **거친 집합의 경계 영역**: 노이즈 의심 인스턴스를 "판정 유보"로 격리하고, 확실 영역만으로 규칙을 유도한다.
- **속성 축소(reduct)**: 어떤 속성을 빼도 인스턴스 구별력이 유지되면 그 속성은 판별에 잉여 — 우발적 속성을 걸러내는 방향의 도구. 단 reduct 계산은 NP-hard.

답하지 못하는 부분(§4에서 상술): **빈도는 의도가 아니다.** 지지도 필터는 "자주 나타나면 개념"이라는 가정인데, 코드베이스의 의도적 단일 불변식(예: 보안 게이트 하나, 유일한 terminal-signal rethrow 사이트)은 정확히 저지지도다. 그리고 스케일링(무엇을 속성으로 삼는가) 자체에 노이즈가 들어오면 격자는 그 노이즈를 충실하게 개념으로 결정화한다.

### R3 결론과 action의 결속 — **답한다. 절단면이 corpus 원칙과 일치**

함의 검사는 결정론이고 실행 가능하다: "인스턴스 X가 함의 A→B를 위반한다"는 사건표 조회로 판정되며, LLM의 서술이 아니다. 소유권 경계가 깨끗하게 나온다 —

- **코드 소유**: 사건표 구축(구조 관찰), 닫힘 연산, 격자 계산, 함의 유도, 위반 탐지, 반례 탐색, 외연 카디널리티 단언.
- **LLM 소유**: 속성 어휘의 설계(무엇을 관찰할 가치가 있는가), 닫힌 집합에 이름 붙이기(격자는 개념을 찾지만 명명하지 않는다), 위반의 중대성 판정, 경계 영역 인스턴스의 의미 판정.

이것은 "LLM은 의미 작업, 도구/코드는 결정론 작업" 원칙의 이 도메인 구체화다. review의 판정이 "LLM이 그렇게 느꼈다"가 아니라 "이 규칙, 이 반례 카운트"가 된다.

### R4 진화 시 무모순 유지 — **답한다. 이 계열이 두 번째로 잘하는 것**

- **충돌 탐지**: 새 인스턴스(새 파일, 바뀐 span)가 기존 함의 기저의 어떤 규칙에 반례가 되는지는 결정론적으로 전수 계산된다. "개념 추가가 기존 판정과 충돌하는가"가 탐색 문제가 아니라 검사 문제가 된다.
- **해소의 형태가 유한 열거된다**: 반례 발생 시 선택지는 (a) 규칙 약화(전제에 속성 추가), (b) 인스턴스를 예외로 격리(경계 영역), (c) 인스턴스가 결함(review finding). 어느 쪽인지는 의미 판정(LLM/사람)이지만, 선택지 집합 자체는 형식이 강제한다.
- **가역성**: 격자·기저는 사건표의 순수 함수다. 행/열을 되돌리면 격자가 되돌아온다. 별도의 믿음 개정 장부가 필요 없고, 사건표의 버전이 곧 이론의 버전이다. (본격적 믿음 개정 — 우선순위 있는 규칙 철회 — 은 이 계열 밖이며 비단조 추론 계열의 영역.)

### R5 비용과 증분성 — **답하되, 지수 벽 조건부**

증분 격자 갱신 알고리즘이 실재한다(Godin의 증분 알고리즘, AddIntent — van der Merwe·Obiedkov·Kourie). **캐시 무효화의 단위가 자연스럽게 정의된다: 인스턴스 행 하나(= 파일/span의 속성 벡터).** 파일이 바뀌면 그 행들만 재관찰하고 격자를 국소 갱신한다. content_sha256 기반 재사용 키가 이미 있는 현행 구조와 결이 같다. 단 최악의 경우 격자 크기는 min(|인스턴스|, |속성|)에 지수적이고, 함의 기저의 pseudo-intent 열거에는 부정적 복잡도 결과가 있다(Distel·Sertkaya 계열로 기억 — **확인필요**). 실무 데이터에서 개념 수는 보통 훨씬 작지만 **보장이 없으며**, 상한 초과 시 iceberg 문턱으로 절단하는 운영 정책이 필수다 — 그리고 그 절단이 바로 R1의 저빈도-의도 문제를 다시 연다.

### R7 판정의 유용성 — **부분 답**

FCA 위반 보고는 구조적으로 "왜"를 담는다: "X는 속성 A를 갖는데, A를 가진 다른 47개 인스턴스는 전부 B도 갖는다. X만 없다." 이것은 (i) 위반된 규칙, (ii) 규칙의 증거 기반(외연 47), (iii) 수리 방향 두 갈래(B를 갖추거나, X가 예외인 이유를 명시해 규칙을 약화하거나)까지 준다. 현행 review 렌즈의 산출을 이 형태에 결속하면 "맞다/틀리다"를 넘어선다. 담지 못하는 것: **수리의 의미적 내용**. "B를 갖추라"까지가 형식의 한계이고, B를 어떻게 갖추는지는 LLM 몫이다.

### 답하지 않는 것

- **R2 자기적용**: 침묵. 격자가 사건표의 순수 함수라는 사실은 수학층의 자기승인 문제를 소거하지만(재계산에 권위 순환이 없다), 진짜 순환 — 속성 어휘를 누가 정하고, 그 어휘 선택을 무엇이 심사하는가 — 은 형식 밖에 그대로 남는다. 부트스트랩 고정점은 다른 계열에서 와야 한다.
- **R6 다형 소스**: 형식 차원의 답만 있다. "사건표로 투영 가능한 것은 전부 같은 격자에 올라간다"는 참이고 통일 지평으로서 매력적이지만, 소스 유형별 투영(스케일링) 설계라는 실비용이 그대로 남고, 이것이 R6의 실제 난이도다. §4-3 참조.

## 3. 현행 onto-mcp와의 접점 — 무엇이 이미 있고 무엇이 없는가 (실측 기반)

| 현행 | FCA 관점 | 판정 |
|---|---|---|
| `CodeStructureInventory` (spans+kind+hierarchy+imports+sha) | **사건표의 원재료가 이미 생산되고 있다.** 객체=span/파일, 속성=kind·import 대상·경로 세그먼트·네이밍 토큰으로 투영하면 그대로 formal context | 재사용. 신규 관찰 계층 불필요 — 투영 계층만 추가 |
| `core-lexicon.yaml` 1,476줄 | 개념 멤버십이 **선언**되어 있고 외연(어떤 인스턴스가 증거인가)이 체계적으로 유지되지 않음 | FCA는 멤버십을 **파생**으로 뒤집는 제안: 개념 = 닫힌 외연, lexicon 항목은 그 명명·의미 주석 |
| INV-* 12종·G1~G11 | 손으로 쓴 함의들. 함의 기저는 이것의 기계 유도 대응물 | **개념 경제 경고**: 유도된 함의를 별도 어휘로 만들면 규칙 개념이 이중화된다. 유도 기저는 기존 불변식/게이트 개념의 후보 공급원으로 접속해야지 병렬 체계가 되면 안 된다 |
| INV-BENCH-1 (반복·fixture 미달 → PRELIMINARY 강등) | iceberg 지지도 문턱과 같은 규율: **증거 카디널리티 미달은 제거가 아니라 강등** | 이 기존 패턴을 그대로 쓰면 R1의 저빈도-의도 절단 문제를 완화 — 저지지도 개념을 지우지 말고 PRELIMINARY로 격하 |
| reconstruct의 comprehension-reduce/semantic-map (LLM authoring) | 현재 개념 귀납이 전부 LLM 의미 작업. 결정론 귀납 층이 없음 | FCA는 LLM 앞단의 결정론 전처리로 삽입: 닫힌 집합·함의 후보를 코드가 계산하고 LLM은 명명·선별만 |
| 알려진 한계: 상속/호출/타입 참조 엣지 부재 | 사건표의 속성 빈곤으로 직결. 관계 없는 사건표에서 유도되는 함의는 표층적("service/ 경로면 *.test.ts 동반" 수준) | FCA 도입의 가치가 구조 증거의 깊이에 상한됨 — 호출/참조 엣지 확장과 묶어서만 의미 있음 |

요약: **현행 시스템은 FCA의 입력(관찰)과 출력 소비처(lexicon·불변식·review finding)를 이미 갖고 있고, 가운데의 결정론 귀납 엔진만 없다.** 중복 도입 위험은 낮고, 오히려 기존 개념(inventory, INV, PRELIMINARY 강등)에 정확히 접속되는 형태다.

## 4. 깨지는 지점 (이 미션에서의 실패 조건)

1. **스케일링 회귀(R1의 반쪽)**: 격자는 사건표를 충실히 결정화할 뿐이다. 속성 어휘가 부실하면 표층 개념만 나오고, 속성에 우발 잔해가 섞이면 잔해가 개념으로 승격된다. "무엇이 노이즈인가"의 판정은 사라지지 않고 속성 설계 단계로 이동한다. 이 이동 자체는 가치가 있지만(판정이 한 곳에 모이고 아래가 결정론화됨), **"사람 관여 0"을 이 계열 단독으로 달성한다는 주장은 성립하지 않는다.**
2. **빈도 ≠ 의도**: iceberg/지지도 기반 노이즈 필터는 의도적 희소 패턴(단일 보안 게이트, 유일 불변식 사이트)을 노이즈와 구별하지 못한다. 완화는 제거 대신 강등(위 INV-BENCH-1 패턴) + 저지지도 개념의 LLM 심사 큐 — 즉 결국 의미 판정 재도입.
3. **이진 사건표의 표현 빈곤**: 순서·수치·등급은 개념 스케일링으로 부호화해야 하고 속성 폭발을 부른다. 결정적으로 **관계 구조(호출 그래프, 데이터 흐름, authority 위계의 방향 엣지)를 본체가 담지 못한다.** Relational Concept Analysis(RCA)라는 확장이 문헌에 있으나 도구 성숙도는 낮은 것으로 안다(**확인필요**). 이 미션의 "의사결정 방식" 개념화는 관계·순서가 본질이라, FCA 단독으로는 개념의 절반(분류 축)만 잡고 절반(절차·의존 축)을 놓친다.
4. **지수 벽**: 개념 수 최악 지수적, reduct NP-hard, pseudo-intent 열거의 부정적 복잡도 결과(**확인필요**). 162k줄 규모 repo의 span 단위 사건표는 수만 행이 되고, 속성 설계에 따라 격자가 폭발할 수 있다. 운영은 항상 iceberg 절단 + 도메인별 부분 사건표(모듈 단위 분할)를 전제해야 하며, 분할하는 순간 "전역 격자"라는 이론적 매력은 줄어든다.
5. **R2 무응답**: 자기적용·부트스트랩·순환권위에 침묵. 이 계열을 코어로 삼으면 R2가 통째로 미해결로 남는다 — component 이상으로 승격하면 안 되는 일차 근거.
6. **명명 부재**: 격자는 개념을 찾지만 이름과 의미를 주지 않는다. 닫힌 집합 수백 개에 이름을 붙이는 것은 전부 LLM 작업이고, 이 명명이 곧 lexicon 품질이므로 LLM 부담이 사라지는 게 아니라 형태가 바뀐다(자유 귀납 → 제시된 후보의 명명·선별).
7. **도구 공백(TS 런타임)**: 아래 §5 — 성숙한 TypeScript 구현을 알지 못한다. 자체 구현(CbO/In-Close/AddIntent는 각 수백 줄 수준)이 현실적이나, 알고리즘 정확성 검증 부담(속성 기반 테스트, 참조 구현 대조)이 생긴다.

## 5. 실재 구현체·표준·성숙도

표준화 기구 표준은 없다. 정본은 교과서 Ganter & Wille, *Formal Concept Analysis: Mathematical Foundations* (1999).

**알고리즘 (문헌상 확실, 자체 구현 가능 규모)**
- NextClosure (Ganter) — 개념·pseudo-intent 열거의 고전. 구현 난이도 낮음.
- CbO / FCbO (Kuznetsov; Outrata·Vychodil) , In-Close 계열 (Andrews) — 빠른 개념 열거. 구현 난이도 중.
- AddIntent (van der Merwe·Obiedkov·Kourie) — 증분 격자 갱신. R5의 핵심.
- TITANIC (Stumme 등) — iceberg lattice.
- LCM (Uno 등) — 닫힌 빈발 항목집합 = iceberg intent 계산. 항목집합 마이닝 쪽이라 구현이 가장 성숙.

**도구**
- ConExp / ConExp-NG — Java GUI 연구 도구. 실재, 유지보수 산발적. 런타임 임베드 부적합, 탐색적 검증용.
- ToscanaJ — Java, 사실상 정체 상태로 기억(**확인필요**).
- Python `concepts` (Sebastian Bank, PyPI) — 실재. 소규모 사건표에 적합, 대규모 성능은 미검증(**확인필요**). 프로토타입·오라클 대조용으로 적절.
- `fcapy` (Python) — 존재로 기억하나 성숙도 불확실(**확인필요**).
- SPMF (Fournier-Viger, Java) — 실재하는 패턴 마이닝 라이브러리. 닫힌 항목집합 마이닝(CHARM/LCM류) 포함은 확실, FCA 격자 직접 지원 여부는 **확인필요**.
- R `RoughSets` 패키지 — CRAN에 존재로 기억(**확인필요**), 거친 집합 근사·reduct.
- TypeScript/JS 생태계 — 성숙한 FCA 라이브러리를 알지 못함. 부재 추정(**확인필요**).

**비용 평가**: 외부 의존 도입보다 자체 구현이 현실적이다. 핵심 루프(닫힘 연산자 + CbO + AddIntent + 함의 검사)는 합쳐 1~2천 줄 규모로 추정되고 순수 함수라 테스트 용이성이 높다. 진짜 비용은 코드가 아니라 (a) 소스 유형별 스케일링 설계(의미 작업, 반복적 재설계 예상), (b) 격자 크기 운영 정책(문턱·분할·강등), (c) 명명 파이프라인(LLM 호출 예산)이다.

## 6. 판정

**component_candidate.** 이 계열은 이 미션의 코어(자기 자신을 파악하고 진화하는 논리 체계 전체)가 될 수 없다 — R2에 침묵하고, 의미 부여(스케일링·명명·중대성)를 전부 외부에 의존하며, 관계·절차 구조를 담지 못한다. 그러나 세 지점에서는 대체재가 잘 안 보이는 구체적 기여를 한다:

1. **reconstruct의 결정론 전처리**: 관찰 → 사건표 → 닫힌 집합·함의 후보 계산 → LLM은 명명·선별. "무엇이 개념인가"의 아래 절반이 반증 가능해진다.
2. **review의 규칙 위반 엔진**: "함의 A→B, 반례 X, 증거 외연 n" 형태의 finding — 왜·무엇을·어느 방향으로가 형식에 실린다.
3. **개념 경제의 기계화**: 외연 동치/포함 질의로 중복 개념 도입을 결정론적으로 차단.

채택한다면 결합 조건: 저지지도는 제거가 아니라 PRELIMINARY 강등(기존 규율 재사용), 유도 함의는 기존 불변식 개념에 접속(병렬 어휘 금지), 관계 축은 별도 계열(구조 증거의 엣지 확장 또는 규칙/논리 계열)과의 결합을 전제, R2는 다른 계열의 답을 기다린다.
