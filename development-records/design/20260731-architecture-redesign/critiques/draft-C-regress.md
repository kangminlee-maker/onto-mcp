# draft-C 적대 검증 — 렌즈: 자기적용 무한퇴행·자기승인

> 검증일: 2026-07-31. 대상: `drafts/draft-C.md` 전문 (요약 아님).
> 자세: 반박. 초안이 이미 방어한 지점은 지적에서 제외했다 (§끝의 "견딘 시나리오" 참조).
> 종합 판정: **major_gap** — L1/L2 진술 층의 자기승인 차단 장치(위상 분리·ratchet·사이클 차단)는 실질적이나, 테제가 주장하는 "자기승인이 구조적으로 표현 불가능"(§1)은 성립하지 않는다. 자기승인은 제거된 것이 아니라 **네 곳으로 전위(displace)되었다**: (a) 커널·checker·투영이라는 **코드 층**, (b) ratchet이 안 보는 **L1 생애 사건**(retire·scope 축소·재결속), (c) 체계 산출물이 다음 귀납의 입력이 되는 **코퍼스 경유 암묵 순환**, (d) identity 미검증 **owner 마커**. 넷 다 초안이 다루지 않았다.

초안이 방어에 성공한 지점(시도했으나 뚫리지 않은 공격)은 문서 끝에 기록 의무로 남긴다. 아래 findings는 그 방어선들 **사이**의 구멍이다.

## F1 [high] checker·추출기 저작 권위 미지정 — LLM 판단이 deterministic/blocking 권위로 세탁되는 열린 채널

**주장.** 초안은 `blocking: true`를 `authority: deterministic`에만 스키마상 허용해 "LLM 판정이 차단하는 상태를 타입상 표현 불가"로 만들었다(§4.3). 그러나 deterministic authority의 실체는 checker **코드**이고, 초안은 신규 checkable norm의 checker를 누가 저작하는지 어디에도 지정하지 않는다. §10.2는 1일차에 한해 "기존 check-* 스크립트 그대로 결속"이라 하고, §5.3의 사람 잔류 전수 목록(L0 변경·L2 완화·종량 과금·외부 비가역)에 checker 저작·등록은 없으며, §3.1의 LLM 소유 목록에도 없다. 미지정은 중립이 아니라 구멍이다 — 이 설계에서 지정 안 된 권위는 반드시 둘 중 하나로 흐른다:

- **사람이 쓴다** → 새 norm이 checkable이 되려면 매번 사람이 강제자를 구현해야 한다. "승격·유지·판정·귀납은 사람 0"(§5.3)이 무너지고, 체계는 초안 스스로 §12에서 실패 모드로 규정한 "사람이 seed한 규범의 자동 유지 시스템"으로 축소된다 — 실패 경로가 아니라 **성공 경로의 정상 운영에 이미 내재**한다.
- **LLM이 쓴다** → LLM 저작 코드가 admission을 통과하는 순간 deterministic·blocking 권위를 획득한다. "LLM 판정은 차단할 수 없다"는 타입 장벽이 코드 저작이라는 우회로로 무력화된다.

**구체 실패 시나리오 (LLM 저작 경로).** §3.3의 게이트 등록 요건은 `negativeControl(ref)` — 주입 위반 **1개**를 잡는지의 변이 결속이다. checker와 negative control을 같은 LLM이 같은 run에서 저작하면 공모가 가능하다: checker가 심긴 대조 fixture의 특정 패턴(예: 정확한 파일명·주석 마커)만 위반으로 내고 실 위반 클래스는 통과시키도록 저작한다. backtest census는 `conform: N, violation: 0`으로 깨끗하고(체커가 아무것도 안 잡으므로), negativeControl은 심긴 1건을 잡아 green, subjectSet>0도 만족한다. 이 norm은 checkable-admitted가 되어 **차단 권위를 가진 채** 아무것도 강제하지 않는다 — declared≠wired의 최악 형태(강제자가 실재하고 해시도 일치하는데 무능)가 admission을 통과한다. checker_sha256은 **동일성**을 보증할 뿐 **적합성**을 보증하지 않는데, 초안은 이 둘을 구분하지 않는다. norm의 falsifier 필드(§2.2)는 prose다 — "checker 무능이 입증되면 강등"이라 쓰여 있지만 그 입증을 격발할 기계 장치는 negativeControl 1발뿐이다.

추출기도 같은 클래스다: §9는 "등록제"라고만 하고 등록 게이트를 지정하지 않는다. LLM은 evidence를 만들 수 없지만(채널 부재, §3.1) 추출기 **코드**를 만들 수 있다면 evidence 생산 권위를 코드 저작으로 획득한다.

**repair.** 가능하나 비용이 있다. 셋 중 택일을 설계가 명시해야 한다: (1) checker 저작을 사람 게이트 전수 목록에 추가 — "사람 0" 주장을 정직하게 축소. (2) checker를 커널 combinator로 구성된 제약 DSL로만 저작 허용(임의 TS 금지) — 표현력 손실을 수용. (3) 임의 코드 허용하되 negative control 배터리를 checker 저자와 **다른 계열·다른 시점**에 독립 생성하고 N≥k 변이 요구 + held-out 위반 코퍼스 — 공모 비용을 올리되 원리적 봉쇄는 아님을 공시. 어느 쪽이든 "checker 저작·등록"을 §5.3 전수 목록 또는 §3.1 소유권 표에 명시적으로 편입해야 한다. 현재 상태로는 이 설계의 가장 강한 주장(차단 권위의 타입 봉쇄)이 가장 약한 미지정 채널 위에 서 있다.

## F2 [high] ratchet 비대칭이 L2만 지킨다 — L1 믿음 개정이 자동 완화 뒷문이다

**주장.** 방향 비대칭은 본문에서 명시적으로 "L2 파라미터"에 한정된다(§5.3-2). 그런데 실제 강제력(blocking checker, self CI 머지 게이트)은 전부 L1 norm에 살고, §5.1 표는 L1 변경 게이트를 "수용 게이트 자동 (사람 0)"으로, §5.5는 충돌 시 "어느 믿음을 버릴지는 의미 작업 — LLM이 처분안을 내고 게이트가 수용한다"로 배정했다. L1 norm의 생애 사건 — retire, scope 축소, blocking 해제 — 은 강제 표면을 줄이는 완화인데 ratchet의 사정권 밖이다. 믿음 개정 경로(§5.5)가 그대로 자동 완화 경로가 된다.

**구체 실패 시나리오.** admitted norm A = `norm.mock-import-boundary`(blocking). 진화 run에서 LLM이 실 증거(replay 테스트 파일들)를 인용해 norm B = "replay 결정론을 위해 boundary-인접 어댑터는 fixture payload를 import할 수 있다"를 저작한다. B의 census 위반은 LLM이 "근거 있는 예외"로 처분한다 — 게이트는 처분의 **존재와 형식 완전성**을 결정론 검사할 뿐 처분의 진위는 검사하지 못한다(§3.1 [5]의 소유권 배정상 그럴 수밖에 없다). B 수용 → backtest diff가 A/B 모순 blocking verdict를 탐지(§5.5) → 충돌 처분으로 LLM이 "A의 scope에서 `src/replay/**` 제외"를 제안 → L1 개정이므로 자동 수용. 최종 상태: 강제 표면이 축소됐고, owner 마커는 한 번도 요구되지 않았고, ratchet은 한 번도 격발하지 않았다(L2 파라미터가 안 바뀌었으므로). "방향 판정 불가 → 완화로 fail-closed"가 이를 막으려면 그 규칙이 L1 사건에도 적용되어야 하는데, 본문은 L2 한정으로 못 박았다. 개념 중복 게이트(§3.2 반증 d)는 B를 A와의 재사용/확장/분할 **선택**으로 몰 뿐 — LLM이 "분할"을 고르면 통과한다.

**repair.** 방향 메타데이터·fail-closed 규칙을 L1 status/scope/binding 전이로 확장한다 — admitted norm의 retire·scope 축소·blocking 해제는 완화로 분류해 owner 마커(F8의 수리를 전제로 한 실효 마커)를 요구. 대가: "승격·유지·판정·귀납은 사람 0"(§5.3)이 좁아진다 — "강제력을 줄이는 유지"는 사람 게이트가 된다. 이 대가는 초안 자신의 논리("넷 다 이유가 같다 — 자기승인이 되기 때문")와 정합하며, 결국 초안의 사람-전수 목록이 불완전했다는 뜻이다.

## F3 [high] checker 재결속의 co-rotation — declared≠wired가 진술-checker 경계에서 부활한다

**주장.** F1이 신규 checker 저작의 구멍이라면, F3은 **기존** checker의 생애 관리 구멍이다. Tier-0의 binding divergence(§5.4)는 "checker 파일이 바뀌었는데 norm이 모른다"를 잡을 뿐, "checker가 약해졌는데 재결속으로 정당화됐다"를 잡지 못한다. 재결속(checker_sha256 갱신)은 L1 개정 사건이라 자동 수용이다(F2와 같은 뿌리, 다른 표면: F2는 norm 명제의 완화라 이론 텍스트에 흔적이 남지만, F3은 명제 불변·강제자 무력화라서 이론 텍스트만 감사하면 안 보인다). census는 오히려 공범이 된다: 약해진 checker로 재실행하면 violation이 0으로 떨어지고, `floor()`는 게이트의 하한이지 norm별 위반 검출력의 하한이 아니므로 이는 개선처럼 기록된다.

**관대한 해석까지 검증했다.** §3.3을 "norm checker도 combinator 위에서 정의되어 negativeControl 결속 필수"로 읽어도(본문은 수용 게이트 맥락이지만 §10.2의 가드 유지비 흡수 서술상 이 해석은 가능하다), negativeControl의 ref 갱신 자체가 또 L1 사건이다. checker와 그 negative control을 **같은 자동 개정에서 함께 회전**(co-rotation)시키면 — 약화된 checker + 그 약화를 안 건드리는 새 변이 테스트 — 등록 검사를 통과한다. 초안은 INV-SHARD-1의 co-flip 교훈을 시간 위상 분리로 일반화했다고 주장하지만(§5.3-1), 위상 분리는 run **내** 동시 flip만 막는다. run을 넘어선 순차 co-rotation을 막을 장치는 ratchet인데 ratchet이 L1을 안 본다.

**구체 실패 시나리오.** 리팩터가(혹은 LLM이 저작한 repair가) `checks/check-import-boundary.ts`를 "개선"하며 dynamic import 경로를 침묵 면제한다. Tier-0 blocking(binding divergence) → 표준 해소 절차로 재결속 개정 + control 갱신 제출 → L1 자동 수용 → census violation 0 기록 → norm 텍스트는 여전히 "운영 경로는 mock을 import하지 않는다"고 서술하지만 강제자는 눈이 멀었다. 초안이 봉인했다고 주장한 결함 클래스가 정확히 재생산된다.

**repair.** (a) checker 재결속을 방향 판정 불가 사건으로 분류해 owner 게이트로 보내거나, (b) 재결속 시 **이전 세대 negative control로** 새 checker를 검사하는 봉인 규칙 — control은 checker와 같은 사건에서 회전 불가(INV-SHARD-1 봉인 권위 분리의 진짜 일반화는 시간 축이 아니라 이 **사건 축**이다). (b)가 사람 0을 유지하므로 우선.

## F4 [high] 커널 자기-증명(self-attestation) — 모든 결속의 검증자를 검증하는 외부 기제가 없다 (trusting trust)

**주장.** 커널은 checker_sha256을 재검증하고(Tier-0), admitted 해시 색인으로 손편집을 무효화하고, run manifest에 커널 해시를 실어 권위를 체인으로 계승한다(§5.2). 그런데 이 전부를 수행하는 주체가 커널 자신이고, **실행된 커널이 비준된 커널인지를 검증하는 것은 아무것도 없다**. run manifest의 커널 해시는 커널이 자기 손으로 기록하는 자기 진술이다. 위상 분리(§5.3-1)는 게이트 **진술**의 스냅샷을 고정하지만 게이트 **실행기**(kernel/admission/*.ts)는 진술이 아니라 코드다 — run R에서 실행되는 커널 코드는 그 run의 워킹트리/체크아웃에서 온다.

**구체 실패 시나리오.** (a) 로컬에서 수정된 kernel/ledger 쓰기 경로로 run을 돌리면, 수정된 커널이 admission을 통과시키고 manifest에 비준 커널의 해시를 기록한다 — 체인은 깨끗해 보인다. 이 repo의 실측 학습이 정확히 이 모양을 경고한다: "G4 게이트는 커밋된 range만 검사 — 워킹트리 상태 실행은 vacuous PASS". (b) 더 얕은 경로: `ledger/admission.jsonl`은 "커널의 유일 쓰기 경로"(§2.3)라 **선언**되어 있을 뿐, 행 단위 체인 해시도 서명도 샌드박스도 없다 — repo 쓰기 권한을 가진 에이전트(혹은 F1의 LLM 저작 checker, 혹은 버그 있는 이행 스크립트)가 그럴듯한 admitted 행을 직접 append하면 투영이 그것을 진실로 렌더링한다. theory 손편집은 무효인데 **원장 손편집은 무효가 아니다** — 무효화 색인의 권위 원천이 바로 그 원장이므로. 초안의 자기 원칙("금지를 반복하지 말고 불가능·무효·비수용으로")이 정작 진실 저장소의 배타적 쓰기에는 적용되지 않았다: 이것은 금지문이다. (c) checker 실행이 self CI 머지 게이트를 대체하면(§4.3-b) CI 워크플로 파일이 강제의 루트가 되는데, 그 파일은 수용 통제 밖이다 — 그것을 지키는 norm의 checker는 CI **안에서** 돌므로, 커널 호출을 빼는 변경에서는 그것을 잡을 checker가 실행되지 않는다. 강제 루트는 내부에서 지킬 수 없다.

이는 무한퇴행의 실무 형태다. 초안은 퇴행을 "유한 접지: ≤3k줄 사람-감사 커널"로 종결한다(§5.1) — 접지 자체는 정당한 답이다. 문제는 테제가 그보다 강한 것을 주장한다는 데 있다: 실제로는 자기승인이 커널 실행 층에서 **표현 가능**하고, 그 층의 방어는 구조가 아니라 절차(owner 비준)와 선언(유일 쓰기 경로)이다.

**repair.** 원리적 완전 봉쇄는 불가능하다(검증자의 최종심은 항상 미검증 — Thompson 접지). 그러나 두 가지가 필요하고 가능하다: (1) **주장 교정** — 테제를 "표현 불가능"에서 "L1/L2 진술 층에서 표현 불가능 + 커널 층에서 변조-증거(tamper-evident)"로 약화하고, Node 런타임·npm 의존·CI 플랫폼이 신뢰 기반으로 남는다는 잔여를 명시 수용. (2) **변조-증거 기제** — 원장 행에 prev_hash 체인, admission을 보호 브랜치 CI에서만 유효로 하고 CI가 커널 디렉터리 해시를 **커널 코드를 실행하지 않는 별도 job**에서 pinned ref 대비 재계산, CI 루트는 branch protection + required check(플랫폼 소유, repo 파일 아님)로 앵커, 로컬 run 산출은 proposed-only로 격하, checker 실행 샌드박스(원장 경로 마운트 불가). 이것 없이는 "binding divergence는 blocking"이 자기 손으로 자기를 검사하는 진술에 그친다.

## F5 [high] 자기 산출물이 다음 귀납의 증거로 재유입된다 — 고정점이 반향(echo) 측정으로 퇴화

**주장.** self 코퍼스에서 체계 자신의 산출물(ledger, theory 투영, run 아티팩트, verdict)을 귀납 증거 기반에서 **격리하는 조항이 없다**. 오히려 두 군데가 역방향으로 배선돼 있다: §6 evidence 표가 "실행 기록: 테스트 결과·**run 원장**·CI 로그"를 sound execution evidence로 명시 등재했고, 소비 게이트(§3.2-3)는 "concept은 어떤 norm/**verdict**/투영이 그것을 참조할 때만 active"라서 체계 자신의 판정이 개념의 소비자로 계상된다. §5.3-3의 사이클 차단은 justification 그래프의 **명시 엣지**만 보는데, 이 순환은 justification 엣지가 아니라 **코퍼스를 경유한 암묵 엣지**로 닫힌다.

**구체 실패 시나리오.** 세대 1에서 그럴듯한 가짜 norm/concept X가 게이트를 통과한다(귀납 오류가 게이트 아래서 일어날 수 있음은 §12가 자인한 최대 위험이다). X는 theory YAML로 투영되고 X를 인용한 verdict들이 run 원장에 쌓인다. 세대 2 reconstruct-on-self: 추출기가 run 원장(execution, sound)과 theory YAML(설정 추출기의 사정권 — 제외 조항 없음)을 읽는다. 이제 X' 후보는 후보 자격 게이트(§3.2-1)의 "권위 증거 ≥ 1"(체계 자신의 verdict가 참조)과 "재발 ≥ k"(투영 파일들에 반복 등장)를 **체계 자신의 산출물로** 충족한다. 소비 시효는 영원히 격발하지 않는다 — 체계가 자신의 판정으로 자신의 개념을 소비해주므로. Tier-2 고정점 비교는 O_2 ⊇ X ≈ O_1을 확인하고 잔차 없음을 보고한다. **고정점 검사가 "체계가 자기가 쓴 것을 다시 읽을 수 있는가"의 측정으로 퇴화하고, 세대가 갈수록 코퍼스에서 자기 투영의 비중이 커져 검사는 점점 더 쉽게, 점점 더 공허하게 통과된다.** §12의 셔플 통제군은 부트스트랩 프로브 하니스를 1회 검사할 뿐 이 상시 루프를 검사하지 않는다. 이것이 이 설계에서 가장 순수한 자기승인이다.

**repair.** evidence 스키마에 provenance 격리를 추가 — 추출 대상이 체계 산출물(ledger/, theory/, run/)이면 `system_generated: true`를 결정론 라벨링(경로 기반이라 결정론 판정 가능)하고, 후보 자격 게이트의 재발·권위 계상과 소비 게이트의 참조 계상에서 제외한다. 격리선은 "커널·추출기·checker **소스**"(정당한 self 증거)와 "커널이 쓴 **진술·투영**"(반향) 사이다. 수리 비용 낮음 — 그러나 이 조항 없이는 테제의 "자기재구축 고정점을 회귀 게이트로" 주장이 성립하지 않는다.

## F6 [high] 사람 게이트의 기계 소비자 부재 — owner 마커는 identity 미검증 문자열이고, 이 repo의 마커 저자는 LLM 에이전트다

**주장.** 자기승인 차단의 최종 방벽이 사람 게이트 4곳(§5.3)인데, 그 실현체가 전부 기계 소비자 없는 절차이거나 위조 가능한 표식이다.

- **L2 완화**: "G4 `INVARIANT-CHANGE` 마커 패턴 계승"(§5.3-2) — G4 마커는 커밋 메시지 문자열이다. 이 repo를 실제로 운용하는 것은 커밋 권한을 가진 LLM 에이전트이고, 에이전트가 마커를 타이핑하는 것을 막는 identity 검증이 없다. "owner 마커 필수"의 기계적 의미는 "누군가 이 문자열을 썼다"이지 "owner가 승인했다"가 아니다. 현행 repo에서 G4가 작동한 것은 사람이 PR을 읽는 운용 관행 덕인데, 이 설계의 목표 상태(사람 관여 최소의 자율 진화 루프)에서는 그 관행이 없다. 초안 자신의 원칙으로 재면 owner 마커는 역량 표면이 아니라 금지문이다.
- **L0 비준 + 이종 계열 독립 리뷰(DDC-lite)**(§5.1): 이 게이트의 완료를 소비하는 기계 게이트가 지정되지 않았다. 초안 자신의 타입 체계로 말하면, 이종 리뷰의 산출은 `authority: llm_claimed`라 차단 불가이고, "owner 비준 완료"는 checker가 결속되지 않은 prose norm — 즉 **realization: semantic, disclosure-only**다. 설계가 죽이겠다고 선언한 declared≠wired가 설계의 최상위 게이트에서 정확히 재생된다.

**구체 실패 시나리오.** 진화 run이 F9의 자기-쐐기(아래)로 admission이 정지한 상태. 무인 운용 중인 에이전트가 "파이프라인 복구"를 위해 완화 변경에 마커를 붙여 커밋한다 — 선의의 복구 행동이 곧 자기승인이다. 마커의 형식 요건은 전부 충족되고, G4류 검사는 green이고, 원장은 "owner 마커 있음"을 기록한다. owner는 사후에야 알거나 영영 모른다. 세 겹 장치(위상 분리·ratchet·사이클 차단)가 한 겹도 발화하지 않는다.

**repair.** owner identity를 역량 표면으로: (1) L0/L2-완화 admission은 owner 서명 커밋(등록된 GPG/SSH 키) 또는 원장 밖 승인 토큰(에이전트가 생성 불가한 채널)을 커널이 검증할 때만 유효 — 서명 없는 완화는 비수용. 단일 사용자 도구라 키 관리 부담은 작다. (2) DDC-lite 완료를 기계 소비자에 결속 — 이종 리뷰 산출물의 해시·좌석 identity를 L0 변경 admission의 필수 입력 필드로 스키마화(리뷰 내용은 llm_claimed여도 "리뷰가 실행되었다"는 결정론 검증 가능). 수리 안 하면 "사람이 남는 곳 전수 4곳"은 4곳 모두 장식이다.

## F7 [medium] 고정점 검사는 자기일관성을 재지 정확성을 재지 않는다 — 동일 계열 재귀납의 공유 맹점은 잔차에 나타나지 않는다 (Thompson의 원 논점)

**주장.** §5.4 Tier-2는 "GCC 3-stage의 번역"을 자처한다. 그러나 GCC 3-stage가 잡는 것은 비결정성이지 오컴파일이 아니며, Thompson의 논문이 보인 것이 정확히 **자기 컴파일 고정점은 결함을 안정적으로 보존한다**는 사실이다. O_{n+1} vs O_n 비교에서 양쪽을 같은 커널 + 같은 LLM 계열이 생산하면, 그 계열이 체계적으로 못 보는 규범 클래스 X는 O_n에도 O_{n+1}에도 없어 diff가 0이고, "고정점 잔차 = 정직한 자기무지 목록"(§5.4)에도 X는 등재되지 않는다 — 잔차는 재귀납기가 **볼 수 있는데 놓친 것**만 담지, **볼 수 없는 것**은 담을 수 없다.

**구체 실패 시나리오.** 특정 계열이 부재-기반 규범(예: "X를 하지 않는다" 류 — 강제 흔적이 위반의 부재로만 나타나는 규범)을 구조적으로 유도하지 못한다고 하자. 세대 0 귀납이 이 클래스를 통째로 빠뜨리고, Tier-1/2 재귀납도 같은 계열이면 발산 0, 잔차 0, fixedpoint green — 체계는 "나는 나를 안다"를 측정값으로 보고하지만 그 측정기가 맹점을 공유한다. 초안 §1의 정직 공시("자기적용은 귀납이 되는가를 보증하지 않는다")는 귀납 **자체의** 실패를 다루지, 고정점 **검사가** 그 실패를 영구히 은폐한다는 이 층은 다루지 않는다. §12의 프로브는 이종 2계열을 쓰지만 그것은 부트스트랩 1회의 실험 설계이고, 상시 fixedpoint Tier-1/2의 좌석 계열은 미지정이다. 이 repo 자신의 실측(이종 프론티어 draft 2벌의 공유 맹점, 2026-07-21 기록)은 이종 계열조차 완전 방어가 아님을 보여준다 — 동일 계열이면 더 말할 것 없다.

**repair.** Tier-1/2 재귀납 좌석을 원 저작 계열과 **이종 계열로 강제**하는 것을 L2 checkable 메타규범으로(좌석 identity는 producer 필드로 결정론 검증 가능 — 설계의 기존 부품으로 조립된다). 더불어 잔차 목록의 한계("재귀납기 가시 범위 내 잔차")를 공시 문구가 아니라 잔차 스키마의 필드로 박아, "잔차 0"이 "맹점 없음"으로 읽히는 소비를 막는다. 이종 강제도 공유 맹점을 축소할 뿐 제거하지 못함은 정직하게 공시.

## F8 [medium] ratchet 자기-쐐기(self-wedge) — 조임 자동 수용이 무인 자기-정지와 자동 지식 소멸을 승인하고, 회복은 완화라서 사람 몫이다

**주장.** "체계는 스스로 엄격해질 수는 있어도 관대해질 수는 없다"(§5.3-2)의 이면: **엄격함은 안전과 단조가 아니다**. 조임으로 분류되는 변경이 체계를 무인으로 망가뜨릴 수 있고, 모든 복구가 완화라서 owner 없이는 회복 불가다.

**구체 실패 시나리오.** (a) 초안의 조임 목록에 "시효 단축"이 있다. LLM이 소비 시효를 N→1 사이클로 줄이는 L2 변경을 제안하면 자동 수용된다. 다음 사이클에 definition-only concept 전량 — §10.5-5가 완충이라 명시한 .onto/domains 11개 수입 지식 포함 — 이 자동 retire된다. append-only라 사건은 남지만, 복원(시효 연장)은 완화라 owner 마커 대기다. (b) `floor(n)` 상향은 조임이다. floor를 현실 불가능한 값으로 올리면 모든 게이트가 FAIL — admission 전면 정지. 정지 해제는 완화. 체계가 자기 손으로 자기를 잠그고 열쇠를 사람에게 던진다. "승격·유지·판정·귀납은 사람 0"은 정상 경로 주장일 뿐, 이 설계의 오류 회복 경로는 구조적으로 사람 1이다 — 초안은 이 비대칭의 비용을 공시하지 않았다.

부수 구멍: 방향 메타데이터는 "L2 파라미터가 필수로 갖는다"인데 **신규 파라미터의 방향 라벨은 누가 검증하는가**. 커널은 추론하지 않으므로(§5.1) 라벨의 의미적 정합을 판정할 수 없다. 신규 파라미터의 도입 자체가 완화인 경우(예: `max_census_violations_tolerated` 도입 — 현행 암묵값 0의 완화)를 "도입=항상 widening/fail-closed"로 못 박는 규칙이 초안에 없다.

**repair.** (1) 조임 자동 수용을 "다음 run에서 negative control 통과 + admission 처리량이 0으로 떨어지지 않음"을 확인한 뒤 확정하는 2-phase로. (2) 시효·floor류 파라미터에 커널 공리 수준의 하한/상한 밴드(밴드 밖 변경은 방향 불문 owner). (3) "신규 L2 파라미터 도입은 무조건 widening" 규칙 명문화. (4) 오류 회복이 사람 경로임을 §5.3 전수 목록에 정직하게 추가.

## F9 [medium] G8/G9 패리티 폐기 — ledger↔projection 드리프트의 탐지기가 사라져 declared≠wired가 원장≠투영으로 재탄생한다

**주장.** §10.2는 패리티 가드를 "이중 권위의 보상 장치였고, 투영이 커널 소유가 되면 검사 대상 자체가 소멸"이라며 폐기한다. 전제가 틀렸다: 이중 **권위**는 소멸하지만 이중 **표현**은 남는다. 원장이 진실이고 theory YAML·프롬프트 payload가 투영인데, 체계의 자기 인식 경로 전체(LLM이 읽는 self 서술, MCP 응답, review 디스패치의 norm 집합)는 투영을 소비한다. 투영기 버그는 원장을 오염시키지 않으면서 **체계가 믿는 자기 모습**을 통째로 어긋나게 한다 — 그리고 Tier-0/1/2 어디에도 투영 왕복 검증이 없다(§5.4는 checker binding과 backtest 델타만 명시).

**구체 실패 시나리오.** projection의 scope 직렬화 버그로 admitted norm 30개가 theory YAML에서 scope 필드가 빈 채 렌더된다. review의 [2] "적용 norm 집합 계산"이 투영을 읽으면 부분 결손(다른 norm의 매칭은 남음)일 때 vacuous_scope 공시 없이 조용히 좁아진 norm 집합으로 판정이 돈다. 원장은 무결하므로 fixedpoint는 green이다. 이 repo가 세 번 실측한 "실패하지 않으면서 커버리지를 잃는 가드"의 재판이며, 아이러니하게 초안이 그 봉인을 위해 만든 `floor()` combinator가 정작 투영 층에는 안 걸려 있다.

**repair.** 왕복 검증(원장 → 투영 → 재파싱 → admitted 해시 색인과 전수 대조)을 Tier-0에 편입하고, 투영 소비 지점의 norm 집합 카디널리티에 floor를 건다. G8/G9의 폐기는 "패리티 검사가 커널 안으로 이사"로 정정되어야지 소멸이어서는 안 된다.

## F10 [medium] 조상 조항(grandfathering) — 진화 후 정합성이 전방(forward-only)으로만 성립한다

**주장.** §5.5는 과거 **verdict**의 불변("게이트 스냅샷 도장이 찍힌 채 남고, 재해석은 admission 층")을 다뤘지만, 과거에 수용된 **norm 재고**가 조여진 현행 게이트 아래서도 여전히 수용 가능한지는 어떤 주기적 검사도 재판정하지 않는다. Tier-0는 binding과 census 델타만 본다. 결과: 현행 강제 집합(blocking 가능한 admitted norm들)이 게이트 세대의 혼합물이 되고, "오늘의 게이트라면 수용을 거부했을 norm이 오늘의 CI를 차단하는" 상태가 표현 가능하다 — admitted ≠ currently-admissible이며, 이를 드러낼 유일한 장치가 드문 owner-트리거 Tier-2의 공시뿐이다. "진화 후에도 정합성이 유지된다"는 물음에 이 설계의 답은 신규 유입에 대해서만 있고 기존 재고에 대해서는 없다.

**구체 실패 시나리오.** L2 조임으로 census 요건이 conform ≥ 50으로 상향된다(자동 수용). 세대 1에 conform 12로 수용된 norm N은 스냅샷 도장 아래 admitted+blocking으로 존속한다. 이후 N이 오탐으로 머지를 막을 때, 감사자는 "현행 기준으로 N의 수용 근거가 미달"임을 Tier-2를 돌리기 전까지 알 수 없다.

**repair.** L2 조임 수용 시 커널이 영향받는 admitted 재고의 **재수용 검사 큐**를 결정론 생성(checkable은 즉시 재판정 — §5.5의 stale 전파와 같은 기계), 현행 게이트 미달 재고는 자동 강등이 아니라 `grandfathered` 1급 상태 + 공시로 표기. append-only와 충돌하지 않고(새 사건), R5 비용도 델타 한정이라 감당된다.

---

## F11 [low] stratum은 진술의 수용을 규율하지 판정의 사정권을 규율하지 않는다 — 자동 수용 L1 norm이 L0 커널 변경을 차단할 수 있다

**주장.** L1 norm의 scope에 `kernel/**`을 금지하는 규칙이 없다. self reconstruct는 커널 소스도 코퍼스로 읽으므로(§6), LLM 귀납이 kernel/을 사정권에 둔 checkable norm을 자동 수용시킬 수 있고, 그 verdict는 deterministic·blocking으로 self CI를 문다(§4.3-b).

**구체 실패 시나리오.** owner가 정당하게 비준한 커널 v1 변경이, 세대 0에서 자동 수용된 L1 norm(예: 커널 코드의 우발적 스타일 규칙이 재발 게이트를 통과해 norm이 된 경우)의 checker에 걸려 CI 차단된다. 해소하려면 그 norm의 retire/수정이 필요한데, 이것이 완화로 분류되면(F2의 수리를 적용한 세계에서) owner 마커 — 사람 최상위 결정(L0 비준)이 기계 최하위 산물(자동 수용 L1)에 볼모로 잡히는 권위 역전이다. 교착은 owner가 풀 수 있으므로 fatal은 아니다.

**repair.** "L_n 진술의 scope는 L_n 이하 대상만"을 커널 수용 게이트의 결정론 검사로 추가하거나, kernel/ 사정권 norm은 L0 게이트(owner)를 요구하도록 승격 규칙을 둔다.

## 시도했으나 초안이 견딘 시나리오 (기록 의무)

- **동일-run 게이트 co-flip**: 제안이 자기 심판 게이트를 같은 run에서 고치는 공격 — §5.3-1의 run 시작 시점 게이트 스냅샷이 막는다. 다중 run 세탁 중 **L2를 경유하는** 경로(run R1에서 게이트 완화, R2에서 통과)는 owner 마커에 걸린다 — 단 L2를 경유하지 않는 세탁(F2)과 마커 위조(F6)는 뚫리며 해당 finding에 계상했다.
- **L3 무한퇴행**: "L2 게이트가 좋은가"를 묻는 층의 무한 상승 — stratum enum 닫힘 + "탑은 가상, 실재는 유한 접지"(§5.1)는 반영 탑 문헌과 정합하는 정당한 종결이다. 접지 **자체**는 공격 불가; 접지 위 주장의 과잉만 F4로 계상했다.
- **부트스트랩 첫 고정점의 순환**: 첫 고정점을 체계 안에서 만들려는 순환이 있는지 검사 — §5.2가 "체계 안에서 만들어지지 않는다, 지금 이 워크플로가 proto 단계, owner 비준이 seq 1"로 외부 접지를 명시했다. 여기는 순환이 없다. 남는 것은 비준 **이후** 체인의 자기증명 문제(F4)와 비준 게이트 자체의 기계 소비자 부재(F6)뿐이다.
- **justification 순환 권위**: 진술 A가 B를, B가 A를 정당화 — §5.3-3 사이클 하드 블록이 막는다. 명시 엣지 밖의 순환 두 종만 남는다: 커널 층(F4), 코퍼스 경유 암묵 엣지(F5).
- **theory 손편집 승인**: 손편집 YAML을 체계가 읽어 자기 승인 — §2.3 admitted 해시 색인의 inert 처리가 막는다(단, 색인의 권위 원천인 원장 자체의 무결성은 F4).
- **공허 통과 계열**: subjectSet 카디널리티 단언·vacuous_scope 공시·고정점 잔차의 카디널리티 단언 — 일관 봉인돼 있다. 남는 것은 "게이트가 도는가"가 아니라 "게이트를 누가 저작·회전시키는가"(F1·F3)였다.
- **귀납 자체의 실패를 은폐**: 초안이 §1에서 선공시하고 §12에서 kill 기준(Arm B<30% 또는 디코이 오수용>0 → 테제 폐기)을 사전등록했다 — "저자가 못 다룬 것" 지적은 무효. 단 고정점 검사의 공유-맹점 은폐(F7)와 상시 루프의 반향 오염(F5)은 §12가 덮지 않는 별개 층이다.
- **evidence 위조**: LLM이 evidence를 직접 제출 — submit 채널에 수용 슬롯 부재(§3.1)로 막힌다. 우회는 추출기 코드 저작뿐이며 F1에 계상.

## 판정 요약

위상 분리·ratchet 비대칭·사이클 차단·유한 접지·공허 통과 봉인 — L1/L2 **진술** 층의 장치는 설계 의도대로 작동하는 시나리오가 다수였다. 무너지는 곳은 일관되게 두 부류다. 첫째, **진술이 아닌 것들**: 커널 코드(F4), checker/추출기 코드(F1), 사람 마커(F6), 투영 코드(F9), 재귀납 좌석(F7). 둘째, **ratchet의 사정권 밖에 있는 진술 생애 사건들**: L1 retire·scope 축소(F2), checker 재결속 co-rotation(F3), 재고의 재수용 부재(F10) — 그리고 코퍼스를 경유해 justification 그래프 밖으로 닫히는 반향 순환(F5). 초안의 테제는 "진술의 자기승인"을 봉쇄하고 그것을 "자기승인 일반"의 봉쇄로 과잉 청구했다 — 이는 아이러니하게도 초안이 봉인 대상으로 지목한 declared≠wired의 설계 문서 판본이다.

수리 목록은 전부 설계 철학의 기존 부품(해시 결속·좌석 identity·floor·fail-closed·방향 메타데이터의 사정권 확장)으로 조립 가능하므로 verdict는 fatal이 아니라 **major_gap**이다. 단 두 가지 구조적 결과는 피할 수 없다: (1) F1의 checker 저작 trilemma(사람↔세탁↔표현력)는 어느 갈래를 골라도 "사람 0" 또는 "차단 권위 타입 봉쇄" 문구를 깎는 실질 트레이드오프이며, 이 선택을 회피한 채로는 설계가 완결되지 않는다. (2) F2·F3의 수리는 사람-전수 목록을 4곳에서 늘리므로, "사람 = 완화 방향의 고정점"이라는 국소화 주장은 유지되되 그 고정점의 개수 회계는 재작성되어야 한다.
