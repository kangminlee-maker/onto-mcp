# 종합 — 배달 증명을 어디에 두는가 (2026-07-27)

> 입력: 블라인드 패킷 [06](06-crossverify-packet-delivery-proof.md) → 이종 frontier 2벌 독립 판정.
> 리뷰어 A = `claude-fable-5`/max (동일 계열) · 리뷰어 B = `gpt-5.6-sol`/max (교차 계열, hermetic·read-only).
> 둘 다 서로를 모르고, 같은 디렉터리의 초안·주 세션 결론 열람이 구속 조건으로 금지됐다.
> 측정 근거: [05](05-measurement-tool-result-truncation.md).

## 0. 판정 — 주 세션의 가설이 기각됐다

주 세션은 "증명을 본문 **소유**에 묶자"(선택지 C)를 유망하게 봤다. **두 리뷰어가 독립적으로 기각했다.**

- 해시는 **LLM이 못 하는 결정론 작업**이다. 받은 바이트를 쥔 유일한 당사자가 그것을 해싱 못 하는
  유일한 당사자다. (B: *"the receiver is an LLM, not a reliable byte-exact hashing component"*)
- 본문에 퍼진 질문의 답으로 대체하면 ① 부분 내용에서 **추론 가능**하거나 ② 런타임이 답의 정합성을
  **의미 판정**해야 한다 — 후자는 역량 경계 위반(런타임은 계약을 강제하되 추론하지 않는다).

기존 아티팩트의 `observation_content_sha256`을 되돌려받는 변형도 무효다 — **그 값 자체가 결과에 실려
오므로 본문 없이 생존한다**(B). 블라인드로 돌리지 않았으면 이 기각을 못 받았을 것이다.

## 2. 정면 충돌 — 그리고 판정

| | 리뷰어 A (fable) | 리뷰어 B (gpt-sol) |
|---|---|---|
| 증명 위치 | challenge를 **중점**으로 옮긴다. 가운데-소실이면 증명이 본문과 **함께 죽는다**(fail-closed) | **"어디에 둘까"라는 질문 자체가 malformed.** 고정된 증명 바이트는 어떤 삭제에도 보존될 수 있다 — 마커를 늘리면 보존 집합만 커진다 |
| 근거 | 관측된 삭제 기하(head…tail)를 이용한 **무비용 계측** — 값은 이미 초안에 있고 위치만 바뀐다 | 위치는 **건전성 속성이 아니다.** 구조적 탈출구는 ① 원자 프레임 ② 수신자 측 검증 둘뿐 |

**B가 옳다.** A의 중점 배치는 **지금 버전에서 관측된 기하에 맞춘 보정**이고, 그건 두 리뷰어가 다른
대목에서 함께 경고한 바로 그 버전 취약성이다. A 자신도 "핀이 무시되고 + 모양이 tail-only로 바뀌면
중점 challenge가 생존한다"고 자기 한계에 적어 두었다.

**단 A의 착상을 버리지는 않는다.** 위치를 **건전성 주장으로 계상하지 않되**, 이미 존재하는 값을 중점에
두는 것은 비용 0의 **심층 방어**다: 핀이 조용히 무시되는 경우 fail-open 대신 fail-closed로 죽는다.
→ **채택하되 "hardening", 절대 "proof"로 계상하지 않는다.**

## 3. 주 세션 독립 발견 — 두 리뷰어 모두 못 가진 것

리뷰어 B는 *"whether Codex treats `content` and `structuredContent` independently"* 와
*"Vary duplication and JSON escaping independently"* 를 **미측정 항목으로** 올렸다. 실측했다.

**façade는 같은 페이지를 한 결과에 두 번 싣는다** — `content[0].text = JSON.stringify(page)`
**그리고** `structuredContent: page` (observation-read-facade.ts:511-512, 668-669).

    페이지 직렬화(= pageCharBudget이 재는 값)   60,144자
    실제 MCP 결과 프레임(= 전송이 나르는 값)   123,494자   →  2.05배

따라서 `OBSERVATION_READ_PAGE_CHAR_BUDGET = 65_536`은 전선에 **약 134,000자**를 올린다. 실측에서
128,049자는 9지점 중 **5개를 잃었다.**

여기에 더해, 두 리뷰어가 쥔 최근접 손실점은 65,553자(기본값보다 17자 **위**)였으나 그 뒤 측정된
**65,049자도 절단**이다 — 기본값보다 **아래**다. 즉 기본값은 손실 구간에 *인접*한 게 아니라 **안에**
있고, 봉투 배증까지 겹치면 두 겹으로 초과한다.

**단, 이 기능은 opt-in이고 기본 OFF다.** 오늘의 프로덕션 결함이 아니라 **플래그를 켜기 전에 반드시
닫아야 할 결함**이다. 어차피 활성화는 하류 프롬프트 유계화(핸드오프 §6)에 막혀 있다.

## 4. 종합 권고

**원자 프레임(A) + ack 상태 전이 — 그 위에 중점 배치를 무상 경화로.**

1. opt-in ON일 때 **`-c tool_output_token_limit=T`를 그 런치에 대해 선언**한다. 발견된 기본값에
   의존하지 않는다. T와 codex 버전을 런 기록에 남겨 버전 변동이 **보이는 사건**이 되게 한다.
   (`-c`가 `--ignore-user-config`를 넘어 도달함은 llm-caller.ts:1022에 실측 기록됨.)
   ⚠ **천장은 못 올린다**(05 §2 실측: 200000에서도 동일 절단). T의 값어치는 **낮춰서 고정**하는 것뿐.
2. **codex가 세는 표현 전체**를 재서 그 아래로 자른다 — `entry.body`가 아니라 **봉투·이스케이프·중복
   포함 2.05배**. 초과 프레임은 쓰기 **전에** 거부한다. 기존 fail-loud 게이트
   (observation-read.ts:854)가 이미 서버 권위에서 그걸 강제하므로, 고칠 것은 **재는 대상**이다.
   → 이 항목이 §3의 배증을 흡수한다. 중복 적재 자체를 없앨지는 별도 판단(개념 경제).
3. `pageCharBudget`을 **T의 투영**으로 만든다(측정된 보수적 chars-per-token 계수 1개 경유).
   파생값은 원천의 투영으로 남긴다 — 상수를 두 곳에 선언하지 않는다.
4. 초안 2의 **1회용 ack challenge를 유지**하되, 증명의 정체는 **런타임 측 ack 기록 + 원자 프레임
   불변식**이다. write 콜백 = `emitted`, ack = `delivered`. challenge는 **중점**에 둔다(무상 경화, §2).
5. 인용 가능성은 **완전 ack 커버리지**에서만 파생한다:
   `cited ⊆ ack-완전 ⊆ served ⊆ snapshot`.
6. **9지점 생존 하니스를 버전 변동 게이트로 상설화**한다(`scripts/probe-tool-result-truncation.mts`).
   새 codex 버전을 신뢰하기 전에 핀 T에 대해 재실행.
7. **F는 다음 단계 후보**로 둔다. 측정이 "codex 기록이 post-trim"임을 보이면 F가 challenge를
   대체할 수 있다(정확·코드측·워커 부담 0). **미측정 상태로 짓지 않는다.**

## 5. 남은 미측정 (두 리뷰어 요구의 합집합)

1. 선언한 T가 **경계에서 정확히 지켜지는가** (T 아래 무손실 / 위 절단, 3회·2픽스처·분산 기록)
2. codex가 세는 **표현이 무엇인가** — text만 / structured만 / 정규화 렌더링. 중복·이스케이프 독립 변화
3. **T 아래 원자성**을 ASCII·CJK·코드·이스케이프 과다 JSON에서 확인 (실 코퍼스 최악 비율로 마진 설정)
4. **누적 상호작용** — 개별 안전 프레임을 다수 가져간 뒤 앞선 결과가 나중에 압축·변형되는가
5. **ack 경로** — 정확·오타재시도·재생·교차런치·최종 ack 누락·수신 전 프로세스 사망
6. **작은 도구 입력의 무결성** — 되돌아오는 ack 인자가 서버에 그대로 도달하는가
7. **OFF 경로 동등성** — 실 argv·stdin 바이트 포획 후 기존 경로와 정확 일치
8. (F 추구 시) 훅이 **절단 후·모델 제출 전**에 도는가, 그 측면 채널을 모델이 위조 불가한가

## 6. 프로세스 기록

- **블라인드가 값을 냈다.** 주 세션 가설(C)이 양쪽에서 기각됐고, 열람 금지가 없었으면 두 리뷰어가
  05의 결론을 읽고 동의했을 것이다 — 검증이 아니라 추인이 됐을 것이다.
- **동일 계열 수렴은 검증이 아니다.** A와 B가 겹친 7항목은 신뢰도가 높지만, **정면 충돌 1건(§2)에서
  교차 계열 쪽이 옳았다.** 이종을 쓴 이유가 이것이다.
- **리뷰어 지적도 가설이다.** A의 코드 인용 3건(observation-read.ts:647·854, llm-caller.ts:1022)을
  실코드로 재확인하고 채택했다. 그 과정에서 A가 **과소 진술**했음을 발견했다(§3).
