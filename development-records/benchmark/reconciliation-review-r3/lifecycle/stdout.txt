VERDICT

The design is not seam-safe yet. Its core direction is sound—current-child stderr identity, post-trim-only evidence, launch binding, and fail-closed publication—but three lifecycle gaps remain blocking: reconciliation is only one-way, the start marker is not specified as an exclusive claim, and the final delivery receipt is not bound to resume/reuse provenance. The weakest seam is the transition `transport log → rollout → final receipt`: a crash can currently turn “delivery happened but was not logged” into the false statement “verified, nothing delivered.”

FINDINGS

1. **BLOCKER — Reconciliation needs reverse completeness.** Sequence: stdout bytes reach codex; the facade is killed before persisting that emission; the rollout contains the post-trim result but the transport artifact does not. The proposed “for each emitted string, find a transcript match” loop sees no unmatched emission and can publish an empty receipt. Current delivery ordering deliberately permits under-recording ([server callback](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade-server.ts:102), [facade rationale](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade.ts:503)). Fix: require a bijection, including order/cardinality or tool-call ids, between every relevant transcript result and every logged emission. Any transcript result without a logged emission is `unverifiable`, never “verified empty.”

2. **BLOCKER — An atomic marker write is not an exclusive start claim.** Two facade processes can both check an absent marker, mint full budgets, then race their writes. Current code uses check-then-mint-then-write ([start check](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade.ts:447)); publication uses a shared `.tmp` name and rename ([publication](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade.ts:601)). Fix: claim an attempt/dispatch-scoped start file with `O_CREAT|O_EXCL` before minting, use unique temporary files plus fsync/rename, and never use unconditional clearing as concurrency control. The current literal-round descriptor/receipt paths ([construction](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/direct-call-directive-author.ts:3360)) should become attempt/launch-scoped.

3. **BLOCKER — Dispatch identity can be lost across the parse-repair dispatch.** The initial answer-support call owns the facade and transcript; malformed JSON causes a second codex dispatch that explicitly drops the facade ([repair path](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/authoring-llm-call.ts:275)). The receipt is currently read only after the entire authoring operation returns ([call site](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/direct-call-directive-author.ts:3380)). Reconciliation performed against an aggregated or “latest” banner could therefore bind to the repair transcript. Fix: capture dispatch evidence from the per-child stderr buffer ([llm-caller.ts](/Users/kangmin/Documents/onto-mcp/src/core-runtime/llm/llm-caller.ts:1122)) and reconcile the facade-bearing attempt before repair, or carry that attempt’s opaque evidence through `callJsonAuthor`. “Exactly one banner” applies per child, not per authored artifact.

4. **BLOCKER — A reusable authored artifact is not yet bound to its delivery receipt.** Existing resume returns an authored YAML file solely when its reuse hash and artifact hash match; it does not invoke the author callback or check a receipt ([reuse path](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/authored-artifact-reuse.ts:461)). Thus an earlier attempt can reconcile successfully, fail later, lose or overwrite its receipt, and still have its ledger reused. Fix: make receipts immutable and attempt-scoped; record receipt ref/hash, attempt id, launch id, authored-output hash, and verification-contract version in reuse provenance/run-control. Bump the ON-only authored-output contract version when `served` acceptance changes to `delivered` ([version seat](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/authored-artifact-reuse.ts:383)).

5. **BLOCKER — The existing relevant opt-in is already product-reachable.** `source_observation_catalog_tool` is accepted by settings ([settings-chain.ts](/Users/kangmin/Documents/onto-mcp/src/core-runtime/discovery/settings-chain.ts:556)), read by the Core API ([reconstruct-api.ts](/Users/kangmin/Documents/onto-mcp/src/core-api/reconstruct-api.ts:1239)), and forwarded into the production author ([reconstruct-api.ts](/Users/kangmin/Documents/onto-mcp/src/core-api/reconstruct-api.ts:1573)). Wiring Stage 3 to this flag makes Stage 3 product-reachable before Stage 4. Fix: use a non-representable internal test capability, or land Stages 3 and 4 atomically. Default-off is not the same as unreachable.

6. **MATERIAL — A host crash before reconciliation has no same-session recovery.** Killing only the worker lets the surviving runtime catch the failure, mark the attempt failed, and release its lock ([run.ts](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/run.ts:4956), [lock release](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/run-control-validation.ts:1197)). Killing the runtime after worker exit leaves the logical attempt `running` with a held lock; explicit resume refuses it even after lease expiry ([resume admission](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/run-control-validation.ts:954)). Fix: add explicit attempt recovery that either reconciles the exact abandoned dispatch or marks it `unverifiable`/abandoned and creates a new attempt. Otherwise document that this kill point requires a new session root.

7. **MATERIAL — `unverifiable` must not pass through the current nullable receipt API.** Today missing, malformed, or wrong-token receipts become `null`, and `null` becomes an empty served set ([reader](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade.ts:763), [set projection](/Users/kangmin/Documents/onto-mcp/src/core-runtime/reconstruct/observation-read-facade.ts:838)). Fix: expose a discriminated result such as `verified(delivered)` versus `unverifiable(reason)`; make coercion from the latter to an empty set impossible, and surface it in status/operator output.

ANSWERS TO THE SEVEN QUESTIONS

1. **Second dispatch, same session root.** A second fresh top-level run is rejected by run-control before facade launch. An explicit resume after a failed attempt may proceed. It reaches the same literal-round paths, deletes the predecessor receipt, creates a new launch token, and overwrites the descriptor. The token prevents a later reader from accepting the predecessor receipt; the clear removes it outright. An earlier rollout must be rejected because its session id differs—the creation-time window and cwd are secondary validation, never selectors. Attempt-scoped paths would remove the destructive clear entirely.

2. **Resume.** Reusable: authored artifacts with valid reuse provenance and, after this change, their exact hash-bound verified delivery receipts. Never reusable: descriptor, launch token, start/transport artifact, raw stderr, an `unverifiable` result, or a transcript from another dispatch. Earlier reconciliation failure means no receipt and normally no ledger, so resume launches anew. Earlier reconciliation success followed by a downstream failure should reuse the ledger and its bound receipt without reconciling again. A later failed attempt must never fall back to an earlier attempt’s receipt.

3. **Concurrency.** Same session root: run-control serializes admission and rejects the second owner. Distinct session roots: descriptor and receipt paths do not collide. Rollouts do share the codex home and may have overlapping lifetimes and identical cwd, so cwd/time cannot disambiguate them; the exact session id from each child’s private stderr must. Also, codex currently inherits the host process cwd because `spawn` supplies no `cwd` ([llm-caller.ts](/Users/kangmin/Documents/onto-mcp/src/core-runtime/llm/llm-caller.ts:1111)); “canonical cwd” must mean that captured actual cwd unless the spawn contract is deliberately changed.

4. **Kill points.**

   - After delivery but before transport-artifact commit: transcript has an unlogged result; reconciliation must be `unverifiable`.
   - After transport-artifact commit but before worker exit: only transport truth exists; restart under that launch must be refused, and no delivery receipt is readable yet.
   - After worker exit but before reconciliation: transport artifact plus rollout remain, but no receipt. A runtime kill leaves current run-control stuck until explicit recovery or a new session.
   - During receipt publication: readers may see only the old transport schema or the complete new receipt—never a partial receipt. This requires unique temp files, atomic rename, and durability sync. Orphan receipts created before the authored ledger write are not independently reusable.

5. **Budgets and restart.** A durable, exclusive start claim closes the restart hole by refusing every second server before it mints; it does not restore counters. That is acceptable because the policy is “one launch, one server episode.” A plain check followed by atomic replacement does not close parallel starts. If the first process dies before the marker but the marker is strictly ordered before any response, regranting is safe because the first process delivered nothing.

6. **Opt-in boundary.** Prove OFF using an independent pre-change oracle and a deterministic end-to-end fixture: absent and explicit-false must produce identical child argv/stdin/env, call count/order, returned data, and artifact bytes; create no descriptor, transport log, receipt, transcript read, telemetry row, or new failure mode. Add a mutation test that forces reconciliation while OFF and proves the parity test fails. An accidentally reachable Stage 3 becomes visible through a product-surface test that enables every accepted setting/API/MCP input while the version allowlist is unavailable and asserts the reconciler is never invoked. Flag flips currently rotate the reuse key; existing artifacts cause a provenance mismatch and refusal, not silent regeneration. Stage 4 must also rotate the ON-only acceptance-contract version.

7. **Retention.** If the rollout disappears before reconciliation, the result is `unverifiable`, no receipt is published, and pulled citations cannot be accepted. If it disappears after a hash-bound final receipt is published, normal reuse need not depend on it. Never copy raw rollout records, pre-trim or post-trim payloads, prompts, model output, reasoning, unrelated tool traffic, credentials, or the absolute home transcript path into repo-local artifacts. Persist only minimal derived facts: parser/CLI version, attempt/session binding, rollout digest, per-emission match result or digest, and delivered observation/part identities.

WHAT I WOULD MEASURE OR ASSERT BEFORE BUILDING

1. On every proposed supported codex version, prove that the rollout exposes enough stable structure to enumerate all relevant post-trim tool results—not merely search strings—and correlate them to calls. If it cannot, the crash-safe design must change.

2. Barrier-start two facade processes under one launch and assert exactly one exclusive start, one grant, and at most one budget. Repeat with two different launches and the same round/session path.

3. Fault-inject all four kill points, including the narrow “stdout callback completed, artifact commit not executed” window, and assert that only a complete bijection can publish a receipt.

4. Exercise the resume matrix: earlier reconciliation `{verified, unverifiable}` × later `{verified, unverifiable}` × ledger `{present, absent}` × flag `{same, flipped}` × contract version `{same, bumped}`. Assert that evidence never crosses attempt ids.

5. Run two real codex workers concurrently from the same cwd with overlapping time windows, plus a stale earlier rollout. At least three runs over two payload shapes per allowlisted CLI version; session-id selection must remain exact.

6. Extend the existing OFF oracle beyond prompt bytes to the entire product side-effect surface, and add static reachability checks proving Stage 3 has no settings, API, MCP, CLI, or environment entry until Stage 4.

7. Delete, rotate, replace, and truncate the rollout before and during read; assert deterministic `unverifiable`, then scan all emitted repo-local artifacts to ensure no raw transcript content escaped.
