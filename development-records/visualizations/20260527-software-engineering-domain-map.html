핵심 개념 정리

1. Domain Scope

리뷰에서 빠지면 안 되는 concern의 지도입니다. 기존 SE concern에 LLM-native & agentic development가 통합되어, AI 관련 작업도 별도 리뷰가 아니라 같은 프레임 안에서 다룹니다.

  • Data/State
  • Interface/Contract
  • Verification/Quality
  • LLM-Native/Agentic

2. Source of Truth

충돌이 생겼을 때 어떤 문서가 의미를 소유하는지 정합니다. 개념은 concepts.md, 범위는 domain_scope.md, operational rule은 logic_rules.md가 중심입니다.

  • concept definition authority
  • artifact truth
  • domain rule ownership

3. Fail-Loud

LLM-native 개발에서는 조용한 fallback이 탐색 비용을 키웁니다. prompt, context, model, tool, schema, artifact 경계가 깨지면 원인과 위치를 드러내는 diagnostic artifact가 우선입니다.

  • silent degradation is a defect
  • fail-close + fail-loud
  • visible degraded state

4. Structural Coherence

좋은 구조는 모듈, public interface, tests, config, schema, docs가 서로 맞물리는 상태입니다. 구조 문서는 이 연결 관계를 golden relationship으로 검증합니다.

  • module-interface coherence
  • test-code coherence
  • schema-code alignment

5. LLM Boundary

LLM 호출은 단순 API call이 아니라 model/provider, prompt, context, tool, output validation과 LLM/runtime/middleware 소유권이 연결된 behavior boundary입니다.

  • LLM: semantic judgment
  • Runtime: deterministic authority
  • Middleware: transport/adaptation only

6. Problem Framing

리뷰 finding을 실행 가능한 issue로 바꾸는 축입니다. 어디의 문제인지, 어떤 defect kind인지, 어떤 verification이 필요한지로 closure를 결정합니다.

  • implementation_surface
  • defect_kind
  • verification_need

LLM Boundary Ownership Split

영역 소유해야 하는 것 침범하면 안 되는 것
LLM 의미 해석, 판단, 탐색 계획, source-layer reasoning, 초안 생성 persistence, deterministic binding, authorization, idempotency, 최종 authority artifact 조립
Runtime binding, validation, state transition, persistence, audit, cost/security gate, artifact assembly 새 의미 생성, evidence sufficiency 임의 판단, semantic drift의 silent repair
Middleware transport, envelope conversion, routing plumbing, auth/context propagation, retry envelope, observability plumbing 의미 재해석, hidden policy owner 역할, authority/source-of-truth 역할
